# AGENTS.md

Guidance for AI coding agents working on the Turf compiler itself (not on programs written in Turf — for language syntax and stdlib usage, see `README.md`).

## What this repo is

An LLVM-backed, statically-typed, AOT-compiled language. Pipeline: `Lexer → Parser → Resolver (2-pass) → TypeChecker → Codegen (LLVM IR)`, plus a diagnostics layer with an optional local-SLM-assisted `--smart` mode. C++20, CMake, LLVM 22.

## Build

```bash
./scripts/cmake_build.sh --release   # first run also builds the vendored llama.cpp submodule — slow once, fast after
```

`--no-smart` (`-DTURF_SMART=OFF`) builds without `--smart`'s model runtime: no llama.cpp submodule, no OpenMP. `src/SLMEngineDisabled.cpp` replaces `src/SLMEngine.cpp`, the only file that includes `llama.h`, so keep llama.cpp out of every other file or this build breaks. The test suite and `turf-api-tests` pass either way (neither needs a model).

The build produces **two binaries** (LEC-001, `docs/development/FREEZE.md` §6.16, F-PKG-1):
- `build/turfc` is the compiler. Everything in this file that says "the compiler" means it: the test runner, the smoke scripts and CI run it directly, and `TURF_COMPILER` (the override the runner reads) points at `turfc`, never at `turf`.
- `build/turf` is the Go front end under `cli/` (it finds `turfc`, checks its driver interface, and forwards; `turf file.tr` is `turfc file.tr`). **Go is optional**: it is only needed for `build/turf`, and without `go` on `PATH` CMake prints `Go not found: build/turf ... will not be built; build/turfc is unaffected` and the compiler and the whole test suite build and run as usual. `-DTURF_BUILD_CLI=OFF` skips it explicitly.

`./scripts/cmake_build.sh --release-static` (`-DTURF_RELEASE_STATIC=ON`, REL-008 stage 2) builds the self-contained release `turfc` (add `--embed-lld` for the in-process linker of stage 3, which links programs that name no other C library against `lib/rt/<platform>/` instead of running `cc`; `TURF_LINKER=system` forces `cc`; the runtime dir is built by REL-008 stage 4, so today nothing ships one): every LLVM target and the C++ runtime linked statically, no `--smart` runtime. CI builds the release archives this way; it needs an LLVM with static libraries (Ubuntu/Homebrew/MSYS2, not Arch's) plus `libz.a`, `libzstd.a`, `libtinfo.a`, and takes a minute or two longer to link. Check a build with `readelf -d build/turfc | grep NEEDED` (libc, libm and the loader only) or `scripts/release_deps_check.sh` on an archive. Dev builds stay on the shared libLLVM.

Rebuild after any `src/`/`include/` change with `cmake --build build -j$(nproc)` (no need to re-run the full `cmake_build.sh` script unless `CMakeLists.txt` itself changed). `turf` and `turfc` are **versioned independently**. `turfc`'s release version is the root `VERSION` file; `turf`'s is `cli/internal/version/version.go`. What must fit is the **driver interface** `turfc --version` prints on line 2 (`TurfcInterfaceMajor`/`Minor` in `src/main.cpp`): bump the minor when you add a flag or input a driver may use, and the major when you remove or change the meaning of one (`FREEZE.md` §6.16). User-facing text (README, help, diagnostic hints) says `turf`. `turfc` is the tooling interface and what this file's scripts call. The front end's own checks are `cd cli && go vet ./... && go test ./...` and `./scripts/cli_smoke.sh` (SKIP if `build/turf` is absent, unless `CI` is set).

`./scripts/dev_install.sh` symlinks `build/turf` into `~/.local/bin` (`--prefix DIR` for elsewhere, `--with-turfc` to link the compiler too, `--uninstall` to undo), so `turf` works from any directory and finds `build/turfc` by itself. **Don't export `TURF_HOME` for a dev checkout**: both binaries already find their install root from their own real path, and a `TURF_HOME` pointing at one checkout silently makes every *other* build (a worktree, a scratch build directory) use that checkout's `lib/std` and runtime.

## Test

```bash
./scripts/test_runner.sh
```

Runs every `.tr` file under `tests/`. It is a thin wrapper over **`turfc --test`** (REL-002, `FREEZE.md` §6.22): the conventions below are implemented once, in `src/TestRunner.cpp` (discovery, the compile/run child processes, the report) and `src/TestExpectations.cpp` (the `EXPECT-*` markers and the `tests/DIAGNOSTIC_GAPS.txt` policy), and the same code is what `turf test` runs for a user's project. Change a convention there, never in the script, and run `./scripts/test_cmd_smoke.sh` (CI does): it breaks each convention on purpose and checks the run fails for that convention's reason, which a suite of passing tests cannot show. `turfc --test` and `turf test` treat a missing `tests/` (or one with no tests) as an **error**, never a silent pass; the wrapper passes `--exclude custom --exclude 99_known_bugs` and `--diag-register`, which are this repository's own policy (a project needs no register). `TURF_TEST_JOBS` and `TURF_TEST_TIMEOUT_SEC` are read by `turfc --test` itself, and the wrapper reads `TURF_TEST_EXTRA_EXCLUDE` (space-separated paths under `tests/`) for a build that cannot pass a test by design: the ASan CI job skips `41_gc/fail_stack_overflow_deep_recursion.tr`, since an ASan runtime installs no SIGSEGV handler of its own (INV-RT-5). `turfc --test` is POSIX-only for now. Takes an optional `-O0`/`-O1`/`-O2`/`-O3`/`-Os` argument (`./scripts/test_runner.sh -O1`) that forwards that flag to every compile invocation — absent, it's whatever the compiler's own default is. CI runs the full suite once per level this way (`.github/workflows/test.yml`) as OPT-001's regression coverage for "optimization levels never change observable behaviour" (INV-OPT-1); `scripts/opt_levels_smoke.sh` covers the same property for `showcase/`, which the runner doesn't touch at all (see below).

**Formatting gate.** CI runs `./build/turf fmt --check lib/std tests`, so every `.tr` file you add or edit there must already be formatted: run `./build/turf fmt --write lib/std tests` before committing (it changes whitespace only: indentation, trailing space, blank-line runs, the final newline). A file the lexer rejects, such as a `fail_*` test with a malformed number, is skipped and listed, not a failure; to see what was skipped, read the `skipped` lines. Name such a file on the command line and it is an error, because you asked for it.

**Tool API tests.** `build/turf-api-tests` (built with everything else, source `tests/api/analysis_test.cpp`) unit-tests the compiler query facade (`include/turf/Analysis.h`, SMP-001) — the only supported way to run the front end in-process from a tool. `test_runner.sh` only runs `.tr` files, so run this binary directly after any change to the Lexer/Parser/Resolver/TypeChecker's global state; CI and `session_postflight.sh` both run it. Its fixtures are written to a temp directory at run time, never as `.tr` files under `tests/api/`, which the runner would pick up.

**`--smart` without the model.** `TURF_SLM_REPLAY=<file>` answers each model call with the next recorded response in `<file>` (separated by `%%` lines), so the part of `--smart` after the model (JSON parsing, choosing where a fix goes, the sandbox, retry feedback) runs deterministically, in any build. `./scripts/slm_replay_smoke.sh` replays the cases in `scripts/slm_replay/`; `./scripts/slm_deterministic_fix_smoke.sh` covers fixes the compiler makes without the model. Replay bypasses the on-disk cache (`~/.cache/turf/slm`) unless `TURF_SLM_REPLAY_CACHE=1`, which only `./scripts/slm_cache_smoke.sh` uses (with `HOME` pointed at a temp dir) to cover the cache: validated fixes are cached indefinitely, "the model could not fix this" (NONE, or 3 failed attempts) for 24h as a separate `.neg` entry. After any change to `src/SLMIntegration.cpp` or `src/Sandbox.cpp`, run both. A model bug report becomes a replay case: copy the raw response from `TURF_SLM_DEBUG=1` output. The same logs show what the model is told: `TURF_SLM_DEBUG=1` prints the user prompt (the verbatim code plus its structured fields: `error_line`, `inside`, `receiver`, `known_types`, `related`), and `TURF_SLM_DUMP_PROMPT=1` prints the system prompt.

**What the model reads is documentation, so it is tested like code.** Everything under `docs/slm/` (per-code pages, category docs, `syntax_card.txt`) goes into the system prompt, and a small model copies what it is shown. `./scripts/slm_doc_examples_check.sh` compiles every `CORRECT`/`VALID` example in them (a page whose example does not compile fails, and so does a non-retired `docs/slm/codes/Exxx.txt` with none), and `./scripts/slm_prompt_budget.sh` measures, with llama.cpp's tokenizer, that the system prompt for every category doc plus the biggest code page fits the model's 4096-token batch. Run both after touching `docs/slm/**`; CI does. Write an example by compiling it first, and keep it complete (declare what it uses, no `{ ... }` bodies): both the real compiler's acceptance and the token budget are what make a page useful to the model.

**Stdlib public surface (LEC-007, `FREEZE.md` §6.20).** The `pub` items of `lib/std/**` are the 2.x compatibility surface. `tests/46_stdlib_surface/` uses every one of them, and `./scripts/stdlib_surface_check.sh` fails if a `pub` item exists that no file there mentions, or if a public function/method/field name is not `snake_case` (CI and `session_postflight.sh` run it). **Adding a `pub` item to `lib/std` means adding a use of it to that folder in the same change; removing or renaming one is a 3.0 break.** What is public is decided by the owner's rule (F-API-4): a function that does a job is public whether or not this repo uses it; a struct's internals only if a real program needs them; raw C bindings (`fopen`, `getenv`, `socket`, ...) stay private behind checked Turf wrappers. Do not hide something because the repo doesn't call it, and do not expose a libc function because a wrapper is missing — add the wrapper. Conventions for naming, failure (`!T` vs. caller-located panic vs. `bool`) and `defer x.close();` are in `docs/reference/stdlib/README.md`.

**GC regression tests (`tests/41_gc/`) must be run at `-O0` as well as the default level.** Conservative stack/register scanning can mask a real tracing-collector bug at `-O2` purely by register-allocation luck — a value that would otherwise be the only surviving reference to a GC object happens to still sit in a scanned register or stack slot. `./scripts/test_runner.sh -O0` is the only way to catch that class of bug; it's already part of CI, but a session iterating locally on `runtime/turfrt_gc.c` or its Codegen counterpart should run it directly rather than relying on the default-level run alone.

**GC testing aids (FDN-005)** — runtime environment variables, read by every compiled Turf program, combinable with each other and with any `-O` level:
- `TURF_GC_STRESS=1` — collect on every allocation. The most effective way to surface a missed root; slow on allocation-heavy tests (raise `TURF_TEST_TIMEOUT_SEC`).
- `TURF_GC_VALIDATE=1` (Linux/glibc/x86-64) — runs an independent full-stack mark phase and panics (`GC root missed`) if the production scan missed a block it reaches; also reports stray caller-saved register hits. Pair it with `TURF_GC_STRESS=1` to compare mark sets on every allocation.
- `TURF_GC_NO_PROCFS=1` — pretend `/proc/self/maps` is unreadable, exercising the stack-base fallback a procfs-less container takes (`scripts/gc_no_procfs_smoke.sh`).
- An ASan runtime: configure a separate `build_asan/` with `-DTURF_RT_SANITIZE=ON`, then `TURF_COMPILER=$(pwd)/build_asan/turfc ASAN_OPTIONS=detect_leaks=0 ./scripts/test_runner.sh`. Both build trees write the plain `lib/libturfrt.a`, so don't build one while a suite runs against the other.

`scripts/gc_stress_corpus_smoke.sh` runs the long-running programs in `tests/custom/gc_stress_corpus/`, which `test_runner.sh` never touches.

Two conventions the runner enforces:
- A file named `fail_*.tr` is expected to **fail to compile**. A plain-named `.tr` file is expected to **compile and run successfully** (for behavioral checks, `import test;` and call `test::assert(cond, "message")` inside `main()`; a bare `assert(...)` is E041 "Unknown function", because `assert` lives in the stdlib's `test` module, not in the prelude).
- A `fail_*.tr` file containing the marker comment `// RUNTIME_ABORT_EXPECTED` instead means: must compile successfully, then abort at runtime (non-zero exit) — for stdlib guards that fail at runtime, not compile time, e.g. bounds checks.
- **Pin the reason, not just the outcome (LEC-005, INV-TEST-2).** A test may also say *what the compiler said*, with comment markers the runner greps for in the compile output (ANSI colour stripped, matched literally): `// EXPECT-DIAG: E011` (the output contains `[E011`: the header reads `[E011 · control flow]`, so match the prefix, never a closing bracket), `// EXPECT-DIAG: some text` (contains that text — use this for a **warning**, which carries no code), `// EXPECT-NO-DIAG: some text` (must *not* contain it: the shape of a false-positive or cascade fix). For a `RUNTIME_ABORT_EXPECTED` test, `// EXPECT-RUNTIME: Integer overflow` requires the *program's* output to contain the text. Any number of lines, all must hold; they apply to `fail_*`, plain and abort tests alike (a plain test can pin the warnings it compiles with). Match prose, never column numbers or escape codes. **Every compile-time `fail_*` test must carry `// EXPECT-DIAG: Exxx`, and the runner fails it if not** (issue #263) — it is what stops a wrong-reason pass. Where one code covers several mistakes (`E066` is the type-mismatch catch-all: "Type mismatch!", "No matching overload!", "No such method!", "Missing initializer!"), also pin the message title with a second `// EXPECT-DIAG: <title>` line, because the code alone cannot tell them apart. The one exception is a test listed in **`tests/DIAGNOSTIC_GAPS.txt`**, the register of tests whose diagnostic is not pinned by a code. Beyond the `UNPINNED` back-fill baseline (which only ever shrinks; delete a line when you pin the test), it holds what a beginner-friendly compiler must not do: `WRONG-REASON` (the test is rejected for a *different* reason than it was written for), `NO-CODE` (the compiler prints a plain error with no `[Exxx]`, so `turf --explain` has nothing to say — the runner detects any codeless `── error` header itself and demands an entry), `GENERIC-CODE` (the right error under a catch-all code: E066's banner is free text, so the runner demands an entry for any E066 that is not "Type mismatch!") and `CASCADE` (one mistake, several errors). **Runtime-abort tests follow the same rule**: a `// RUNTIME_ABORT_EXPECTED` test must carry `// EXPECT-RUNTIME: <text>` (or `// EXPECT-EXIT: <status>` when the abort is silent by design, e.g. `sys::abort()` is 134). Entries are checked against the real compiler output, so a stale line fails the suite. When a test cannot be pinned to the diagnostic it was written for, **register it; do not weaken the test**, and do not add a new `UNPINNED` line for new work. Format and fix-it steps are in the file's header; the runner prints the register's size every run. The primary location of a diagnostic can be pinned too, through the source line it prints as its snippet (see `tests/38_monomorphization/fail_generic_requires_operator.tr`).

**The one trap everyone hits repeatedly on this project**: `scripts/test_runner.sh` silently *excludes* any file whose name ends in `_module.tr` (`grep -v "_module.tr"`), treating it as a companion/helper file with no `main()`. This means:
- A genuine standalone test named e.g. `scope_something_module.tr` is **silently skipped** — 0 result, not a failure, easy to miss entirely.
- A companion file (declares only functions/structs/enums, no `main()`, meant to be `import`ed by a real test) that does **not** end in `_module.tr` gets run as a standalone test and fails with "No entry point found."

After adding or renaming any test file, sweep both directions:
```bash
# standalone tests wrongly excluded (end in _module.tr but have a main())
find tests -name "*_module.tr" | xargs grep -lE '\bfn\s+(int\s+)?main\s*\('
# companions wrongly included (no main(), but don't end in _module.tr, and aren't a fail_* test)
find tests -name "*.tr" -not -name "*_module.tr" -not -name "fail_*" | xargs grep -LE '\bfn\s+(int\s+)?main\s*\('
```
Also watch for names that end in `_module.tr` as a plain SUBSTRING coincidence (e.g. `fail_import_nonexistent_module.tr`, `scope_struct_by_value_across_module.tr`) — the filter is a bare substring match, not a suffix-of-the-meaningful-name check.

**`scripts/test_runner.sh` only covers `tests/`.** For any change to language syntax or semantics, also grep/compile-check `lib/std/**/*.tr` and `showcase/*.tr` directly — neither is exercised by the test runner (the stdlib is only pulled in by whichever tests happen to `import` it, and showcase programs aren't run by it at all), so a stdlib or showcase file using old syntax can sit broken indefinitely with the full suite reporting green. Confirmed live: a language-syntax change once left two `lib/std/net.tr` (now `lib/std/io/net.tr`) methods on removed syntax, caught only by directly compiling the showcase programs that import `net`.

Compiling one of the 9 prelude modules (`int`/`double`/`bool`/`char`/`strings`/`array`/`io`/`math`/`sys` — see `PreludeModuleNames` in `src/ParserModule.cpp`, all under `lib/std/core/`) *directly* used to be a false positive: `ParsePreludeImports()` auto-imports all of them into every top-level file unconditionally, which meant compiling e.g. `lib/std/core/char.tr` itself imported `char` into `char.tr`, registering every one of its own functions twice (once as an ordinary top-level function, once again under its own module namespace) — any internal UFCS/operator self-call (`isAlpha()` calling `c.isUpper()`) then falsely reported "Ambiguous ... call", even though the identical code compiled and ran correctly as a real `import char;`-ing user program. Fixed by having `ParsePreludeImports()` skip a prelude name whose resolved stdlib path is the same file currently being compiled as the entry point (resolved via the same `TurfInstallRoot()`/`IndexModuleDir()` lookup a real import uses, so it can't disagree about where a prelude module actually lives). This direct-compile check (`turfc --resolve lib/std/core/char.tr`, etc.) IS this bug class's only regression coverage — `test_runner.sh` can't exercise it since none of the 9 prelude files have a `main()`. (`turfc --resolve` writes its binary into the current directory: run that loop from a scratch directory, not the repo root.)

## Repo map

- `src/`, `include/` — the compiler itself (Lexer, Parser, Resolver, TypeChecker, Codegen, Errors, SLM integration); builds to `turfc`.
- `cli/` — the `turf` front end, a standalone Go module (`github.com/turf-lang/turf-lang/cli`; its one third-party dependency is `github.com/BurntSushi/toml` for `turf.toml`, **vendored** in `cli/vendor/` so the build never needs the network; after adding or upgrading a Go dependency, run `go mod vendor` in `cli/` and commit it, or the build fails on an inconsistent vendor directory). It never parses TurfLang source and never rewrites a compiler diagnostic; see `cli/README.md`.
- `examples/` — multi-package TurfLang projects (`geometry`, a library; `plotter`, a program that depends on it), built with `turf`: the Part IX walkthrough as files, and what `docs/reference/projects_and_packages.md` quotes. `scripts/test_runner.sh` never builds them; only `scripts/examples_smoke.sh` does (in a temporary copy, so no `build/` lands in the checkout; it also checks each committed `turf.lock` is current with `--locked --offline`). Run it after any change to the CLI, the package graph or the language surface the examples use.
- `lib/std/` — the standard library, written in Turf itself, grouped into logical subfolders purely for browsing (`core/` — the nine prelude modules `int`/`double`/`bool`/`char`/`array`/`strings`/`io`/`math`/`sys`, which every file can use with no import and whose `io`/`math`/`sys` functions are callable by their bare names (`FREEZE.md` §6.25); `collections/` — `list`/`stack`/`queue`/`map`/`set`; `io/` — `net`; `mem/`, `time/`, `random/`, `fs/`, `json/`, `http/`, `testing/` — `test`). No compiler special-casing; ordinary `.tr` files. A module's subfolder is invisible to `import` — `import list;` doesn't care that `list.tr` lives under `collections/`; the compiler resolves a bare module name by recursively indexing `lib/std/**` once per compile (`IndexModuleDir()` in `src/Parser.cpp`), so moving a module between subfolders never requires touching an import statement anywhere. See `docs/architecture/modules_and_scope_resolution.md` Part 2.4 for the full search order and the `TURF_HOME` environment variable that anchors it (points at a Turf installation root — `$TURF_HOME/lib/std`/`lib/usr`; falls back to the compiler binary's own location if unset, so a plain dev build needs no setup).
- `include/turf/Analysis.h` — the compiler query facade (SMP-001): the stable 2.x API a tool (turf-lsp, the SLM Sandbox) uses to analyse source in-process. Never drive the Lexer/Parser/Resolver/TypeChecker directly from a tool; `docs/architecture/compiler_pipeline.md` §8 says why.
- `tests/` — the regression suite, organized by numbered topic folders (`06_structs`, `07_functions_modules`, etc.) plus `tests/99_known_bugs/` (excluded from the runner — documents accepted/deferred limitations, not live regressions) and `tests/custom/` (also excluded).
- `docs/reference/` — the user-facing language reference (one topic per file, `stdlib/` for the standard library), rewritten from scratch 2026-08-21 against the live compiler + test suite. Start at `docs/reference/README.md`. This is what a language-website "docs" section would be built from.
- `docs/architecture/` — deep internals references for specific subsystems, kept accurate and updated alongside the code they describe (e.g. `modules_and_scope_resolution.md` for the `::`/import system, `memory_model.md` for stack/heap/lifetime, `compiler_pipeline.md` for the Lexer→Parser→Resolver→TypeChecker→Codegen pass structure and CFG static analysis, both explained in CS terms rather than LLVM-specific ones). Read the relevant one before making non-trivial changes to that subsystem — don't re-derive from scratch.
- `docs/planning/` — roadmap and planning docs. `ROADMAP_v2.0.0.md` is the plan of record for what remains before the first public release; `FUTURE.md` is the post-2.0 backlog; `ROADMAP_v1.0.0_COMPLETE.md` and `ARCHITECTURE_OVERHAUL.md` are historical records (the Architecture Overhaul closed 2026-09-27 — `docs/development/changes/OVH-CLOSE.md`).
- `scripts/` — `cmake_build.sh` (build), `test_runner.sh` (test: a wrapper over `turfc --test`), `test_cmd_smoke.sh` (`turfc --test`/`turf test` conventions), `fmt_smoke.sh` (`turf fmt`/`turfc --format`: modes, the verified-result guarantee, idempotence over the repo's own files; run it after touching `src/Formatter.cpp`), `compile_and_run.sh` (compile+run+cleanup one file), `cli_smoke.sh` (the `turf` front end against the real `turfc`), `package_release.sh` (the release archive, REL-003 layout; CI publishes what it builds), `release_smoke.sh` (packages the archive, installs it with the repo-root `install.sh` into a temporary HOME and uses only that: run it after touching either, the packaging or the CLI's install-root lookup), `cross_target_smoke.sh` (`--target` for a foreign machine: object kept, TurfLang diagnostic, no host-linker text), `gen_recipes.sh` (Homebrew/Scoop/AUR recipes from a release's `checksums.txt`), `bundled_link_smoke.sh` (REL-008 stage 3: the embedded lld against a stand-in C runtime with a decoy `cc` on PATH; needs `TURFC=` a turfc built with `--release-static --embed-lld`, else SKIPs), `release_deps_check.sh` (REL-008 stage 1: reads an archive's binaries' headers and fails on any library the operating system does not provide; it is **red by design** until REL-008 stages 2-4 land, so never widen its allowlist to turn it green).
- `.github/workflows/` — `test.yml` (the suites, Linux), `build-archives.yml` (the four release builds: build, package, smoke, dependency check; reusable), `release-shaped-ci.yml` (calls it on every push/PR; publishes nothing; its dependency-check step is expected red until REL-008 stage 4) and `release.yml` (a `v*` tag: calls it, then publishes). The release is built by the same workflow CI runs, so edit `build-archives.yml`, not a copy.
- `docs/development/` — **if your task is one of the architecture-overhaul feature groups (`ARCH-001`, `TYPE-001`, `SEM-001`, … — `docs/planning/ARCHITECTURE_OVERHAUL.md` Appendix B), read `docs/development/SESSION_PROTOCOL.md` and follow it**; it adds a freeze document, a change record per feature group, and `scripts/session_{pre,post}flight.sh` on top of everything in this file. This file stays the source of truth for build and test conventions.

## Conventions this project holds firmly to

- **Doc comments explain WHY, not what.** A hidden invariant, a past bug this code prevents, a non-obvious constraint — not a restatement of the code. Applies to functions touched by a fix and closely adjacent ones.
- **Every fix gets a regression test** in `tests/<NN_topic>/`, following that folder's existing naming/numbering. A bug fix needs both directions covered where it makes sense: a `fail_*.tr` proving the bad case is now rejected, and/or a plain `.tr` proving the good case still works.
- **Small, scoped commits.** One logical fix or feature per commit, not batched sweeps, with a message explaining the *why* and the failure scenario that motivated it — future readers (human or agent) should be able to understand a change from its commit message alone.
  - Title format is `type(scope): summary (@username)` — Conventional Commits (`feat`/`fix`/`test`/`docs`/`refactor`/`misc`, optional parenthesized scope) with the committer's own `git config user.name` appended in parens at the very end. Consistent across recent history; match it going forward even though older commits predate it.
  - No `Co-Authored-By` trailer or other AI-attribution text in the message body.
- **Everything a module declares is private unless it says `pub`/`public`** (LEC-002, `FREEZE.md` §6.15): functions, methods, structs, enums, errors, machines, extern fns and struct **fields**. A test companion (`*_module.tr`) or a `lib/std` module that another file uses needs `pub` on exactly what that file touches — a call, a type, a field, a method, a UFCS receiver. `E088` names the file and the spelling to add; `turf --migrate=pub --write <module.tr>...` adds it everywhere (the old behaviour) if you'd rather prune afterwards. A `pub` signature or field may not mention a private type (`E089`). The main program file needs none of this. Don't widen `lib/std` to make a test pass — a test that needs `List.data` should declare its own struct with a `data: T*` field (see `tests/05_arrays_pointers_ffi/raw_pointer_index_inside_unsafe_ok.tr`).
- **A `fail_*.tr` proves the file failed to compile, not that it failed for the reason it names.** After adding or changing one, compile it and read the error code. Two wrong-reason "passes" were caught this way during LEC-002 (a reserved word — `run`, `step`, `pub` — used as a name in a companion; and a test that started failing on E088 instead of the gate it was written for). For anything with a distinct error code, assert the code and a fragment of the hint in `tests/api/analysis_test.cpp` (see `testPrivateSymbolAccess`).
