TurfWarning: Non-Interrupting Warning Infrastructure

1. Changes Made:
- Added `TurfWarning` class to `include/Errors.h`, placed immediately after the `TurfError`
  base class and before the `SyntaxError` subclass.
- `TurfWarning` holds a `SourceLocation Loc` and `std::string Message` (both `protected`
  to allow future warning subclasses to build on top of it, mirroring `TurfError`'s layout).
- `TurfWarning::emit()` calls `DiagnosticEngine::add(Loc, Message, /*IsWarning=*/true)` and
  returns normally — it never touches `longjmp`, `std::exit`, or `g_recoverJmp`.
- Added three test files in `tests/warnings/`:
    - `issue173_shadowing_warn.tr`  — nested variable shadowing triggers `ShadowingWarning`
    - `issue173_redundant_cmp_warn.tr` — inner-scope shadowing (second shadowing scenario)
    - `issue173_self_assign_warn.tr`  — `x = x` triggers `SelfAssignmentWarning`
- Added `tests/warnings/run_issue173_tests.sh`: a test runner that compiles each file,
  asserts a "warning" diagnostic is present in compiler output, runs the produced binary,
  and asserts the expected program output is printed. All 3 tests pass.

2. Why the Change was Made:
- Every CFG analysis pass (Issues #185, #186) must emit warnings without halting the
  compilation pass. The existing `TurfError::raise()` path calls `longjmp` and aborts the
  current pass entirely, which is correct for errors but wrong for warnings.
- Previously, warning classes (`ShadowingWarning`, `UnreachableBlockWarning`, etc.) were
  forced to subclass `TurfError` and use the same `raise()` path, which was incorrect by
  design. `TurfWarning` provides the correct mechanism: register and return.

3. How it Helps/Changed:
- `TurfWarning(loc, "msg").emit()` adds a yellow "warning" entry to the
  `DiagnosticEngine` and returns without interrupting the compilation pass.
- A source file that triggers only warnings still compiles to a binary successfully.
- Warnings appear after the build output, sorted by line number (same as errors), because
  `DiagnosticEngine::flushAll()` already sorts all diagnostics together by line/column.
- No existing `TurfError` subclass is affected.
- `DiagnosticEngine::add(IsWarning=true)` and `printDiag()` were already fully implemented
  to render warnings with `Colors::BRIGHT_YELLOW` and the label "warning" — no rendering
  path changes were needed.

4. Reference & Usage Examples (Source of Truth):

a) Emitting a warning that does not interrupt compilation:
```cpp
// In any analysis pass — safe to call anywhere:
TurfWarning(Loc, "msg").emit();
// Execution continues here normally.
```

b) Creating a warning subclass (for CFG analysis passes):
```cpp
class CfgUnreachableWarning : public TurfWarning {
public:
  CfgUnreachableWarning(SourceLocation Loc, const std::string &BlockName)
      : TurfWarning(Loc, Colors::BRIGHT_YELLOW +
                             "Unreachable block: '" + BlockName + "'." +
                             Colors::RESET) {}
};

// Usage:
CfgUnreachableWarning(loc, "then-branch").emit();
// Analysis continues.
```

c) Compiler output when a warning file is compiled:
```

  Warning: Just so you know, you're creating a new 'x' that hides an older one!
  Note: The older one is at line 9, column 5

     │         ^ Here!

Compiled to program.o
Successfully compiled to program
```
