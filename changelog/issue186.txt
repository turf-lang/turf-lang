CFG Phase 2: Liveness Analysis & Infinite Recursion Detection

1. Changes Made:
- Declared `LivenessAnalysisPass` in `include/Analysis.h` to perform backward data-flow analysis on the Control Flow Graph.
- Added `DeadStoreWarning`, `UnusedVariableWarning`, and `RecursionWithoutBaseError` diagnostic classes in `include/Errors.h`.
- Implemented `LivenessAnalysisPass::runOnCFG()` in `src/Analysis.cpp` using a worklist algorithm to compute `Gen_`, `Kill_`, `LiveIn_`, and `LiveOut_` sets for accurate liveness tracking of variable symbols.
- Added `allPathsRecurse()` and `blockContainsSelfCall()` methods to `CFG` class in `include/CFG.h` and `src/CFG.cpp`, utilizing Depth First Search to check if all paths from entry to exit pass through a self-recursive function call.
- Wired `LivenessAnalysisPass` and `CFG::allPathsRecurse()` into the compilation pipeline in `src/Codegen.cpp` immediately following `AliasAnalysisPass`.
- Created regression test suite in `tests/14_cfg_analysis/` (tests 10-25) verifying liveness (dead stores, unused vars, read-modify-write) and comprehensive infinite recursion scenarios.

2. Why the Change was Made:
- Turf lacked analysis to catch common logic errors like assigning a value to a variable that is immediately overwritten or never read, which usually indicates a typo or forgotten logic.
- Variables declared but never used clutter the codebase and decrease maintainability.
- Recursive functions without a base case will unconditionally cause a stack overflow (segmentation fault) at runtime, which should be caught at compile-time when possible.

3. How it Helps/Changed:
- Variables that are assigned a value that is never subsequently read will emit a non-interrupting `DeadStoreWarning`.
- Variables that are declared but never used in any capacity will emit a non-interrupting `UnusedVariableWarning`.
- Functions where every single execution path leads to a self-call with no base case (e.g., `fn foo(): int { return foo(); }`) will emit a fatal `RecursionWithoutBaseError`, preventing compilation.
- Both non-interrupting warnings allow compilation to continue, while the infinite recursion check guarantees safety by aborting compilation.
- Parameters are properly excluded from liveness warnings to match expected standard behavior.

4. Example Diagnostic Output Format:
── warning at line 3, col 5

  Warning: Variable 'x' is declared but never used.

  Hint: If the variable is intentionally unused, prefix its name with '_' by convention. Otherwise, remove the declaration or use its value.

  3 │     mutable x: int = 5;
    │     ^ Here!

── warning at line 5, col 5

  Warning: Variable 'x' is assigned but the value is never read (dead store).

  Hint: The assigned value is overwritten or the function returns before this variable is ever used. Remove the assignment or use the value.

  5 │     x = 10;
    │     ^ Here!

── error at line 2, col 1

  Error: Infinite recursion detected. Every path through this function calls itself with no base case.

  Hint: A recursive function must have at least one path (a base case) that returns without calling itself.

  2 │ fn loop_forever(): void {
    │ ^ Here!
