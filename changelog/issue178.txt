Default Variable Initialization
 
1. Changes Made:
- Forward-declared `DefaultInitExprAST` in `include/ASTVisitor.h` and added `visitDefaultInit` visitor method.
- Defined `DefaultInitExprAST` in `include/AST.h` and updated `VarDeclExprAST` to carry `HasExplicitInit` flag.
- Implemented `visitDefaultInit` in `include/ASTPrinter.h`.
- Added `visitDefaultInit` in `include/Resolver.h` and `src/Resolver.cpp` to resolve default initializations.
- Added `visitDefaultInit` in `include/TypeChecker.h` and `src/TypeChecker.cpp` to typecheck zero-initialized struct fields and other types.
- Added verification in `TypeChecker::visitVarDecl` to ensure immutable variables (`immutable x: T;`) are not declared without an explicit initializer.
- Implemented `SynthesizeDefault` helper in `src/Parser.cpp` and updated `ParseLetStatement` to auto-inject zero values for variables declared without `= value`.
- Implemented `DefaultInitExprAST::codegen()` in `src/Codegen.cpp` using `GetDefaultValue` helper.
- Implemented `visitDefaultInit` in `src/Analysis.cpp` for control-flow analysis.
- Added unit and negative tests under `tests/03_typechecker/`.

2. Why the Change was Made:
- Previously, declaring a variable without an explicit initializer (e.g. `mutable x: int;`) left its value uninitialized, which led to undefined behavior at runtime.
- Auto-injecting zero values (like `0` for `int`, `0.0` for `double`, `false` for `bool`, `""` for `string`, and `null` for pointers) makes the language safer by eliminating uninitialized variable bugs.
- Deferring struct type default-initialization to a `DefaultInitExprAST` allows the TypeChecker to resolve struct definitions and ensure struct field defaults are recursively injected correctly.

3. How it Helps/Changed:
- Variable declarations without initializers (e.g., `mutable count: int;`) are now fully supported and safely zero-initialized based on their types.
- Declaring an immutable variable without an initializer (e.g., `immutable x: int;`) now correctly triggers a compile-time error.
- Default variable initialization integrates perfectly with typechecking, name-resolution, and control-flow lint checks.

4. Example Diagnostic Output Format (for immutable declaration missing initializer):
── error at line 2, col 5

  Type mismatch!
  Immutable variable 'PI' requires an explicit initializer.

  Hint: Check that you're not mixing incompatible types (like assigning a string to an int variable).

  2 │     immutable PI: double;
    │     ^ Here!
