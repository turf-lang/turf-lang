Unify if and Ternary Operator Syntax

1. Changes Made:
- Removed the `then` keyword from the compiler. Expression-style `if cond then a else b` is deleted.
- Enforced braces `{ }` for all block-style `if` and `elseif` statements in the parser (`src/Parser.cpp`, `ParseIfExpr`). If braces are missing, the compiler reports an error.
- Implemented the ternary operator with the syntax `cond give a otherwise b` in `src/Parser.cpp` (`ParseExpression`). This parsed operator is desugared inline to an `IfExprAST`.
- Added the keywords `give` and `otherwise` to the lexer keywords mapping, and removed `then`.
- Updated the TypeChecker (`src/TypeChecker.cpp`, `TypeChecker::visitIf`) to dynamically detect if an `IfExprAST` represents a ternary expression (based on the lack of `BlockExprAST` in the branches). If so, it infers the expression type as the common promoted type of the `then` and `else` branches rather than unconditionally setting it to `void`.
- Refactored `SourceFile` (the global input stream) in the Lexer, Parser, and Sandbox components from a moved `std::ifstream` object to a pointer (`std::ifstream*`). This resolved a critical stream corruption and resource release bug caused by `std::move` and destruction of moved-from streams in libc++ on macOS/Darwin.
- Updated the `@intrinsic` handling for `assert` / `fail` in `src/Builtins.cpp` to dynamically select the correct target symbol for `stderr` (`__stderrp` on macOS/Darwin, `stderr` on other platforms) based on preprocessor configuration, ensuring static linking succeeds on macOS.

2. Why the Change was Made:
- Removing the `then` keyword standardizes standard block `if` control flow structures.
- The new `cond give a otherwise b` ternary syntax replaces traditional ternary operators like `cond ? a : b` to avoid symbol collision / parser ambiguity with the type-annotation colon introduced in Issue #150.
- Proper type checker inference for ternaries allows using them inside variable declarations and assignments (e.g. `mutable abs_x: int = x > 0 give x otherwise -x;`).
- Moving away from `std::ifstream` move operations solves compiler crashes on macOS due to stream state loss.

3. How it Helps/Changed:
- Cleans up language syntax and enforces consistent style with mandatory block braces.
- Prevents syntax ambiguities while keeping single-expression conditional evaluations simple and readable.
- Enables compilation and verification of compiler components natively on macOS/Darwin without stream or linking errors.

4. Reference & Usage Examples (Source of Truth):

a) Standard Block If (Mandatory Braces)
Syntax:
  if <cond> {
      <body>
  } elseif <cond> {
      <body>
  } else {
      <body>
  }
Example:
  if x > 0 {
      io.printline("positive");
  } else {
      io.printline("non-positive");
  }

b) Ternary Conditional
Syntax:
  <cond> give <thenExpr> otherwise <elseExpr>
Example:
  mutable abs_x: int = x > 0 give x otherwise -x;

c) Nested Ternary Conditional
Syntax:
  <cond> give <thenExpr> otherwise (<cond> give <thenExpr> otherwise <elseExpr>)
Example:
  mutable res: int = a > b give 10 otherwise (a == b give 20 otherwise 30);
