String Operations (+, ==, s[i])

1. Changes Made:
- Updated `TypeChecker::inferArithmeticType()` in `src/TypeChecker.cpp` to emit a helpful hint instructing users to convert non-string operands using `<expr> to string` when attempting string concatenation with non-string types.
- Updated `TypeChecker::visitArrayAccess()` in `src/TypeChecker.cpp` to recognize `string` base expressions and infer `int` return type for character access (`s[i]`).
- Implemented `EmitStringConcat()` helper and `+` string concatenation handling in `BinaryExprAST::codegen()` in `src/Codegen.cpp` using heap allocation (`malloc`, `strcpy`, `strcat`).
- Implemented `EmitStrcmp()` helper and deep content comparison for string equality (`==`) and inequality (`!=`) in `BinaryExprAST::codegen()` in `src/Codegen.cpp`.
- Implemented string character access (`s[i]`) in `ArrayAccessExprAST::codegen()` in `src/Codegen.cpp` via GEP pointer arithmetic and zero-extension (`i8` to `i64`).
- Updated `getExprType()` in `src/Codegen.cpp` to resolve variable symbols via `NamedValues` and return `int` when indexing a `string` expression.
- Added comprehensive positive and negative test suite in `tests/12_string_ops/` covering concatenation, equality, character access, and acceptance criteria.
- Enabled previously commented-out string equality assertions in `tests/03_typechecker/05_cast_full.tr`.

2. Why the Change was Made:
- Strings in Turflang were raw C strings (`i8*`) without core string operations: concatenation (`+`), content equality (`==`), and character access (`s[i]`).
- String `==` previously compared raw pointer addresses rather than string content, causing confusing behavior.
- String indexing (`s[i]`) previously failed at compile time because strings were not treated as indexable types.

3. How it Helps/Changed:
- "Hello, " + "world" now compiles and produces "Hello, world" at runtime.
- String equality (`==` and `!=`) compares actual character content correctly.
- Character access (`s[i]`) produces the ASCII character code as an `int` (e.g. "hello"[1] evaluates to 101).
- Concatenating a string with a non-string type produces a clear TypeChecker diagnostic with an actionable hint to use `<expr> to string`.

4. Example Diagnostic Output Format:
── error at line 3, col 26

  Type mismatch!
  Cannot apply operator '+' to types 'string' and 'int'. Hint: To concatenate a non-string, convert it first with `<expr> to string`.

  Hint: Check that you're not mixing incompatible types (like assigning a string to an int variable).

  3 │     mut s: string = "hi" + 5;
    │                          ^ Here!
