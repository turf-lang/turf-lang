Strict Semicolon Rule: Delete RequiresSemicolon()

1. Changes Made:
- Deleted the `RequiresSemicolon` function and all its references in `include/Parser.h`, `src/Parser.cpp`, and `src/main.cpp`.
- Updated `ParseLetStatement` to expect and consume a semicolon `;` at the end of both array and standard variable declarations, raising `"Expected ';' after statement."` if missing.
- Updated `ParseBlock` to implement the new strict semicolon rule: expression statements must end with a semicolon, and block-producing constructs (`if`, `while`, `for`, `fn`, `struct`) must not have a semicolon (raising `"Unexpected ';'`" if followed by one).
- Updated `ParseFile` to implement the same rules for standard library files and imports.
- Updated top-level parsing loops in `src/main.cpp` (both pre-pass and main-pass) to follow the strict semicolon rules for top-level constructs.

2. Why the Change was Made:
- The dynamic_cast-based `RequiresSemicolon` checks on AST nodes were expensive and fragile, breaking whenever new AST nodes or constructs were introduced.
- Standardizing a simple and absolute semicolon rule based on block-producing constructs vs expression statements simplifies parsing and increases compiler performance and reliability.

3. How it Helps/Changed:
- Streamlines parsing logic, making the code much easier to maintain.
- Provides clean, clear compiler error diagnostics when semicolons are either missing from statements or incorrectly placed after block constructs.

4. Reference & Usage Examples (Source of Truth):

a) Expression Statements (Require `;`)
Syntax:
  <expression>;
Example:
  mutable x: int = 5;
  x = x + 10;

b) Block-producing constructs (Do NOT have `;`)
Syntax:
  if <cond> {
      ...
  }
  while <cond> {
      ...
  }
Example:
  if x > 0 {
      io.printline("positive");
  }
