FFI Hardening: extern fn, ptr type system, variadic ..., extern from "lib", --link

1. Changes Made:

Phase A — ptr type system (src/Codegen.cpp):
- `getTurfTypeFromLLVM`: all LLVM `PointerType` nodes now map to `TurfPtr()` instead
  of the incorrect `TurfString()`. This was the root cause of every "cannot assign
  extern fn return value to a ptr variable" failure.
- `RefineLLVMType`: extended the refinement check to also cover `OpaquePointerType`
  and `string` in the expected-type guard, so `mutable s: string = extern_fn()` still
  resolves correctly by context.
- Added `isPointerLike(const TurfType *)` helper: centralises the check for
  `string`, `ptr` (OpaquePointerType), `T*` (TurfPointerType), and `void*` — all
  share the same LLVM opaque pointer representation and should be freely cast between.
- `CastToType`: pointer-like types now cast freely between each other (no-op at the
  IR level). The string guard now only fires when one side is genuinely non-pointer.
- `isTypeCompatible`: all pointer-like types are mutually compatible by definition.
- `getExprType` for `FuncCallExprAST`: removed hardcoded `malloc`/`realloc`/`free`
  return-type constants; they now resolve through `FuncReturnTypes` lookup first
  (covers user `extern fn` declarations), with an intrinsic fallback at the bottom.

Phase B — malloc/realloc/free builtin collision (src/Codegen.cpp):
- `FuncCallExprAST::codegen` early-dispatch: the builtin path for `malloc`/`realloc`/
  `free` is now skipped when the user has declared an `extern fn` with that name
  (detected via `TheModule->getFunction(CalleeName)`). The user `extern fn` declaration
  wins; the builtin path is taken only when no user declaration exists. Fully backward
  compatible with `import mem` / `@intrinsic("malloc")` path.

Phase C — variadic `...` (include/Lexer.h, src/Lexer.cpp, include/AST.h,
           src/Parser.cpp, include/ResolverSymbolTable.h, include/SymbolTable.h,
           src/Resolver.cpp, src/TypeChecker.cpp, src/Codegen.cpp):
- `TOK_ELLIPSIS = -73` added to `include/Lexer.h`.
- `src/Lexer.cpp`: `...` is lexed before `..` (range operator) so three dots are
  not consumed as a range token plus a stray dot.
- `include/AST.h` (`ExternFuncDeclExprAST`): added `IsVarArg_` (bool) and `LibName_`
  (string, for Phase D) fields; added `isVarArg()` and `getLibName()` accessors;
  updated constructor and `clone()`.
- `src/Parser.cpp` (`ParseExternDecl`): detects `TOK_ELLIPSIS` at the start of a
  param slot (pure vararg) and after a comma (printf-style); sets `IsVarArg = true`
  and breaks from the param loop; passes `IsVarArg` to the constructor.
- `include/ResolverSymbolTable.h` (`ResolverFunctionSymbol`): added `IsVarArg` field
  and `isVarArg()` accessor.
- `include/SymbolTable.h` (`FunctionSymbol`): added `IsVarArg` field to keep
  `GlobalSymbolTable` registration in sync.
- `src/Resolver.cpp` (`hoistTopLevel`, `visitFuncCall`): `Sym.IsVarArg` set from
  `Extern->isVarArg()`; arity check accepts `ArgCount >= Sym->arity()` for vararg
  symbols; candidate collection uses the same condition.
- `src/TypeChecker.cpp` (`visitFuncCall`): Step a (arity filter) accepts vararg
  candidates when `ArgCount >= Cand->arity()`; Step b (type-compat loop) checks only
  declared params via `min(ArgCount, Cand->arity())`; best-match narrowing loop uses
  same bound.
- `src/Codegen.cpp` (`ExternFuncDeclExprAST::codegen`): passes `IsVarArg_` to
  `FunctionType::get` — emits `declare i32 @printf(ptr, ...)` correctly; sets
  `FSym.IsVarArg` when registering in `GlobalSymbolTable`.
- `src/Codegen.cpp` (`FuncCallExprAST::codegen`): after the declared-params arg loop,
  if `CalleeF->isVarArg()`, all remaining `EvaluatedArgs` are appended raw (no
  `CastToType`) — correct C vararg ABI.

Phase D — extern from "lib" fn + --link (src/Parser.cpp, src/Codegen.cpp, src/main.cpp):
- `src/Parser.cpp` (`ParseExternDecl`): after eating `extern`, optionally parses
  `from "libname"` before `fn`; error path includes panic-mode recovery (skip to
  `;` or EOF) so the next valid statement parses cleanly.
- `src/Codegen.cpp`: added `std::set<std::string> g_RequiredLibs` global; populated
  in `ExternFuncDeclExprAST::codegen` when `LibName_` is non-empty; `codegen` now
  returns `F` (the declared `Function*`) instead of `nullptr`.
- `src/main.cpp`:
  - `CompilerOptions`: added `LinkLibs` (`std::vector<std::string>`) field.
  - `parseArgs`: handles `--link <name>` flag; appends to `LinkLibs`.
  - `linkObject`: signature extended with `ExtraLibs` param; merges `g_RequiredLibs`
    (from source annotations) and `ExtraLibs` (from CLI) into a `std::set`
    (deduplication); appends `-l<name>` for each entry.

Test files added:
- `tests/ffi_ptr_showcase.tr`: end-to-end showcase of `malloc`/`free`/`memset`/
  `strlen`/`puts`/`atoi` via `extern fn`.
- `tests/ffi_ptr_verify.tr`: 7-checkpoint ptr verification — ptr as turf fn param,
  ptr as turf fn return type, `mutable h: ptr = null`, multi-ptr independence,
  chained extern calls, string-to-ptr implicit coercion.

2. Why the Change was Made:
- Before this change, all extern fn return values of pointer type were incorrectly
  typed as `string` by `getTurfTypeFromLLVM`, making `mutable raw: ptr = malloc(64)`
  a type-error at compile time.
- `malloc`/`realloc`/`free` were always intercepted by the builtin early-dispatch
  before user `extern fn` declarations could take effect, so declaring them as
  `extern fn` produced silent wrong codegen.
- Variadic C functions (`printf`, `sprintf`, `fprintf`, `snprintf`, etc.) could not
  be declared at all; any attempt caused a WrongArityError at the Resolver.
- There was no way to annotate which library an extern fn requires, making it the
  user's responsibility to manually pass `-l` flags to the linker externally.
- Without `--link`, users had no in-language way to add linker flags without editing
  the compiler source.

3. How it Helps/Changed:
- All C pointer-returning functions can now be declared and called cleanly:
    extern fn malloc(size: int): ptr;
    mutable raw: ptr = malloc(64);   // compiles and runs correctly
- All C variadic functions are now first-class:
    extern fn printf(fmt: string, ...): int;
    printf("val: %d\n", 42);         // emits: declare i32 @printf(ptr, ...)
- Library annotation drives the linker automatically — no manual flags needed:
    extern from "m" fn pow(base: double, exp: double): double;
    // linker receives: cc program.o -o program -lm -lm (deduplicated)
- `--link` provides an escape hatch for libraries not annotated in source.
- Pointer types (`ptr`, `string`, `T*`, `void*`) are now all mutually compatible at
  the Resolver, TypeChecker, and Codegen layers with zero IR-level casts.
- `ptr` flows through Turflang-defined functions as first-class parameters and return
  types with `define internal ptr @fn_name(ptr %p)` — no wrapper or conversion.

4. IR correctness examples:

a) extern fn malloc with ptr assignment:
    extern fn malloc(size: int): ptr;
    mutable raw: ptr = malloc(64);
    // IR: %calltmp = call ptr @malloc(i64 64)  — no bitcast, no inttoptr

b) Variadic printf:
    extern fn printf(fmt: string, ...): int;
    printf("value: %d\n", 42);
    // IR: declare i32 @printf(ptr, ...)
    //     %calltmp = call i32 (ptr, ...) @printf(ptr @str, i64 42)

c) extern from auto-link:
    extern from "m" fn pow(base: double, exp: double): double;
    // Linker command: cc program.o -o program -lm

d) Turflang fn with ptr param and return:
    fn make_buffer(size: int): ptr { ... return p; }
    // IR: define internal ptr @turf_make_buffer_int(i64 %size)
    //          ret ptr %calltmp
