## Why
`ROADMAP_v2.0.0.md` REL-001. Much of it had already landed under LEC-001
(`turf version`/`--version`, `turf help` and `turf <cmd> --help`, subcommand
dispatch, "did you mean" for unknown *commands*, the driver-interface line,
the ABI stamp symbol). What was still open on 2026-10-06:

- `--version` showed neither the LLVM version, the runtime ABI nor the install
  root, the three facts a bug report needs.
- `turfc` had no help text of its own at all, and `turfc --bogus` /
  `turf --bogus` printed a bare `Unknown option` with no suggestion, exit 1.
- Exit codes were undecided: `turfc` usage errors shared status 1 with compile
  errors, while `turf`'s own usage errors were 2.

## Language semantics
### Old behaviour
`turfc pass.tr --chek` → `Unknown option: --chek`, exit 1.
### New behaviour
→ `Unknown option: --chek`, `did you mean '--check'?`, exit 2.
### Is this breaking?
Only for a script that treated *every* nonzero `turfc` status as "compile
error" and distinguished usage errors by status 1. None in this repo does.
Driver interface goes 1.1 → 1.2 (additive); `turf` still needs only 1.1.
No TurfLang source is affected.

## Compiler architecture
- **Driver (`src/main.cpp`)** · `ExitOk/ExitError/ExitUsage`; every
  command-line mistake exits `ExitUsage` (unknown option, option without its
  value, no input, non-`.tr` input, bad `-O`, unknown `--migrate=` name, unknown
  or missing `--explain` code, `--module` without `--check`, `--migrate=pub`
  with no files). Read/write failures, bad package graphs and compile errors
  stay 1. `unknownOption()` suggests via `getDamerauLevenshteinDistance`
  (<= 2, only for arguments longer than 3 chars, `name=` flags compared with
  the `=`). `turfc help` prints `turfcUsage()` and exits 0; `turfc --help` is
  deliberately still an unknown option, pointing at `turfc help` (owner
  decision). `--version` gains `llvm`, `runtime`, `root` lines; the install root
  is printed resolved, so `<build>/..` shows as the real directory.
  `CompilerExecutablePath` is now set before `--version` is answered, which
  only reads the environment and that path.
- **Codegen** · `RuntimeAbiSymbol` (`include/Codegen.h`) replaces the string
  literal in `WrapMainWithRuntimeBootstrap()`.
- **`turf` (Go)** · `driver.CompilerInfo.Extra` keeps `turfc --version` lines
  3+; `turf version` prints them indented under turfc's line; `turf help`
  documents the statuses.

## New invariants
- F-CLI-1..4, `FREEZE.md` §6.21. Enforced by `scripts/cli_smoke.sh` (each status
  and message asserted, `turf --bogus` byte-identical to `turfc --bogus`).
- The ABI symbol the compiler names is the one `libturfrt.a` defines:
  `cli_smoke.sh` runs `nm` on the archive against `turfc --version`'s
  `runtime` line (C cannot read the C++ constant, so a check is the only link).

## Removed assumptions
- "A nonzero `turfc` status means the program is wrong." It can now mean the
  command line is (2).
- "`turfc` prints only two lines for `--version`." Only lines 1-2 are the
  contract; `turf` ignores the rest (`Extra` is display-only).

## Known pitfalls
- `turf run` returns the program's status, so a program returning 2 looks like
  a usage error there. Documented, not fixable without breaking `exec`.
- The suggestion bar ignores arguments of 3 chars or fewer: `-x` is within 2
  edits of `-g`, which would be a wrong guess.
- Keep the `KnownOptions` table in step with `parseArgs()`; a new flag missing
  from it still works but is never suggested.

## Unresolved questions
- **Version single-sourcing.** The roadmap asks for the version to come from
  one place into the binary, the runtime, the archive name and the README.
  Today `turfc` reads `VERSION`, `turf` has its own constant (independent by
  F-PKG-1), the archive name comes from the git tag, and the README says
  `v1.0.0`. **Deferred by the owner (2026-10-06) to the release work
  (REL-003/REL-008)**, which changes how the archive is built anyway. Until
  then, before tagging, check by hand that `VERSION`, the tag and the README
  line agree. The proposal on the table: name the archive after `VERSION`, make
  the release workflow fail if the tag differs, and check the README line.
