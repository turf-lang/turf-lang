## Baseline

tests, `turf-api-tests` passing, doc links resolving. After: **964/964** (916 + 48 new) at the
default level and at `-O0`, `turf-api-tests` passing.

## Why

Error variants were bare names (plus STD-002's one universal `string` message).
There was no typed payload (`FileNotFound(path)`), no way to read one, and no
propagation shorthand: every call site wrote `recover as err run { return err; }`
(eleven copies in `json.tr` alone), and returning a `!T` call's result from a
`!T` function was rejected with the self-contradictory "function declares
'!Rec' but returns '!Rec'" (audit F-21). LEC-003 supplied the missing half of the
payload problem — destructuring — so this is the feature that uses it.

## Language semantics

### Old behaviour

```turflang
error IOError { NotFound, Denied }
fn open(p: string): !int { return IOError::NotFound("msg"); }   // the message was the only data
fn load(p: string): !int {
    immut n: int = open(p) recover as err run { return err; };    // the whole propagation story
    return n;
}
fn viaReturn(p: string): !int { return open(p); }                // rejected: '!int' but returns '!int'
```

### New behaviour

```turflang
error IOError { NotFound(path: string), Denied(path: string, mode: int), Timeout }

fn open(p: string): !int { return IOError::Denied(p, 7, "no access"); }  // fields, then a message
fn load(p: string): !int { return try open(p) + 1; }                     // try: pass the error on
fn viaReturn(p: string): !int { return open(p); }                        // passes through unchanged

fn code(p: string): int {
    immut v: int = load(p) recover as err run {
        compare err {
            matches IOError::NotFound(path):          return 1; done
            matches IOError::Denied(path, mode) if mode == 7: return 2; done
            matches IOError::Timeout:                 return 3; done
            otherwise:                                return 99;
        }
    };
    return v;
}
```

The rules are `FREEZE.md` §6.18 and `docs/reference/error_handling.md`. In brief:
a variant declares typed fields; constructing takes N arguments or N+1 with a
trailing `string` message; a bare `E::V` for a variant with fields is not a value
(only an `==`/`!=` operand or a pattern head); a payload is read only by a
pattern (`matches E::V(a, ..)`, positional, every field or `..`); `try` is a
prefix keyword that returns the error unchanged from an enclosing `!V` function
and runs pending `defer`s; `return f();` of exactly the function's own `!T` passes
through.

### Is this breaking?

Barely, and every case is an error that is either new syntax or was already wrong:

- **`try` is a reserved word.** Grepped `tests/`, `lib/`, `showcase/`, `examples/`,
  the README: no identifier spelled `try`. `cli/internal/manifest/manifest.go`'s
  reserved list (copied by hand from the lexer, checked by `scripts/project_smoke.sh`)
  gained it.
- **Adding fields to an existing variant breaks its constructions** — by design
  (`IOError::NotFound` alone is E096). That is why the stdlib migration below
  changed both producers and left `==` comparisons alone (equality reads the
  variant only). A caller that *constructs* `io::FileError::NotFound` itself now
  needs a path; none existed in the repo.
- A `compare` over an error value now accepts variant patterns; everything that
  compiled before still does (no test changed).
- `err == E::V("msg")` (a comparison against a fresh message construction) used to
  be a type error and now works (see *Removed assumptions*).

## Compiler architecture

Pass by pass; `docs/architecture/errors_and_recover.md` §1.2b, §1.4.4, §1.10, §1.11 and
§2 have the detail.

- **Lexer** — `TOK_TRY` (`-108`), reserved.
- **Types** — `ErrorPayloadField`, `ErrorVariantInfo`; `TurfUserErrorType` holds per-variant
  field lists (`getVariantInfo()`), `getVariants()` is still the names.
- **AST** — `ErrorDeclExprAST` holds `ErrorVariantInfo`s; new `TryExprAST`,
  `ErrorVariantPatternExprAST`; `ScopeAccessKind::ErrorVariantConstructWithMessage`
  renamed `ErrorVariantConstruct`; `ScopeAccessExprAST::IsTagOperand`;
  `ReturnExprAST::PassesThroughFallible`; `FuncDefExprAST::UsesTry`. `ASTVisitor`
  gained `visitTry` / `visitErrorVariantPattern`; `ASTPrinter` prints both.
- **Parser** — `ParseErrorDecl()` reads `Variant(field: Type, ...)`; `try` in
  `ParseUnary()`; `FuncBodyTryScope` records a `try` on the enclosing function;
  `ParsePattern()` reads `Type::Variant(sub, .., ..)` (`ParsePostfixExpression()` stops
  at the header's first `(` via the one-shot `PatternHeadCallPending`).
- **Resolver** — payload field spellings resolved (Pass 1b) and validated
  (`visitErrorDecl()`: unknown type, private-in-public E089, error/`!T`/`void` field E096);
  `visitFuncCall()` decides construction arity from the declared fields; `visitScopeAccess()`
  rejects a bare fielded variant unless `IsTagOperand` (set by `visitBinary()` for `==`/`!=`
  and by the pattern resolver); `visitTry()` (E095 in a `defer`, `DeferDepth_`);
  `normalizeHeaderPattern()`; `buildFunctionSymbol()` marks `UsesTry` as
  `ReturnsReboundError`; `visitReturn()`/`ReturnPassesFallible_` for the
  never-returns-error warning; `visitRecoverExpr()`'s bare-error restriction now skips a
  callee that passes errors on.
- **TypeChecker** — construction argument typing (E096) and the registered error type as
  the call's type; `visitTry()` (E095); `visitReturn()` pass-through + tailored hints;
  `visitErrorDecl()` (unsafe gate, generic field instantiations); `checkPattern()` for
  variant patterns; `visitCompare()` covers a declared error type's variants;
  `AllPathsDiverge()` understands `compare`.
- **Monomorphizer** — `try` operands and variant-pattern sub-patterns walked.
- **CFG/analysis** — `AnalysisVisitor` / `BodyDeclCollector` see pattern bindings inside a
  variant pattern and `try` operands; `try` added to the expression walkers of
  `SelfFieldDefVisitor`, `NullableRefCollector`, `NarrowingVisitor`, `EscapeCheckVisitor`,
  `AliasAnalysis`, `ValueRange` (including `collectAddressTaken()` — see *Known pitfalls*)
  and `CFG.cpp`'s self-call scan. A `try` is not modelled as a CFG return edge (neither is a
  `return` inside a `recover` block).
- **Codegen** — `%TurfErrorValue = { tag, message, payload }`; a named
  `errpayload.<Error>.<Variant>` struct per variant with fields, GC-allocated with its own
  descriptor; `CodegenErrorVariantConstruct()`; `TryExprAST::codegen()`; pass-through
  `return`; variant-pattern tests in `CodegenPattern.cpp`.
- **Diagnostics** — new `include/ErrorsPayload.h`: E095 `TryMisuseError`, E096
  `ErrorPayloadError`; docs `docs/errors/codes/E095.txt`, `E096.txt`; E092/E093 docs extended.

## Runtime changes

None to `runtime/`. An error value grew one pointer word (`payload`); the runtime only ever
sees it as an opaque GC block whose descriptor Codegen emits.

## Standard-library changes

- `io::FileError` — `NotFound(path: string)`, `ReadFailed(path: string)`.
- `json::JsonError` — every variant carries `offset: int`, the byte offset at which the
  parser gave up.
- `json.tr` — the eleven `recover as err run { return err; }` are gone: `try` where a value
  is unwrapped, a direct `return self.parse_object();` where the `!T` passes through
  (`parse`, `parse_value`).
- `math`, `strings`, `map`, `net` errors were reviewed and left as they are: no caller has
  asked for data those failures don't already name (`NetworkError`'s variants say which
  syscall failed; a host/port payload would be speculative).

## New invariants

INV-ERR-1 (payload traced, error passed on unchanged) and INV-ERR-2 (`try` is a return)
in `INVARIANTS.md`, both `holds`, each with the live evidence.

## Removed assumptions

- **"`return f();` of a `!T` from a `!T` function is a type error."** It was audit F-21's
  finding; the success type was compared with the operand's whole union.
- **"`err == E::V("msg")` is handled"** (STD-002's own doc comment said "unusual but not
  illegal"). It was a type error ("Cannot compare '<error>' with 'E'"): the construction call
  was typed as a `NamedType` standing in for the error type, and `inferRelationalType()`
  allows `==` against `AnyErrorType` only for a type that `isUserError()`. Found while
  writing `25_errors/21_error_equality_with_payload_variant.tr`; the construction now gets
  the registered `TurfUserErrorType`, like a bare reference.
- **"A `recover` block's body inside a `defer` is checked for escaping jumps."** It was not:
  `FindEscapingControlFlow()` never looked inside `recover`, so `defer f() recover run {
  return 5; };` passed INV-DEFER-2 and then crashed the compiler (`sanitizeSymbolName`).
  Found live while checking whether a `try` inside a `defer` would be caught. Fixed
  (`tests/40_defer/fail_return_in_recover_block_in_defer.tr`). Not a `try` bug, but the same
  class and one line to close.
- **"`AllPathsDiverge` recognises only `return`/`break`/`continue` and `if`-with-`else`."**
  Reading a payload is a `compare`, so every `recover as err run { compare err { ... } }`
  needed a dead `return` after it. It now also accepts a `compare` with `otherwise` (or one
  that provably covers everything) whose arms all diverge.
- **"A function whose `return`s all name an error type by name is the only kind that can
  fail."** A `try` and a pass-through `return` fail too, and neither names a type the
  Pass 1 scan can collect. The Parser records `try`; the Resolver notes a `return <call>`
  whose callee returns `!T`. Without this `NeverReturnsErrorWarning` fired on the new idiom.
- **"`ReturnsReboundError` callees are safe for the bare-error check."** The check under-used
  what a rethrowing callee can fail with (it only saw the errors it names itself); it now
  skips such a callee, which `try` makes common.

## Known pitfalls

- **`return` inside `recover` returns from the enclosing function.** Reading a payload is
  normally `recover as err run { compare err { ... return N; ... } }`, so the `compare` has to live in
  a helper that turns the payload into the function's own return value. Several of the tests here failed
  on the first draft for this reason alone (a `return` in `main`; at least three of them). It is documented behaviour
  (`errors_and_recover.md` §1.4.2), just easy to forget.
- **`run`, `step`, `produce`, `pub` are reserved words** — three test files failed to parse because a
  helper function was named one of them (`fn run(...)`, `fn step(...)`, `fn produce(...)`).
- **A `fail_*.tr` only proves it failed.** All 28 new ones in `25_errors` (and the two elsewhere) had their error code printed and the
  message read; none needed rewriting for a wrong reason, but `fail_payload_field_unknown_type.tr` is
  E042 (the ordinary unknown-type error), not E096, by design.
- **Message inside a pattern is not bindable.** With a subject that is not a variable
  (`compare f() { ... }` cannot be an error value anyway) there is nothing to call `.message` on; with `err`
  it is still in scope in the arm.
- **The constructor argument of `==` is never evaluated.** `err == E::V(expensive())` compares tags
  without running `expensive()` (STD-002's documented decision, unchanged).
- **`collectAddressTaken()` (`ValueRange.cpp`) does not look inside `recover`.** I added `try`
  there because `try f(&x)` is now the idiomatic call and a missing case would leave `x` unmarked
  address-taken; the same gap exists for `f(&x) recover ...`. Left as is — out of scope — but it is a real
  (F-OPT-2-shaped) hole worth LEC-005's attention along with `ASTDiff.h`/`Lint.cpp`, which never walk
  `try`, `recover` or `compare`.
- **`--dump-ast` never prints inside a `recover`** (`ASTPrinter` has no `visitRecoverExpr`, pre-existing), so a variant pattern in the usual `recover as err run { compare err { ... } }` shape does not appear in the dump; it does where the `compare` is reachable (`25_errors/20`).
- **Not covered by anything:** LSP hover/goto on a variant pattern or a payload field
  (`ErrorVariantPatternExprAST` is in the facade's node-span table but no test lands a query on it);
  `--migrate=pub` and the formatter on the new syntax were not re-checked.
- **A payload type that is a struct is built lazily**, at the first constructor or pattern in a function
  body. That is sound because every struct is complete before any body is generated; a future change that
  emitted error values before the struct pre-pass would hit an opaque field.

## Unresolved questions

None blocking. For the owner, when convenient:

1. **`NetworkError`, `MathError`, `MapError`, `StringParseError` kept payload-free** (see *Standard-library changes*).
   The roadmap's list names `io`/`fs`/`net`/`json`/`http` "where a caller would want them"; only `io` and `json` had data a
   caller demonstrably wants. `fs`/`http` declare no error types of their own.
2. **A variant pattern cannot bind the message** (`matches E::V(a, msg)` with N+1 would be the natural spelling). `err.message`
   covers every real use; binding it would make the N/N+1 rule apply to patterns too. Additive later.
3. **Stage commits are split by file ownership, not by working state** (see *Commits*): bisecting inside stages 3–7 lands on
   trees that may not link.
