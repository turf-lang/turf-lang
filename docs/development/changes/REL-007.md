## Stage 0 — before the first test build

**turf-lang no longer carries the CLI.** `cli/` was a byte-for-byte mirror of
turf-cli and is deleted. CMake builds `build/turf` from `TURF_CLI_DIR`
(default `../turf-cli`) and re-resolves a cached path that has no `go.mod`, so
an existing build directory switches over on its next configure.

**The CLI is pinned.** `TURF_CLI_REVISION` (repo root, one commit hash) is
the turf-cli commit every CI and release build checks out, so two builds of
one turf-lang commit ship the same `turf`. A commit, not a tag: turf-cli's own
version is still `1.0.0-dev`; it is tagged when 2.0.0 is. Moving the pin is a
turf-lang commit.

**`scripts/smoke/cli_source_smoke.sh`** reads what Go stamps into the binary
(`go version -m`) and checks: turf-lang has no `cli/`; `TURF_CLI_DIR` is the
`github.com/turf-lang/turf-cli` module; the CMake cache points at it; the
binary's main package is `turf-cli/cmd/turf`; its `vcs.revision` is the
checkout's HEAD; and that HEAD is the pinned revision (required in CI, a NOTE
locally). Runs in `test.yml` and before each of the eight archives is
packaged (`--build-dir=build-smart` for the smart ones). Seen failing, with
the right message, for: a build directory still configured against `cli/`; a
`turf` built inside turf-lang; a `turf` older than the checkout; a wrong pin.

**The Windows smart archive is required.** Its steps were
`continue-on-error` because it had never been built; they are not any more.
The three macOS steps (suite, GC, smokes on macOS) were informational until
their first run had been read; they are enforcing since that run was green.
