## Why

A corrected line was available only with `--smart`, which needs the larger build
and a flag, and covered 11 rename classes. The compiler often knows the exact
edit (a misspelled name with one close match, a missing `;`, a `.` where `::`
belongs). TDP-2-001 prints it in every build, after checking it.

## Language semantics

None.

## Compiler architecture

- **Diagnostics** · `src/diagnostics/CompilerFix.{h,cpp}` is the rule engine:
  `CompilerFixes::build()` turns the fix-its an error carries into a
  description and an edited copy of the source; `CompilerFixes::check()`
  re-analyses that copy through `turf::analyze` (lint and flow analysis on) and
  accepts it only if the original error (same code, same line) is gone and no
  error appears that the original lacked. `CompilerFixes::MaxChecksPerCompile`
  (10) bounds the cost. Raise sites attach edits with the `withFixIt()` family
  in `Errors.h` (and `ErrorsModule.h`); nothing matches an error's name or text.
- **Lexer / driver** · `checkCompilerFix`, `flushAll`, `printDiag` and `add` in
  `Lexer.cpp` run the check once per diagnostic and print the `Fix:` block;
  `main.cpp` writes `--smart-write-fix`. Only errors, only outside `lib/std`,
  only one candidate.
- **SLM** · `tryDeterministicFix()` and the `[Deterministic Fix]` status line
  are removed. `--smart` asks the model only for an error with no compiler fix;
  its suggestion is labelled `[Model Suggestion]` (was `[AI Suggestion]`).
  `--smart-write-fix=<path>` writes the program with every shown compiler fix,
  in any build and without `--smart`, or the model's validated suggestion when
  the compiler had none.
- **TypeChecker / Resolver** · the raise sites for E026, E029, E030, E031, E039,
  E040, E041, E042, E046, E048, E052, E054, E060, E068, E087, E102, E138 and
  E014 attach their edit.
- **Tooling** · `TestExpectations.{h,cpp}`, `TestRunner.cpp`: the `EXPECT-FIX`
  marker (below).

## New invariants
A `Fix:` is printed only after the edited program has been re-analysed in this
run. A clean compile never enters the fix path.

## Removed assumptions
- A rule-based fix needs `--smart` and a smart build.
- A suggestion labelled `[AI Suggestion]` came from a model.

## Tests

- `// EXPECT-FIX: <description>`: each marker must match a printed `Fix:` line
  exactly. With the diagnostic register (this repository's suite), every
  printed `Fix:` line must also have a marker; a project's `turf test` opts in
  with the marker, so its existing tests are unaffected. The runner then
  reruns the compiler with `--smart-write-fix` and analyses the fixed program
  in-process, requiring at least as many fewer errors as fixes printed and no
  error the original lacked.
- `tests/55_compiler_fixes/`: one fixture per code family and an ambiguous typo
  that gets no fix. Existing `fail_*` tests whose errors now carry a fix gained
  their `EXPECT-FIX` line.
- `scripts/dev/diagnostic_fix_coverage.py`: per-code counts of hints and fixes.
- `scripts/slm/slm_deterministic_fix_smoke.sh` is rewritten: each fixture prints
  its fix with and without `--smart`, `--smart` never reaches the model, the
  `--smart-write-fix` program compiles and runs, a clean compile never enters
  the fix path. `scripts/slm/slm_benchmark/run_benchmark.py` counts a `Fix:` line
  as a compiler fix and `[Model Suggestion]` as a model fix.
- `TURF_FIX_DEBUG=1` prints a `[fix]` line for each error with fix-its the path
  looks at.

## Known pitfalls

- In this repository, a `fail_*` test whose error gains a fix fails until its
  `EXPECT-FIX` is added.
- Output scrapers see `Fix:` lines. DX-2 (`--diagnostics=json`) has not landed.
- At most 10 fixes are checked per compile; later errors get none.
