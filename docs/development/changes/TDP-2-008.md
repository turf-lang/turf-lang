### Why

A `Fix:` builds on a hint: the hint says what to write, the fix writes it. The
`fail_*.tr` suite exercised 139 codes; 18 of them printed at least one error
with no `Hint:` line (E105, E106, E115, E116 and E118 never had one), and a
further set carried only general advice ("Check the number of arguments.",
"Check that all your blocks are properly closed."). Every error now prints a
hint that names the construct at hand, and `diagnostic_fix_coverage.py --check`
keeps it so.

### Compiler architecture

- **Raw parser errors** · `LogErrorAt()` (`src/frontend/Lexer.cpp`) appends a
  per-code hint to an error whose message has no `Hint:` of its own, so a raw
  site cannot print without one (E102, E103, E105, E106, E107, E108, E110,
  E115, E116, E118, E123, E150 and the other syntax codes). Sites that know
  more write their own `\n  Hint:` and keep it: the operator arity sites
  (E115) show the declaration to write, E107 and E116 name the function,
  E123 names the array.
- **`SyntaxError`** · `defaultHintFor(Code)` (`ErrorsLex.h`) replaces the single
  "check your punctuation" line with one per code (E109, E104, E105, E106,
  E034, E113).
- **Instantiation errors** · `Monomorphize.cpp` carries the inner error's hint
  as the hint of the "In this instantiation" error instead of folding it into
  the message in parentheses; when the inner error had none, the hint names the
  instantiation (`'twice<bool>'`) and the generic to change. This covers E057,
  E064, E068, E124, E128, E131 and E150 reached through a generic. `SemanticError`
  takes an optional hint.
- **Type-checker defaults** · `typeErrorDefaultHint()` (`ErrorsType.h`) says
  what to write for E025, E044, E057, E058, E064, E066, E134. The wrong-argument-
  count sites (E044) name the callee and the count or the overload to match;
  `WrongArityError`, E026 (`ErrorsModule.h`), E067 and E111 name the function,
  the module or the variable to introduce.
- **Tooling** · `diagnostic_fix_coverage.py --check` exits 1 and prints the code
  and file of every error that prints no `Hint:`. CI (`.github/workflows/test.yml`)
  and `scripts/dev/session_postflight.sh` run it.

### Tests

- `python3 scripts/dev/diagnostic_fix_coverage.py --check` (801 `fail_*.tr`
  files, 727 errors, all hinted; 139 of 139 exercised codes hint every time).
- No new fixtures: the existing `fail_*` tests exercise each raise site. A
  hint's text is not pinned by `EXPECT-DIAG`, which matches the code.

### Known pitfalls

- `--check` sees only what the suite raises. A raw `LogErrorAt()` site is
  covered by the per-code fallback; a typed error class that passes no hint to
  `TurfError` and has no default prints none until a fixture reaches it.
- An error whose message already contains `Hint:` is left alone by the
  `LogErrorAt()` fallback, so a site that writes its own hint wins.
- Do not write the hint into the message text of a typed error; pass it as the
  hint argument so it prints once, after the `Note:` lines.
