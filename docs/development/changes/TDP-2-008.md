## DX-3 — Hint backfill

| | |
|---|---|
| **Status** | landed (uncommitted, 2026-10-24) |
| **Dates** | started 2026-10-24 · landed 2026-10-24 |
| **Commits** | (filled in at commit time) |
| **Sessions** | 1 of 1 |
| **Depends on** | TDP-2-001 (`scripts/dev/diagnostic_fix_coverage.py`, the table it prints) |
| **Frozen decisions relied on** | D-6 of `docs/planning/ROADMAP_v3.0.0.md` (diagnostic text is outside the compatibility promise) |

### Why

A `Fix:` builds on a hint: the hint says what to write, the fix writes it. The
`fail_*.tr` suite exercised 139 codes; 18 of them printed at least one error
with no `Hint:` line (E105, E106, E115, E116 and E118 never had one), and a
further set carried only general advice ("Check the number of arguments.",
"Check that all your blocks are properly closed."). Every error now prints a
hint that names the construct at hand, and `diagnostic_fix_coverage.py --check`
keeps it so.

### Compiler architecture

- **Raw parser errors** · `LogErrorAt()` (`src/frontend/Lexer.cpp`) appends a
  per-code hint to an error whose message has no `Hint:` of its own, so a raw
  site cannot print without one (E102, E103, E105, E106, E107, E108, E110,
  E115, E116, E118, E123, E150 and the other syntax codes). Sites that know
  more write their own `\n  Hint:` and keep it: the operator arity sites
  (E115) show the declaration to write, E107 and E116 name the function,
  E123 names the array.
- **`SyntaxError`** · `defaultHintFor(Code)` (`ErrorsLex.h`) replaces the single
  "check your punctuation" line with one per code (E109, E104, E105, E106,
  E034, E113).
- **Instantiation errors** · `Monomorphize.cpp` carries the inner error's hint
  as the hint of the "In this instantiation" error instead of folding it into
  the message in parentheses; when the inner error had none, the hint names the
  instantiation (`'twice<bool>'`) and the generic to change. This covers E057,
  E064, E068, E124, E128, E131 and E150 reached through a generic. `SemanticError`
  takes an optional hint.
- **Type-checker defaults** · `typeErrorDefaultHint()` (`ErrorsType.h`) says
  what to write for E025, E044, E057, E058, E064, E066, E134. The wrong-argument-
  count sites (E044) name the callee and the count or the overload to match;
  `WrongArityError`, E026 (`ErrorsModule.h`), E067 and E111 name the function,
  the module or the variable to introduce.
- **Tooling** · `diagnostic_fix_coverage.py --check` exits 1 and prints the code
  and file of every error that prints no `Hint:`. CI (`.github/workflows/test.yml`)
  and `scripts/dev/session_postflight.sh` run it.

### Tests

- `python3 scripts/dev/diagnostic_fix_coverage.py --check` (801 `fail_*.tr`
  files, 727 errors, all hinted; 139 of 139 exercised codes hint every time).
- No new fixtures: the existing `fail_*` tests exercise each raise site. A
  hint's text is not pinned by `EXPECT-DIAG`, which matches the code.

### Known pitfalls

- `--check` sees only what the suite raises. A raw `LogErrorAt()` site is
  covered by the per-code fallback; a typed error class that passes no hint to
  `TurfError` and has no default prints none until a fixture reaches it.
- An error whose message already contains `Hint:` is left alone by the
  `LogErrorAt()` fallback, so a site that writes its own hint wins.
- Do not write the hint into the message text of a typed error; pass it as the
  hint argument so it prints once, after the `Note:` lines.

## SL-3 — The benchmark corpus and its held-out split

| | |
|---|---|
| **Status** | landed |
| **Dates** | 2026-11-08 · 2026-11-09 |
| **Line** | 2.3.0 |
| **Issue** | #342 |
| **Depends on** | the mutators of `scripts/slm/slm_benchmark/mutate.py`; `turfc --package-graph` |

### Why

`--smart` was measured on 22 cases, and the prompt documents in `docs/slm/`
were tuned against them. A number from a corpus that small, read by the same
person who tunes the prompt, says little about a program nobody has seen.

### How it works

- **`build_corpus.py`** writes `corpus/train.jsonl`, `corpus/heldout.jsonl`
  and `corpus/STATS.md`. A case is a passing program with one line mutated
  (or a test with two), kept only when the compiler rejects it near that
  line. Its oracle is the original: the fix is right when the program prints
  what the original printed and exits 0.
- **Sources.** Test files, in a fixed random order until the candidate pool is
  full; every `showcase/` program; every file of an `examples/` package,
  compiled through a package graph from a scratch copy of the packages. A
  program that compiles but is not run here (network, varying output) gives
  cases with oracle `recompile`.
- **One case per code.** A code no mutant reaches gets the shortest
  single-error `fail_*.tr` that reports it (oracle `recompile`). `STATS.md`
  lists the codes the suite expects that still have no case: warnings, errors
  that need a second module, E119 (no source line), codes a test makes up.
- **Hard negatives.** `hard_negatives/*.tr`, each with a
  `// HARD-NEGATIVE: <why>` line: use before declaration, two equally good
  renames, a missing field, a missing return value, text or number. The right
  outcome is no suggestion (oracle `abstain`).
- **Split.** By sha1 of the source path, a quarter held out, so no held-out
  case has a sibling mutant in train.
- **`check_heldout.py`** (CI, `test.yml`) fails when a file under
  `scripts/slm/`, `src/slm/` or `docs/slm/` other than the builder and the
  scorer names the held-out split.

### Tests

- Two runs with the same seed and compiler write identical files.
- `python3 scripts/slm/slm_benchmark/check_heldout.py` passes.

### Known pitfalls

- The corpus depends on the compiler's diagnostics. Regenerate it after a
  change to a message, a code or a mutator; the diff shows what moved.
- A package case's `mutated_source` is one file, not the program: put it in
  place of `source_test` and build the package named by `package`.

## SL-2 — Scoring: utility with an interval, and a rules-only baseline

| | |
|---|---|
| **Status** | landed |
| **Dates** | 2026-11-09 |
| **Line** | 2.3.0 |
| **Issue** | #343 |
| **Depends on** | SL-3 (the corpus), DX-2 (`--diagnostics=json`), `--smart-write-fix` |
| **Frozen decisions relied on** | D-12 (`K = 3`) |

### Why

The old report was eight percentages over 22 cases with no single verdict, so
nobody could say whether a change to `--smart` helped. And the model's worth
was never set against what the compiler already fixes without it.

### How it works

- **`run_benchmark.py`** compiles each case of a split per path (`rules`:
  no `--smart`; `model`: `--smart`). What was shown is read from the JSON
  diagnostics' `fix` edits and from the program `--smart-write-fix` writes for
  a model fix, never from stdout. A package case is built through a package
  graph (`build_corpus.package_tree`).
- **Judging.** A shown fix is compiled; for oracle `asserts` it is run and
  must exit 0 printing the original's output; for `recompile` it must
  compile; on a hard negative any fix is wrong. Utility +1 / 0 / −K.
- **Report.** Mean utility with a percentile bootstrap 95% interval;
  model − rules with a paired bootstrap; false confidence; silence on hard
  negatives; Brier score of the printed confidence; correct rate, p50/p95
  latency and peak RSS (from `wait4`) by provenance; utility by category, code
  and kind. One JSON record per run in `bench/results/smart/`.
- **`scripts/slm/slm_benchmark_smoke.sh`** (CI) checks classification and
  judging on four fixed cases, the model answered by `TURF_SLM_REPLAY`.

### Tests

- `scripts/slm/slm_benchmark_smoke.sh`: a rule fix judged correct by running
  it, silence on a hard negative, a replayed model fix judged correct and the
  same fix judged wrong against output it never prints.
- Rules-only baseline on both splits, recorded in `bench/results/smart/` and
  in `scripts/slm/slm_benchmark/README.md`.

### Known pitfalls

- A two-error case scores a fix that clears one error as wrong: the program
  still does not compile.
- The model path runs one case at a time and needs exactly one `.gguf` in
  `models/`; on a laptop without a GPU a split takes hours.
- The Brier score covers only fixes that carry a confidence; a rule fix counts
  as 1.0, which is what the user is told.

## SL-1 — Fix Score v2: facts and tiers

| | |
|---|---|
| **Status** | landed (model-path calibration pending: see Known pitfalls) |
| **Dates** | 2026-11-09 |
| **Line** | 2.3.0 |
| **Issue** | #344 |
| **Depends on** | SL-2 (the scorer), SL-3 (the train split the threshold is fitted on) |
| **Frozen decisions relied on** | FREEZE §6.9 (amended: the display gate is the tier) |

### Why

A model suggestion that passed the sandbox scored 0.9 whatever the edit did,
so a "fix" that commented out the failing statement was shown with the same
confidence as a one-character typo fix. The compiler's own fixes had no score
at all, and SL-2's rules-only baseline found 16 of 47 shown on the train split
did not compile: 12 were fixes for errors that only existed because an
earlier line failed to parse.

### How it works

- **`src/diagnostics/FixScore.{h,cpp}`** (every build): `Facts`, `tier()`,
  `flags()`, `flagLine()`. Facts are computed from the lines a fix replaces and
  what replaces them, on a token stream (the file may not parse before the
  fix): semantic loss (fewer calls, asserts, `return`s or assignments),
  surface (a declaration other than the one on the error's line changed or
  removed; a field line is one with the `name: type` shape), new warnings
  (pointing into the changed text only), minimality (token edit distance over
  `max(6, 1.00 × tokens on the error's line)`), ambiguity, provenance. A
  function declared rather than called (after `fn`/`function`/`func`/`def`/
  `fun`, or with a return type or `{` after its `)` at a statement's start) is
  not a call. No weights: any flag makes a valid fix `plausible`; with none a
  rule fix is `proven` and a model fix `verified`.
- **The threshold** is fitted on the train split by
  `scripts/slm/slm_benchmark/fit_fix_score.py` (the 95th percentile of the
  right fix's distance over its error line, 336 single-mutation cases) and
  frozen as `kWideRatio`/`kWideFloor`.
- **Rule fixes.** `CompilerFixes::check()` returns the warnings the patched
  program has on the fix's lines; `scoreCompilerFix()` (`Lexer.cpp`) fills the
  facts. `flushAll()` gives no fix to an error the parser reports while
  recovering from a syntax error (registry category `SYNTAX_ERROR`): from the
  syntax error's line to the next line that starts a declaration (first
  column, a word or `@`), that line included, since a broken statement can
  swallow its first token. An error in a later declaration keeps its fix
  (`fail_parse_error_resync_reports_next_function.tr`,
  `fail_header_names_main_file.tr`). A plausible fix prints
  `Check before applying: …` under the `Fix:` block; JSON `fix` gains `tier`
  and `flags` (schema 1.2).
- **Model fixes.** `verifySuggestion()` scores the accepted candidate
  (`scoreSuggestion()`, using the sandbox's original and validation
  diagnostics). The display gate is the tier, not `confidence >= 0.8`; a
  verified suggestion prints a `Checked:` line, a plausible one its flags.
  `confidence` is kept for `TURF_SLM_DEBUG` and the benchmark's Brier score;
  `Fix tier: <tier> | <flag>…` is printed there too.
- **Ambiguity.** For a rule fix, the alternatives the compiler checks (only a
  unique one is shown). For a model fix, `--smart=thorough` (interface 1.15,
  feature `smart-thorough`): once an answer validates, two more are sampled
  (temperature 0.7, seeded by their number; `SLMEngine::generateSuggestion()`
  takes a temperature and seed), checked in the sandbox and never cached; two
  different validated programs make the fix plausible. Without the flag a
  model fix's ambiguity is not measured (`Candidates = 0`).
- **`run_benchmark.py`** records each shown fix's tier and reports the
  correct rate per tier with a bootstrap interval.

### Tests

- `scripts/slm/slm_replay_smoke.sh`: `deletion.comment_out` (a model "fix"
  that comments out the failing statement validates and is `plausible`:
  "it removes a call and an assignment"); `insert_line.empty_original` is
  `verified` with its `Checked:` line; the retry case's signature change is
  `plausible`; `insert_line.thorough_agree` (three equal answers: verified)
  and `insert_line.thorough_disagree` (a second, different validated program:
  plausible).
- `scripts/slm/slm_benchmark_smoke.sh`: a rule fix is `proven`, a replayed
  model fix `verified`.
- `diagnostics_json_check.py` (schema 1.2, fixtures), `diagnostic_snapshots.py`
  (regenerated: no snapshot fix is plausible).
- Rules-only benchmark, train: utility −0.038 [−0.099, +0.018] → +0.043
  [+0.004, +0.081]; wrong rule fixes 16 → 4 (the four are two-error cases,
  first fix right); no right fix lost. Held-out (scored once, not tuned on):
  +0.023 [−0.077, +0.108], 15 shown, 3 wrong.

### Known pitfalls

- **Model calibration is not measured yet.** "`verified` is measurably more
  reliable than `plausible` on the held-out split" needs the model path run
  (one `.gguf` in `models/`, hours on a CPU). Until then the rule tiers are
  the only measured ones (train: proven 35 shown, 88.6% correct).
- A model prior from SL-2's measured per-category precision is not used yet:
  there is no model run to take it from.
- The capability fact is SL-5's (below).

## SL-5 — Checks on what a fix does, and the sandbox's depth

| | |
|---|---|
| **Status** | landed |
| **Dates** | 2026-11-09 |
| **Line** | 2.3.0 |
| **Issue** | #345, #363 |
| **Depends on** | SL-1 (the facts and tiers), F-S4a (flow analysis outside Codegen, `AnalysisOptions::RunFlowAnalysis`) |
| **Frozen decisions relied on** | FREEZE §6.9 (amended), D-16 (the Codegen recheck may run inside `--smart`) |

### Why

SL-1's facts were read from the lines a fix replaced, so they could not see
what the fix did to the rest of the program: a warning it caused two lines up,
a `pub` item it added, a reach for `unsafe` or `os`. And the sandbox stopped at
the front end, so a model fix that type-checked but left a function with no
`return` was shown, although a compile rejects it (#363, found rating
`--smart` fixes by hand).

### How it works

- **`FixScore::describeProgram()`** (`src/diagnostics/FixScore.{h,cpp}`) takes
  the whole file before and after the fix, the replaced range, the error's
  line, and the fixed file's diagnostics from the same analysis of each
  (`FixScore::Program`). It fills minimality (`describeEdit()`, now only
  that) and four checks, each of which can only add a flag, so only lower the
  tier:
  - **Deletion:** fewer calls, asserts, `return`s or assignments in the file.
  - **API surface:** a declaration (function, struct, enum, `pub immut`, a
    struct's field line) that does not read the same after the fix, other
    than the one on the error's line; and, added, a `pub` item or a field of
    a struct the program had (`it adds the public declaration …`, `it adds
    the field … to …`). What the error line's declaration became is not an
    addition (E176's own fix writes `pub immut` over `export immut`; the
    snapshot test caught it).
  - **Capability** (`capabilityDiff()`): more `unsafe` or `extern`, a new
    `import` of `os`, `fs`, `http` or `io`, a raw pointer (`ptr` as a type, or
    a type followed by `*` where a product would have an operand), a `mem::`
    call.
  - **Warning delta:** SL-1's rule for the text the fix wrote, plus a warning
    elsewhere that the original did not have on the same line (lines after
    the fix moved back by what it added), counted when the function it is in
    had no error before the fix and the file had no syntax error (the
    analysis skips such functions, so it had nothing to compare), or when its
    message names (between backticks) a word the fix removed or added. Shown
    as `E163 (line 7)`.
- **Rule fixes:** `CompilerFixes::check()` fills `Program`'s two diagnostic
  lists (its baseline keeps every diagnostic now); `scoreCompilerFix()` builds
  the rest.
- **Model fixes:** `scoreSuggestion()` reads the sandbox's original and
  patched source and `Sandbox::getOriginalAnalysisDiagnostics()`: the
  original program analysed once per compile exactly as candidates are, so
  the two lists compare like with like. `isOriginalErrorResolved()` also
  allows the error lines that analysis finds.
- **Sandbox depth** (`SandboxDepth`, `src/slm/Sandbox.h`): `front end`
  (parse, resolve, type-check, lint), `analysis` (the default: also the flow
  analyses, `RunFlowAnalysis`), `codegen` (opt-in: a candidate that passes the
  analysis is compiled by a child `turfc --emit-llvm -O0 -o /dev/null`, which
  runs Codegen and the LLVM verifier and links and runs nothing; its first
  lines of output go back to the model). Codegen works on process-wide LLVM
  state the host compile is still using, hence the child; the patched copy is
  a hidden file next to the original (`.turf-smart-check-XXXXXX.tr`) so its
  imports resolve as the file's do, removed after the run. A package build
  (its entry must be the root package's `src/main.tr`) and a directory it
  cannot write to skip the recheck; a check that cannot run never rejects. `TURF_SLM_SANDBOX_DEPTH=frontend|analysis|codegen`
  picks one. The sandbox now also analyses with the compile's package graph.
  The depth is recorded on the suggestion (`AISuggestion::sandboxDepth`), and
  `TURF_SLM_DEBUG` prints it with each candidate's time (`(depth analysis,
  31.8 ms)`) and as `Sandbox depth: …`.
- The `Checked:` line names the capability check.

### Tests

- `scripts/slm/slm_replay_smoke.sh`, one case per check: `capability.unsafe_block`,
  `capability.import_os`, `capability.mem_call` (`unsafe`, a raw pointer and
  `mem::` at once), `capability.add_pub` (API surface),
  `warning_elsewhere.unused_after_fix` (E163 on a line the fix did not write;
  the helper's own unused variable, there before, is not counted),
  `deletion.comment_out` (SL-1's, now over the whole file) and
  `flow_reject.missing_return` (#363: the placement that drops `main`'s
  `return` is rejected at the analysis depth, the one-line placement passes).
  The smoke's `a field named \`m\`` check was in double quotes, so the shell
  ran `m` and the check matched anything; it is single-quoted.
- Timing (#363): `scripts/slm/slm_benchmark/sandbox_depth_timing.py`
  replays each single-mutation train case's right fix at each depth.
  Train split, 422 single-mutation cases, 319 reaching the sandbox
  (`bench/results/smart/2026-11-09-43cbfe4c-sandbox-depth.json`), ms per
  candidate:

  | depth | mean | p50 | p95 | right fixes validated |
  |---|---|---|---|---|
  | front end | 36.7 | 36.4 | 47.1 | 307 |
  | analysis | 39.4 | 39.4 | 48.9 | 307 |
  | codegen | 109.3 | 112.0 | 132.9 | 304 |

  The analysis depth costs about 3 ms a candidate and turned down no right
  fix. In that run the codegen depth turned down three right fixes, all in
  `examples/plotter` (a package build, whose entry must be `src/main.tr`);
  a package build now skips the codegen recheck.
- Rules-only benchmark at bf5043eb: the same as SL-1's on both splits (train
  +0.043 [+0.004, +0.081], 35 shown, all `proven`; held-out +0.023
  [−0.077, +0.108], 15 shown, all `proven`). SL-5's checks raised no flag on
  any shown compiler fix.

### Known pitfalls

- The API-surface and capability checks read tokens line by line, not the
  AST: the original program may not parse. A declaration split over lines is
  compared by its first line.
- A warning elsewhere in the function the error was in counts only when it
  names something the fix touched; one that names nothing (a complexity
  warning) is not seen.
- The `codegen` depth costs a child compile per validated candidate and
  writes a hidden file next to the source for the length of it.

## #364 — The explanation is written after the fix is checked

| | |
|---|---|
| **Status** | landed (model-path cost pending: see Known pitfalls) |
| **Dates** | 2026-11-09 |
| **Line** | 2.3.0 |
| **Issue** | #364 |
| **Depends on** | SL-1, SL-5 (the sandbox the fix passes first) |
| **Frozen decisions relied on** | FREEZE §6.9 (amended) |

### Why

The model wrote its explanation in the same answer as its edit, before the
sandbox ran. After a retry the user saw the last attempt's explanation ("My
last attempt closed the `if` but also dropped that `;`") under an edit that ran
from their original program to the final one; and every explanation could
hedge about what the sandbox then settled ("I'm not certain that `to int` is
supported"). Found rating `--smart` fixes by hand for the paper.

### How it works

Decided with the owner (2026-11-09): nothing the model writes while working
out a fix is shown.

- **The fix request** (`grammars/slm_suggestion.gbnf`, schema 4) is `reasoning`,
  `fix_mode`, `original_code`, `new_code`, `category`. `reasoning` comes first so
  a small model thinks before it writes code; it is never shown or cached
  (`AISuggestion::reasoning`). `suggested_comment` and `warning` are gone: the
  headline and the `Note:` line were prose written before the check too, and
  the Fix Score's flags say what to look at. The system prompt tells the model
  to put doubt in `reasoning` or answer NONE.
- **`explainFix()`** (`SLMIntegration.cpp`) runs once a fix validates, on any
  attempt, before it is cached: one request with its own grammar
  (`grammars/slm_explanation.gbnf`: `summary`, `explanation`), a short system
  prompt (the compiler's voice; the fix is checked, so no doubt about it;
  describe the edit shown and nothing else), and a user turn with the error,
  the error's line, the edit as plain `before` and `after` lines (the lines
  equal at both ends left out, no gutter: a small model read `- 12 |` as
  code) and `errors_on_the_way`, the first error each failed attempt met; it
  is told to quote code exactly as the edit has it. The summary is
  the `[Model Suggestion]` headline and the explanation the `Explanation:`
  line. No answer: the fix is shown without them. A fix from the cache keeps
  the summary and explanation cached with it and is not explained again.
  `TURF_SLM_DUMP_PROMPT` prints both prompts; `TURF_SLM_DEBUG` prints
  `[SLM] explain: written in N ms`.
- `--smart=thorough`'s extra samples are never explained.
- An older response that names its first field `explanation` is read as
  `reasoning`.

### Tests

- `scripts/slm/slm_replay_smoke.sh`: `method_block.explain_after_retry` (attempt 1
  uses a field Box lacks, attempt 2 passes, the third answer is the
  explanation: the request carries `errors_on_the_way` and the whole edit as
  `before`/`after`, and
  its summary and explanation are what is shown); `method_block.exact_copy`
  with no explanation answer shows the fix without one. The thorough cases
  carry an explanation answer before their extra samples.
- `scripts/slm/slm_prompt_budget.sh` measures the real explanation request
  from the replayed retry: 334 tokens (cap 4096).

### Known pitfalls

- The extra request's cost with a real model is not measured here (no model
  run on this machine); it goes with the GPU-laptop model run. Replay timing
  says nothing about it.
- Whether dropping `explanation` as the shown field and keeping `reasoning`
  changes fix quality is measured by the same run; `reasoning` goes only if
  it shows no help.

## SL-4 — Checks on the model

| | |
|---|---|
| **Status** | landed (qualification and drift wait on a full model run: see Known pitfalls) |
| **Dates** | 2026-11-09 |
| **Line** | 2.3.0 |
| **Issue** | #346 |
| **Depends on** | SL-2 (the benchmark the qualification runs), SL-5 (the backstop for injection) |
| **Frozen decisions relied on** | FREEZE §6.9 (amended) |

### Why

`--smart` runs whatever `.gguf` the user puts in `models/`. Nothing said whether
a model was any good, whether it answered the same way twice, how long a run
could take or how much memory it needed, and a change in the harness that
made more answers unusable (the issue-#267 class) showed up only as worse
suggestions. Source text reaches the prompt, so a program can also try to
steer the model.

### How it works

- **Qualification.** `scripts/slm/qualify_model.sh <file.gguf>` runs the
  determinism check and the benchmark's train split on both paths with
  `TURF_SLM_MODEL` (the compiler runs that file instead of the one in
  `<root>/models`), records it under `bench/results/smart/qualify/`, and prints
  the SHA-256, utility, false confidence, latency and peak RSS. The thresholds
  are in `docs/slm/qualified_models.tsv`'s header: model − rules ≥ 0 (paired),
  false confidence ≤ 20%, deterministic. `--record` lists a model that meets
  them. `--smart` hashes the model it loads (SHA-256, kept beside the cache by
  path, size and modification time, so once per file) and prints one note when
  it is not listed; it never blocks.
- **Determinism.** Greedy sampling (temperature 0) was already the rule.
  `scripts/slm/slm_determinism_check.sh` compiles three replay programs twice
  with `TURF_SLM_NO_CACHE` (the cache off both ways) and compares the raw
  answers and the written fix; it SKIPs without a model. The cache fingerprint
  line is `schema4:<turfc size>:<mtime>:llama=<revision>;model=<sha256>`
  (`smartModelIdentity()`); the llama.cpp revision comes from CMake
  (`TURF_LLAMA_REVISION`, `git rev-parse` of the submodule; `none` without the
  runtime). The prompt documents were already hashed into each entry's key.
- **Drift.** `.github/workflows/slm-drift.yml` (weekly, optional) restores the
  qualified model from the Actions cache by the SHA-256 in the repository
  variable `SLM_QUALIFIED_MODEL_SHA256`, runs the determinism check and the
  benchmark, and `scripts/slm/slm_benchmark/check_drift.py` fails on utility
  below the qualification's interval or a conformance rate that rose. With no
  variable or no cached model it ends green with a notice.
- **Output conformance.** Per run: answers, empty answers, parse failures (no
  JSON object, or one that does not parse), grammar escapes (JSON missing a
  field, or `fix_mode`/`category` outside its values) and splice failures by
  kind (copy not found, empty `new_code`, unchanged). `TURF_SLM_DEBUG` prints
  `[SLM] conformance: …` at the end of the run; `run_benchmark.py` sums it per
  path into the record and the report.
- **Resource bounds**, each ending with the compiler's own diagnostics:
  the memory check before loading (`enoughMemoryFor()`: the file plus 512 MB
  against MemAvailable on Linux, free + inactive + purgeable pages on macOS,
  `GlobalMemoryStatusEx` on Windows; a system that does not say is not
  refused); a wall-clock budget of 180 s for the whole run
  (`TURF_SLM_BUDGET_SECONDS`), checked before every model call and passed to
  the engine (`SLMEngine::setDeadline()`), which stops a generation at it (a
  fix that already passed is still shown; `--smart=thorough` cut short with no
  disagreement seen counts as not measured); and the 512-token answer cap,
  now `SLMEngine::kMaxAnswerTokens`.
- **Prompt injection.** The source reaches the model only inside the user
  prompt's JSON string `code`, escaped. Replay cases put an instruction in a
  comment and a JSON-breaking string literal in the program, and replay an
  answer that obeys the comment: dropping the assert and importing `os` are
  both shown as plausible, with the reason (SL-5 is the backstop).

### Known pitfalls

- No model is qualified yet: `qualify_model.sh` runs the whole train split on
  the model path, hours on a CPU. It goes with the GPU-laptop model run.
- The drift job does nothing until the variable is set and the cache seeded.
- The memory check counts the file as resident; with mmap the kernel may page
  it, so a machine just under the line could have run it slowly.
