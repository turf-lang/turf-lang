## Why

Four analysis defects, each found by running real programs, and one crash.

1. A whole-array definite-assignment rule can't be sound. After `a[0] = 1;` a
   read of `a[3]` saw a value nothing assigned, and a loop that filled every
   element was rejected because the loop might not run:
   `mut a: int[10]; for i in 0..10 { a[i] = i; } print(a[3]);` was E008.
2. A `recover run { }` block was walked as part of its statement, in one flat
   sequence with no loop edges, so a loop in the block made a value carried
   round it look dead, and `return`/`break`/`continue` in it were not seen.
3. Writing one element made the array's earlier value look dead, and the
   dead-store warning for a declaration's initializer said "assigned but never
   read" about a variable that was read.
4. `while true` with its only exit in a `recover`, `compare` arm or `unsafe`
   block warned of an infinite loop.
5. An `if`/`else` whose branches differ only in an `INT_MIN` literal crashed the
   compiler (turf-fuzz `findings/crash/lint-branch-compare-int-min-literal`,
   `findings/crash/84e0cb6e67`).

## Language semantics

### Old behaviour
`mut a: int[5]; return a[3];` was E008 until an element was written, and any
one element write counted as assigning the whole array.

### New behaviour
A fixed-size array is assigned from its declaration. Its storage is
zero-filled, so every element nothing wrote reads as the zero value of its type.
An element type with no zero value (`(&T)[N]`) still needs an initializer
(E128); so does an unsized `T[]`. Separately, an array literal of `null`s (or of
`&N`s) takes the target's `(&?N)[n]` type in an assignment, argument, `return`
or field value (`TypeChecker::arrayLiteralWidensToNullableRefs()`, reached
through `literalAcquiresType()`); 2.0 accepted this in a declaration only.

### Is this breaking?
No. The change accepts strictly more programs. Warnings change: three false
ones are gone and one is reworded (see Diagnostics).

## Compiler architecture

- **Lexer** · None.
- **Parser** · None.
- **AST** · `ASTDiff.h` compares integer literals with `APSInt::isSameValue`
  (`==` on different widths read past the narrower value: the crash in 5).
  `RecoverExprAST::BlockInCFG` marks a run block the CFG holds.
- **Types** · None.
- **TypeChecker** · `arrayLiteralWidensToNullableRefs()`, `literalAcquiresType()`.
- **CFG/analysis** · `CFGBuilder::branchToRecoverBlocks()` (`CFG.cpp`) builds
  each `recover run { }` block as blocks of its own, branching before the
  statement, so loops and exits in it have their edges; every pass reads the block
  once, on its path. `DefiniteAssignmentPass` treats `ArrayDeclExprAST` of a
  fixed size as assigned at the declaration. An element write is a read of the
  array and a write, so the earlier store stays live. `LivenessAnalysisPass`
  reports a dead declaration initializer as `DeadInitializerWarning`, and none
  for an array declared with no initializer. `Lint.cpp`'s `LoopExitFinder` finds
  an exit anywhere in a loop body.
- **Diagnostics** · `DeadInitializerWarning` (`ErrorsFlow.h`): "The initial value
  of 'x' is never read: every path assigns 'x' again before reading it.", with a
  hint to declare `mut x: T;`.
- **Optimization** · None.

## Runtime changes
None. Storage was already zero-filled (`ArrayDeclExprAST::codegen()`).

## Standard-library changes
None.

## New invariants
None.

## Removed assumptions

- An element write assigns the whole array.
- A read of an array element needs a prior write or initializer.
- A `recover run { }` block is part of its statement's block, with no control
  flow of its own.
- A write to one element ends the life of the value stored before it.
- Integer literals can be compared with `APInt::operator==` regardless of width.

## Known pitfalls

- A scalar, struct or string local still needs an assignment on every path
  before a read (E008). Only a fixed-size array is assigned from its
  declaration.
- A run block that the CFG does not hold (one in a loop condition) is walked in
  place by the analysis; it diverges, so what it stores never reaches the code
  after it.
- `BlockInCFG` must be set for every pass that would otherwise walk the block
  twice.

## Unresolved questions

None. The `FREEZE.md` §6.4 amendment (a fixed-size array is assigned from its
declaration) was decided by the owner on 2026-10-15, who also set `FREEZE.md`
aside as a gate for the 2.x → 3.0.0 work. The argument for it: a whole-array
definite-assignment rule cannot be sound. After `a[0] = 1;` a read of `a[3]` saw
a value nothing assigned, and a loop that fills every element was rejected
because the loop might not run. Per-element tracking is not decidable in general
(an index is any expression). The change accepts strictly more programs and
states what the storage already did.
