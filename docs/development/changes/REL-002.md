## Why
`ROADMAP_v2.0.0.md` REL-002 asks for three things; this record is for the first.
`turf test` was a stub that exited 2 with `'test' is not implemented yet
(REL-002)`, while the conventions that decide whether a test passed lived only
in a 720-line shell script (`scripts/test_runner.sh`) that cannot run a
project's tests: it assumes the repository's directory layout, never passes a
package graph, and exists in no installed toolchain.

Owner requirements, 2026-10-06: a project **without `tests/` is an error**, and
the command is available on **both `turfc` and `turf`**.

## Language semantics
### Old behaviour
`turf test` → `turf: 'test' is not implemented yet (REL-002)`, exit 2.
### New behaviour
`turf test` (in a project) compiles and runs every `.tr` file under `tests/` and
exits 0 only if all pass. `turfc --test [<dir>]` does the same for a directory
with or without a package graph. No TurfLang source changes meaning.
### Is this breaking?
No. One compiler rule is relaxed, and only for a graph that carries the new
`"tests"` key: a file under the root package's `tests/` may be the entry point.
A graph without the key behaves exactly as before. Driver interface 1.2 → 1.3
(additive); `turf` still needs only 1.1 for everything but `turf test`.

## Compiler architecture
- **`src/TestRunner.cpp` / `include/TestRunner.h`** (linked into `turfc`, not
  `turfcore`: it starts processes and is no use to a tool linking the
  front-end library). Discovers tests, runs each as `compile` then `run` in
  child processes of this same `turfc` (the compiler keeps its state in
  globals, so two compiles in one process would see each other), judges the
  result, prints one line per test and the summary the shell script printed.
  A small POSIX process helper (`fork`/`exec`, own process group, output
  pipe, deadline, `SIGINT` forwarding) replaces `xargs -P` and `wait_with_timeout`.
  A status is 128 + the signal number, as a shell reports it, which
  `EXPECT-EXIT: 134` and the "compiler crashed" rule depend on (LLVM's
  `ExecuteAndWait` loses the number). Windows: `turfc --test` says it is not
  supported yet (needs a process runner for that platform, REL-008).
- **`src/TestExpectations.cpp` / `include/TestExpectations.h`**: the pure half,
  a line-for-line port of the shell functions (`check_diag_expectations`,
  `check_runtime_expectations`, `check_exit_expectation`, `check_diag_policy`,
  `check_runtime_policy`) as string functions. The diagnostic register is applied
  only when `--diag-register` is given.
- **Package graph** (`PackageGraph.h/.cpp`): `PackageInfo::TestsRoot`, the
  `"tests"` key (root package only, must exist), `PackageGraph::inTests()`;
  `packageOf()` attributes a tests/ file to the root package; the entry-file
  rule accepts any file under tests/ (src/ keeps its one entry point,
  `main.tr`).
- **Imports** (`ParserModule.cpp`, `CollectPackageModuleCandidates`): a file
  under tests/ also sees the helper modules in tests/. A `src/` module does not.
  Same-named helper and `src/` module is E090, like any ambiguity.
- **Driver** (`main.cpp`): `--test` is a mode, recognised only as the first
  argument (`runTestMode()`), with its own option parser; anywhere else it is a
  usage error. Interface 1.3.
- **`turf` (Go)**: `cmd/turf/cmd_testrun.go` (`cmdTest`) replaces the stub
  (`cmd_stub.go` deleted). It finds the project, checks `tests/` exists *before*
  the compiler handshake or any dependency resolution, resolves the graph with
  `Graph.JSONWithTests()` (the only writer of the key), checks the compiler
  speaks 1.3, and runs `turfc --test tests --package-graph …` from the
  project root. `--offline`/`--locked` apply as for `build`; other flags pass
  through; `-o` and `--package-graph` are refused.
- **`scripts/test_runner.sh`** is 60 lines: validate `-O`, find the compiler,
  `exec turfc --test tests --diag-register tests/DIAGNOSTIC_GAPS.txt --exclude
  custom --exclude 99_known_bugs`.

## Removed assumptions
- "The conventions live in a shell script." They live in `src/TestRunner.cpp`.
- "A package build has one entry point, `src/main.tr`." Still true for src/; a
  graph that names `tests/` adds each test file as a program of its own.
- **"The runner rejects an unpinned `fail_*` test."** `AGENTS.md` said it did and
  the code did not (see *Known pitfalls*).

## Known pitfalls
- **The diagnostic policy's "unpinned" check never fired in the shell script.**
  `check_diag_policy` tested `[[ "$kinds" == " " ]]` for "no register entry",
  but with no entry `kinds` was two spaces, so a compile-time `fail_*.tr` with no
  `// EXPECT-DIAG: Exxx` and no register line passed as "Rejected properly"
  (reproduced on a scratch tree). The port enforces the rule as `AGENTS.md`
  states it. Every existing test already satisfies it, so no result changed.
  Two further register checks (`GENERIC-CODE`, `WRONG-REASON emits=`) searched for
  a literal `[E066]`, which no header prints (it reads `[E066 · …]`); the port
  matches the header's real shape. Both kinds are empty today, so neither was ever
  exercised.
- A file named `*_module.tr` is never run, however the name arose
  (`own_module.tr` and `fail_internal_dep_module.tr` were both skipped while
  writing the smoke script). The existing trap, unchanged.
- `turf test` needs a `src/main.tr` or a root module: the project is resolved
  like any other command first. A project with only `tests/` is not a package.
- Tests run in parallel and share the machine: a test that binds a fixed port
  or writes a fixed temporary path collides with itself. `--jobs 1` is the
  workaround.
- Ctrl-C kills every running test's process group and exits 130; the temporary
  directory holding the test executables is removed on that path too, but not
  after `SIGKILL` of `turfc` itself.

- **Exit status for a missing `tests/`.** 1 ("the tool ran and reported a

## Stage 2 — `turf fmt` (2026-10-06)

The formatter itself is unchanged: indentation from the real lexer's bracket
depth, trailing whitespace, blank-line runs, one final newline
(`include/Formatter.h`). What stage 2 adds is the *guarantee* and the command
around it. `FREEZE.md` §6.23 (F-FMT-1..3, confirmed by the owner 2026-10-06).

### What changed
- **`verifyFormatting` / `formatChecked`** (`Formatter.h/.cpp`). Every result is
  checked before it is written or reported: (1) no non-whitespace byte changed
  (covers comments, which are not tokens); (2) the real lexer reads the same
  token stream (kind and value, never position) from both texts (catches
  whitespace moved *inside* a token, which (1) cannot see); (3) formatting the
  result again changes nothing. A failure leaves the file unchanged and is
  reported as a formatter bug.
- **A source the lexer rejects is declined, not fatal.** A `TurfError` raised
  outside a recovery guard prints and calls `exit(1)`. So `turfc --format` on a
  file with a malformed number ended the whole process, and a batch ended at the
  first one; an unterminated string was formatted best-effort and followed by the
  compiler's own error. `tokenKeys()` now lexes inside the parser's `setjmp`
  guard against a private diagnostic list, and `format()` answers `Ok = false`,
  the case the header always said `Ok` was for. (By the same path a language
  server that calls `format()` outside a recovery guard would have ended its own
  process on such a buffer; not checked against `turf-lsp`.)
- **Lexer globals are restored** (`LexerGlobalsSaver`: look-behind character,
  position counters, bracket depths). `format()` used to leave them at the end of
  its buffer; `tests/api`'s "host state restored" caught it as soon as a
  formatter test ran first.
- **`turfc --format [--write | --check] <file.tr>...`** (`runFormat()`,
  `main.cpp`): several files; `--write` rewrites only a file whose text differs
  (an already formatted file keeps its mtime); `--check` writes nothing, prints
  `would reformat <file>` and exits 1 if any. Two files with no mode, `--write`
  with `--check`, a non-`.tr` file are usage errors (2). Driver interface 1.4.
- **`turf fmt`** (`cmd_fmt.go`): paths are files or directories, `--exclude`,
  `--check`; no path inside a project is `src/` and `tests/`, with `--write` or
  `--check` required; a path that does not exist is an error. One `turfc` run
  per batch of file names (a byte budget, 24 KB on Windows) so the summary is one
  line. `version.RequiredForFmt` = 1.4, checked by `turf fmt` alone.

### Verified live, on the repository's own files
Run on a copy of `tests/`, `lib/`, `examples/`, `showcase/` (1244 `.tr` files):
- 142 files were reformatted (134 under `tests/`, 8 under `lib/std/`), 1089 were
  already formatted, and 13 were declined with a lexical error: all of them
  `fail_*` tests that are invalid on purpose (malformed numbers, an unterminated
  string, a bad escape, empty or multi-character char literals).
- A second pass (`--check`) found nothing to do. No result was refused as a
  formatter bug.
- **The whole suite on the formatted copy** (formatted `tests/` and formatted
  `lib/std` as the install root): 1138 passed, 0 failed, so including the tests
  that pin a diagnostic's source snippet. Formatting is behaviour-preserving on
  everything this repository contains.

### Tests
- `tests/api/analysis_test.cpp` `testFormatterGuarantees`: hands
  `verifyFormatting` the outputs a buggy formatter could produce (a changed byte,
  a dropped line, whitespace moved inside a token, wrong indentation, an extra
  blank line) and requires each to be refused *for its reason*; a lexical error
  of each kind is declined and the process survives; no diagnostics are left for
  the host; CRLF is preserved.
- `scripts/fmt_smoke.sh` (new, in CI): the three modes and their statuses, mtime
  untouched, one bad file does not stop the rest, nothing printed as a compiler
  diagnostic, then the repository's files (second pass clean, nothing refused as a
  bug, every declined file a `fail_` test with a lexical error), then `turf fmt`:
  project mode, directories, `--exclude`, typos, usage errors.
- `cli/cmd/turf/cmd_fmt_test.go`: argument parsing, file collection (hidden
  entries, `build/`, excludes, order, a missing path), batching, the interface
  refusal, the usage errors that need no compiler.

### Known pitfalls
- `turf fmt --write` on a file that does not lex is an error and exit 1 when the
  file was *named*; one only *found* under a directory is skipped (see *Stage 2
  follow-up*). So an intentionally invalid file in a tree needs no `--exclude`,
  but a command line that names it still fails.
- A skipped file is skipped for any lexical error, including one in a file that
  was meant to be valid: `turf fmt --check src` lists it as `skipped` and exits 0.
  The compiler reports the error; the formatter only says it did not look. Read
  the `skipped` lines.
- Formatting is indentation only: `fn   main( ):int{return   0;}` is left as
  written. That is a promise, not a gap (`FUTURE.md` F-11b).
- A file already formatted is never rewritten, but a file that *is* rewritten
  is written in place, not atomically (a crash mid-write could truncate it).
  Git is the safety net the tool assumes.
- The language server's `textDocument/formatting` shares `format()`: it now gets
  `Ok = false` for a buffer with a lexical error instead of dying.

## Stage 2 follow-up — skip files that do not lex; reformat; gate (2026-10-06)

Owner decisions: F-FMT-1..3 confirmed; "skip files that do not lex" when given a
directory, in preference to an `--exclude` per `fail_*` test.

- **`turfc --format --skip-unlexable`** (with `--write` or `--check`; a usage
  error without either): a file the lexer rejects is printed as `skipped <file>:
  it has a lexical error (…)`, counted in the summary (`; N skipped (lexical
  error).`) and does not change the status. Only a *lexical* error: a result
  that fails verification is a formatter bug and still fails
  (`FormatResult::Unlexable` tells them apart; `tests/api` checks it). A missing
  file is still an error. Driver interface 1.4 → **1.5**; `RequiredForFmt` = 1.5.
- **`turf fmt`** splits what it collects (`collectFmtFiles` returns *named* and
  *walked*): named files go to turfc as before, walked ones with
  `--skip-unlexable`. A file both named and reached by a walk is named, so naming
  it still means "this must format". One turfc run per kind, so a command line
  that mixes both prints two summary lines.
- **Tests.** `scripts/fmt_smoke.sh`: the flag's four behaviours on turfc
  (skips and counts, `--check`, missing file stays an error, no-mode is a usage
  error), the repository's own files (`--check --skip-unlexable` clean, skipped
  count equals the count that could not be formatted), and on `turf fmt` a
  directory skip, `--write` skip, a named file failing, and named-beats-found.
  Checked by mutation: `turf` not passing the flag makes the script fail.
- **The reformat** is one commit of `turf fmt --write lib/std tests`, and CI runs
  `turf fmt --check lib/std tests`.
- **A boundary violation stage 2 introduced, found and fixed (2026-10-06,
  stage 3 session).** `Formatter.cpp` isolated its lexing from the caller's
  globals by hand (`DiagnosticEngine::saveState/restoreState`, a copied
  `jmp_buf`, a `LexerGlobalsSaver`), which `scripts/check_boundary.sh` check 7
  (INV-API-1: only `GlobalStateScope` saves and restores front-end state) flags.
  Stage 2 never ran that script, so it shipped red. Both lexing walks
  (`computeLineIndents`, `tokenKeys`) now run inside
  `turf::detail::runIsolated()` (`include/turf/FrontEndIsolation.h`, internal,
  implemented beside `GlobalStateScope`), which also serializes them with
  `analyze()` through the same mutex, as the hand-written version did not.
  Behaviour is unchanged (`fmt_smoke.sh`, `tests/api`, the repository check all
  as before; `turf fmt --check lib/std tests` over 1234 files takes 0.8s).
  Lesson for stage records: run `check_boundary.sh` with the suite.
