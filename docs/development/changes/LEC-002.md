## Why
Everything declared at a module's top level is visible to every importer
(`docs/architecture/modules_and_scope_resolution.md` §1.3). There is no way
to hide a helper function, a helper struct (`json`'s `Parser` is part of the
stdlib's public surface by accident), or a struct field (`List<T>.data`, a
raw pointer, is public only because nothing can be private — STD-003 item 5).
A package's API must be explicit to be versionable (LEC-001), and 2.0 is the
only cheap moment to flip the default (R1).

## Language semantics
### Old behaviour
```turf
// util.tr
fn helper(): int { return 1; }
struct Parser { pos: int }
// main.tr
import util;
util::helper();          // compiles: everything is public
mut p: util::Parser = util::Parser::default();
p.pos = 3;               // compiles
```
### New behaviour (target — nothing below is enforced yet; stage 1 is the freeze)
```turf
// util.tr
pub fn api(): int { return helper(); }
fn helper(): int { return 1; }             // private
pub struct Box { pub value: int, cache: int }
// main.tr
import util;
util::api();             // ok
util::helper();          // error: `helper` is private to module `util`
```
`pub` and `public` are interchangeable; see `FREEZE.md` §6.15 for every rule.
### Is this breaking?
Yes (R1). Every multi-module program must add `pub` to its API. Stage 6's
`turf --migrate=pub` automates it. Single-file programs are unaffected.

## Compiler architecture
Stage 1 changes no compiler code. Planned, by stage:
- **Lexer** (2): `pub`/`public` → new `TOK_PUB` (one token, two spellings, as
  `{"mut", TOK_MUTABLE}, {"mutable", TOK_MUTABLE}` in `Lexer.cpp`'s keyword
  table).
- **Parser / AST** (2): a `Visibility` field on function, struct, enum,
  error, machine, extern-fn declarations and on struct fields; `pub` accepted
  as a prefix at every top-level declaration form and before a field. The
  keyword lists at `ParserStmt.cpp:198` (recovery/"did you mean" set) and the
  top-level dispatch sites that enumerate declaration-start tokens
  (`main.cpp:900`, `main.cpp:1315`, `ParserModule.cpp:489`,
  `ParserCore.cpp:147`, `AnalysisFacade.cpp:304`, `ParserStmt.cpp:176`) must
  all learn `TOK_PUB` — the same set `TOK_UNSAFE` had to be added to.
- **Resolver / TypeChecker / Monomorphizer** (3–5): checks at every
  cross-module lookup; clone resolution in the template's module context
  (**verify live how clones resolve today before relying on it**, per the
  roadmap).
- **Diagnostics** (3–5): see below.

## Diagnostics design (owner emphasis: hints)
Few classes, rich hints. Codes are allocated when each class is added.
| Class (planned) | Raised when | Hint names the fix |
|---|---|---|
| `PrivateSymbolAccessError` | any cross-module use of a private function, type, constant, method, field or UFCS candidate | "mark it `pub` in `m.tr` if it is meant to be used from other modules"; for a field: the `pub` accessor/constructor that exists (`T::new`, a `pub` method) if one does; for a stdlib module: the public function that does the same job |
| `PrivateInPublicError` | a `pub` signature/field mentions a private type | names **both** declarations; hint: make the type `pub`, or make the item non-`pub` |
| `MisplacedVisibilityError` | `pub` where it means nothing: local variable, statement, `import`, `operator`, machine transition, parameter, or combined with `export` | says why it is meaningless there and what to write instead (e.g. operators: "operators are visible wherever their operand types are — remove `pub`") |
Every one carries a related-location note at the declaration. No new
`SLM::ErrorCategory` (FREEZE §6.9).

## Known pitfalls
- **`public` is a new reserved word.** Checked 2026-09-29 with
  `grep -rnwI --include='*.tr' -E 'pub|public'` over the whole tree: the only
  hits are prose comments (`tests/06_structs/30_generic_collection_field_chain.tr:1`,
  `showcase/text_toolkit.tr:17`, `lib/std/random/random.tr:81`,
  `lib/std/collections/map.tr:182`, `lib/std/collections/set.tr:120`). No
  code uses either word as an identifier, so reserving them breaks nothing in
  the repo. External Turf programs that named a variable `public` will break
  (covered by R1).
- **The declaration-start token sets are duplicated.** At least seven places
  (listed under *Compiler architecture*; found by grepping `TOK_UNSAFE`, not
  yet individually read) enumerate tokens that begin a declaration or
  statement; missing one likely produces a confusing recovery error rather
  than a crash. Stage 2 must read each and add `TOK_PUB` where it applies.
- **The roadmap's "verify live" items** (monomorphization context; whether
  `extern fn`s are importable today) are unverified as of stage 1.

## Unresolved questions
1. `extern fn` accepting `pub` is an engineering judgement (the roadmap's
   list omits it; its rule is "every named declaration"). Default-private
   would hide libc bindings from importers — desirable, but check that no
   stdlib module relies on re-exposing another's `extern fn` before stage 3.
2. Whether a bare `pub` in the *main* program file should warn as redundant
   is left to stage 2; frozen behaviour is "accepted".
