## Why

`compare subject { matches <expr>: … done … otherwise: … }` could only test the
subject for equality with a value. It could not look *inside* a struct, could not
bind anything, could not say "and only if", and had no spelling for "anything"
except `otherwise`. The consequence was visible in the standard library:
`json.stringify` was a six-way `if v.kind == JsonType::…` chain that then read
the matching field off `v` by hand. The roadmap's D14 also names the thing it
blocks: LEC-004's error payloads are read back by destructuring, and
`docs/architecture/errors_and_recover.md` §5.1 named destructuring as the
missing piece.

A second, smaller reason: the unused-variable warning's hint has always told
the user to "prefix its name with `_`", but `_x` did not lex at all (audit F-22).

## Language semantics

### Old behaviour

```turflang
compare p {
    matches Point { x: 0 }:   // parse error -- `Point {` was the removed struct literal
```

`_x` was a lexer error. `compare b { matches true: … }` over a `bool` silently
never matched `true` (see *Removed assumptions*).

### New behaviour

```turflang
compare p {
    matches Point { x: 0, y: 0 }:      // test both fields
        r = 1;
    done
    matches Point { x, y } if x == y:  // bind, then a guard
        r = 2;
    done
    matches Point { x: 0, .. }:        // test x, ignore the rest
        r = 3;
    done
    matches _:                         // anything
        r = 4;
    done
}
```

The full rules are `FREEZE.md` §6.17 and `docs/reference/control_flow.md`
("Patterns: `_`, destructuring and guards"). In one paragraph: headers are tried
in source order and the first whose pattern *and* guard match runs; the subject is
evaluated once; inside a struct pattern a bare identifier binds (at the top of a
header it is still a variable compared by equality); every field is listed or the
pattern ends in `..`; bindings are immutable, arm-scoped and shadow outer names;
stacked headers must bind identical names at identical types and each keeps its
own guard; a guarded arm never counts toward exhaustiveness; `_` alone is the
wildcard and is reserved, `_name` is an identifier that silences the unused
warning.

### Is this breaking?

Barely, and every case is an error that used to be a silent bug or a lex error:

- **`_` is reserved** as a name (roadmap said "grep": no `_` identifier existed —
  it could not lex).
- **A `bool` compare without `otherwise` must now cover `true` and `false`**
  (E093). The roadmap text calls this an existing rule ("Enum/machine/`bool`
  subjects… existing rule, extended") but only enums were checked; bool is new.
  No test, `lib/std` file or showcase program had a partial bool compare (the
  suite is the evidence). Migration: add the missing arm, or `otherwise:`.
- **A compare over an error value with no `otherwise` and no `matches _:`** is
  E093. Not reachable before: comparing `err` against a variant was already a type
  error, so the only way to reach this rule is a compare with `_` arms that are all
  guarded.
- `matches true:` now actually matches (*Removed assumptions*).

Everything else is additive: a compare of plain value patterns takes the original
`switch`/`strcmp` code path untouched.

## Compiler architecture

Pass by pass; `docs/architecture/compiler_pipeline.md` ("Pattern matching through
the passes") has the table.

- **Lexer** — `_` alone lexes as the new `TOK_WILDCARD`; an underscore followed by
  anything is a `TOK_IDENTIFIER`.
- **Parser** — `ParsePattern()` (`ParserStmt.cpp`): the header is read by the
  ordinary expression parser and *reinterpreted* (an expression followed by `{`
  was a struct name; in a nested position a bare identifier becomes a binding), so
  no lookahead beyond the current token was needed. `ParsingPatternHeader` (an RAII
  flag around that one call) stops `ParsePrimary()` raising the "`Name { … }` is
  no longer valid syntax" hint for exactly this `{`. `RejectVisibilityKeywordAsName()`
  became `RejectReservedWordAsName()` and also refuses a lone `_` (E092, with a
  hint to write `_name`).
- **AST** — `MatchesArm` gained `Guards` (parallel to `Values`) and `Bindings`;
  three new `ExprAST` nodes (`WildcardPatternExprAST`, `BindingPatternExprAST`,
  `StructPatternExprAST`, with `FieldPattern`); `ASTVisitor` gained the three
  `visit*Pattern` methods; `CompareExprAST` gained `Exhaustive` and
  `needsPatternCodegen()`; `ASTPrinter` prints them (`--dump-ast`).
- **Resolver** — `Resolver::resolveArmPattern()` (`ResolverExpr.cpp`).
- **TypeChecker** — `visitCompare()` reworked (arm order, guards, catch-all and
  unreachable tracking, exhaustiveness for enum/machine/bool/error); new
  `TypeCheckerPattern.cpp` with `checkPattern()`; `instantiatedFieldType()` was
  *extracted* from `visitFieldAccess()` so both read the same substitution.
- **Monomorphizer** — guards substituted; struct pattern sub-patterns walked.
- **Codegen** — new `CodegenPattern.cpp`; `CompareExprAST::codegen()` hands off
  before evaluating the subject.
- **CFG/analysis** — `CFGBuilder::visitCompare()` is now a chain (one test block
  per header, guard last, match edge first); `AnalysisVisitor`/`BodyDeclCollector`
  treat a binding as a definition and a body-declared local; `LivenessAnalysisPass`
  skips `_`-prefixed names for both unused and dead-store warnings and never
  reports a pattern binding as a dead store; the guard is walked by the other
  three `visitCompare` visitors (`SelfFieldDefVisitor`, `NullableRefCollector`,
  `EscapeCheckVisitor`).
- **Diagnostics** — new `include/ErrorsPattern.h`: E092 `InvalidPatternError`,
  E093 `NonExhaustiveCompareError`, E094 `UnreachableArmWarning`; docs
  `docs/errors/codes/E092.txt`–`E094.txt`. `FirstWarningAt()` (`ResolverDecl.cpp`)
  deduplicates a TypeChecker warning per compile (see *Known pitfalls*).

## Removed assumptions

- **"`matches true:` works."** It did not. The original `switch` lowering widened
  the subject with `CastToType()` (an `i1` zero-extends to 1) but widened each
  pattern constant with `sextOrTrunc(64)` (an `i1` `true` sign-extends to −1), so
  the `true` arm never matched and a bool compare silently fell through. Nothing
  caught it because a bool compare was never exhaustiveness-checked, so few were
  written. Found by `tests/45_pattern_matching/12_exhaustive_with_wildcard.tr`
  (exit 134 on `g(true) == 1`); fixed in `CompareExprAST::codegen()`
  (`CodegenControlFlow.cpp`); regression test
  `tests/04_control_flow/compare_bool_true_arm_matches.tr`.
- **"A compare's `CFG` is a fan-out from the subject to every arm."** It is a
  chain now. Anything reading `CFGBuilder`'s compare shape (a future pass) must
  not assume every arm has the subject block as a predecessor.
- **"The roadmap's 'existing rule' for bool is real."** It was not (above).
- **"A duplicate literal pattern becomes a warning."** The roadmap says so, but
  the duplicate-value check is an existing hard error with existing `fail_` tests
  that the roadmap also demands stay unchanged. Kept as an error; only the
  *new* unreachable-after-catch-all case is a warning.
- **"Warnings raised from the TypeChecker appear once."** The compiler checks
  every body twice (pre-pass tree and main-pass tree), so an undeduplicated
  TypeChecker warning printed twice. `FirstWarningAt()` piggybacks on the
  per-compile set the facade already scopes with `Push/PopResolverCompileState()`.

## Known pitfalls

- **A `fail_*.tr` only proves it failed.** Three of mine failed for the wrong
  reason on the first draft: the error-value test compared `err` against a
  variant (already an E059 type error — the open-union rule is reachable only via
  guarded `_` arms), one probe left a field out of a pattern it meant to be valid,
  and a first guess at the struct-literal test. Each was checked by printing the
  code.
- **The subject is copied.** Evaluated once and snapshotted into an entry-block
  slot, so a large struct subject is copied once per `compare`. Deliberate (a guard
  that calls something mutating the subject's variable must not change later
  headers' view), but it is a cost; `json.stringify` copies a `JsonValue` it
  already received by value.
- **Top-level parenthesised patterns are value-only.** `matches (Point { x }):` is
  not a pattern; parens wrap a plain value only, as before.
- **A catch-all makes later arms dead in the CFG too, but not unreachable.** The
  chain keeps a fail edge out of a catch-all (so later arms have a predecessor and
  the CFG does not raise a *second* "unreachable block" warning beside E094). The
  cost: in a program that already earns E094, definite assignment sees a path
  where the dead arm "ran", so a variable assigned only by arms before the
  catch-all could be reported unassigned after it. Only reachable in code that is
  already warned as dead.
- **Dead-store on a correct `mut r: int = 0;`.** When a compare is exhaustive and
  every arm assigns `r`, the initial `= 0` really is a dead store and is now
  reported (before, the non-exhaustive fall-through edge hid it). Write `mut r:
  int;` — definite assignment proves it.
- **`FirstWarningAt` keys on file:line:col.** Two warnings of one kind at one
  location are one warning; fine for arms (one per header position), not a general
  dedupe for anything that can legitimately repeat at a point.
- **Not covered by anything:** LSP hover/goto on a binding (`BindingPatternExprAST`
  is in the facade's node-span table, but no test asserts a query lands on it);
  `ASTDiff.h` and `Lint.cpp` never walked `compare` at all (INV-LINT-1, LEC-005's
  job) and still do not, so a lint inside a compare arm is skipped as before.
