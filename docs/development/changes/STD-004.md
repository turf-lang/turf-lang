## Why

Turf had `math::PI` and `math::E` and nothing else: no way to name the largest
`int`, the range of an `int32`, or a `double`'s epsilon short of writing the
digits out. The owner asked for them in 2.2.0 (2026-10-24).

## Language semantics

Twenty-one `export immut` constants in `lib/std/core/math.tr`:

- **Limits:** `INT_MAX`, `INT_MIN` (`int`), `INT32_MAX`, `INT32_MIN`
  (`int32`), `DOUBLE_MAX`, `DOUBLE_MIN`, `DOUBLE_MIN_POSITIVE`,
  `DOUBLE_EPSILON` (`double`).
- **Constants:** `TAU`, `PHI`, `SQRT2`, `SQRT1_2`, `LN2`, `LN10`, `LOG2E`,
  `LOG10E`, beside the existing `PI` and `E`.
- **Infinity and NaN:** `INFINITY`, `NEG_INFINITY`, `NAN` (below).

`DOUBLE_MIN` is the most negative finite `double`, matching what `INT_MIN`
means for `int`. C's `DBL_MIN` is the smallest positive normal value, a
different quantity under the same spelling; Turf names that one
`DOUBLE_MIN_POSITIVE`, so `MIN` means the same thing for every type.

All of them are qualified only (`math::INT_MAX`): a prelude module's constants
are never bare (F-PRE-2), so no program's own `INT_MAX` changes meaning and the
prelude-shadow check (which covers bare functions) has nothing to look at.

An exported constant's initializer may now be a number with one leading `-`
(needed for `INT_MIN`, `INT32_MIN`, `DOUBLE_MIN`). An integer literal given to
a `double` constant is that value as a `double`, negated too; `-0` there is
`+0.0`, as it is for `mut x: double = -0;`. Anything else is still `E022`, with its hint saying
a number may start with `-`.

### Is this breaking?

No. New `pub` names in a module whose constants are qualified, and an
initializer shape that was `E022` before. A program that compiled compiles the
same.

### Infinity and NaN

`math::INFINITY`, `math::NEG_INFINITY` and `math::NAN` (a quiet NaN, sign bit
clear, printed `nan`). Turf has no literal for either value and `/` by zero
panics for `double`, so no initializer can spell them. Owner decision
(2026-10-24): add them now, without new syntax. They are kind 6 of the closed
intrinsic list (`src/sema/Intrinsics.h`, F-STD-2): ordinary `export immut`
declarations in `math.tr`, written `= 0.0`, whose value the compiler supplies,
keyed by the declaring module as kind 5 is. A program's own `INFINITY` keeps
its own value. Rejected: an `inf`/`nan` keyword (it would take two names from
every program), IEEE folding of `1.0 / 0.0` in a constant (it contradicts `/`
panicking everywhere else, and warns E167 in every compile, since `math` is in
the prelude), and an annotation on the declaration (annotations attach to
functions only).

`NAN == NAN` is `false`, so `math` also gets `is_nan`, `is_infinite` and
`is_finite` (`double -> bool`). These are bare-callable; the prelude-shadow
check (`scripts/check/prelude_shadow_check.sh is_nan is_infinite is_finite`)
found no program that declares any of them.

## Compiler architecture

- **Resolver** · `hoistExportedConstant()` (`src/resolve/ResolverCore.cpp`)
  unwraps one unary `-` around a `NumberExprAST` and negates the folded value,
  for an integer literal given to a `double` constant too.
- **Codegen** · `CodegenConstantValue()` (`src/codegen/CodegenCore.cpp`) emits
  an `int32` constant as an `i32`, the width every `int32` value has, instead
  of an `i64`.
- **Resolver, kind 6** · `hoistExportedConstant()` replaces the value of a
  `double` constant that `LookupSuppliedConstant()` (`src/sema/Intrinsics.h`)
  names for the declaring module.
- **Type checker** · unchanged. It already visits an exported declaration's
  initializer like any other, so a negated literal gets the ordinary range
  checks (`E076` for `-2147483649` as an `int32`) and type checks.

## Standard-library changes

"limits" and "infinity and NaN" sections, and `is_nan`, `is_infinite`,
`is_finite`.

- `tests/27_os_and_math_stdlib/04_math_limits_and_constants.tr`: each value,
