## Why

The audit (`OVERHAUL_CLOSURE_AUDIT.md` F-22) and the roadmap list seven defects
under "diagnostics reliability". Each was reproduced live before anything was
changed; two of them turned out to be smaller than they sounded and four larger.

1. **D25 — instantiation errors anchor at the innermost requester.**
   `s.add(b)` on a `Set<Big>` (no `operator==`) reported the error at
   `lib/std/collections/set.tr:125`, inside the stdlib, with no mention of the
   user's own line. And the monomorphizer's depth cap was wrong in a way the
   audit did not know: it counted the **total** instantiations drained, not a
   chain's length, so a program that called one generic function on 65 different
   types was rejected with a bogus `E079` whose "chain" was the whole cache.
2. **Parse-error cascade.** `mut f = fn(a: int): int { ... };` inside a function
   printed "Statements are not allowed outside of a function" — false, and
   printed *before* the real error.
3. **Hints.** E040 for `mut a: int = Node;` (a struct) said "create the variable
   `mut Node: int = 5;`"; E041 for `Node(5)` said "import the module that defines
   it"; `List<int>::default()` said "Expected 'mutable' or 'immutable'".
4. **Duplicate warnings.** `immut k: int = 5;` with no use: "declared but never
   used" **and** "assigned but never read".
5. **False positives.** `mut x: int = 0; x += 1; return x;` warned that the `= 0`
   was never read.
6. **INV-LINT-1.** `LintExpression` skipped every node kind nobody wrote a branch
   for. Confirmed live: `io::printline(a / 0)`, an `unsafe` block, `defer`, an
   array literal, a method call's arguments were all unlinted.
7. **Stdlib warning policy.** Already decided (DEC-4) and implemented in OVH-012
   (`--stdlib-warnings`); re-verified live: `import http; import json;` prints
   zero warnings by default and the `http.tr` one with the flag. Nothing to do.

## Language semantics

### Old behaviour

No language change. What the compiler *said* changed, and so did what it
accepted in four places that were bugs:

- 65 independent instantiations of one generic function → `E079` (wrong).
- `mutate(&i) recover run { ... }; return a[i];` with `i` set to 99 through the
  reference → the bounds check on `a[i]` was **elided**; an out-of-bounds read at
  exit status 0 (confirmed live; the plain call `mutate(&i);` aborted correctly).
- `mut v: int = g() recover run { return &x; };` → no error; a reference to a
  dead stack frame was returned (the same `return &x;` anywhere else is E086).
- Warnings: see above.

### New behaviour

- Any number of independent instantiations compile. `E079` fires when a request
  chain is longer than 64, or the total passes 4096 (a backstop), and prints the
  real chain.
- The check-elision pass sees an `&x` inside a `recover` (and inside every other
  node kind), so the bounds check stays; `return &x;` inside a `recover` block is
  E086.
- A diagnostic raised while re-typechecking an instantiation points at the user's
  call and lists the chain:

  ```
  ── error at line 6, col 6 [E011]
    In this instantiation: Cannot compare struct values with '=='. (...)
    Note: 'Set<Big>.add' requires 'Set<Big>.contains' here (lib/std/collections/set.tr, line 137, col 11)
    Note: 'Set<Big>.contains' requires 'Set<Big>.indexOf' here (lib/std/collections/set.tr, line 133, col 14)
    Note: 'Set<Big>.indexOf' requires 'Set<Big>.bucketFind' here (lib/std/collections/set.tr, line 125, col 29)
    Note: the error itself, inside 'Set<Big>.bucketFind' (lib/std/collections/set.tr, line 59, col 34)
    Note: in generic declaration 'set::Set.bucketFind' (lib/std/collections/set.tr, line 48, col 11)

    6 │     s.add(b);
      │      ^ Here!
  ```

- A parse error inside a function body is one error, not two.
- E040/E041 hints follow what the name is: `'Node' is a struct, not a value.
  Build one with `Node::default()` ...`; `'Node' is a struct, and Turf has no
  `Node(...)` constructor-call syntax ...`; for an enum, "name one of its
  variants, `Color::Variant`". An unknown *lowercase* name keeps the old
  "create it first" hint (guarded by a test).
- `x += 1` is a read of `x`; a never-read variable gets one warning, not two.

### Is this breaking?

No language change. The compiler is **stricter** in two places that were holes
(`return &local` inside `recover` is now E086; an `&x` inside `recover` now keeps
a bounds check — the second can only turn an out-of-bounds read into the abort it
should have been). Warnings can now appear where the lint previously did not
look (call arguments, `unsafe`, `defer`, array literals, `compare` arms) — they
are warnings, and in `lib/std` they are hidden by default (OVH-012).

## Compiler architecture

- **Lexer.** `g_curlyDepth`, the `{`/`}` share of `g_braceDepth`, maintained by
  `getNextToken()` and saved/restored wherever `g_braceDepth` is
  (`ParserModule.cpp`'s `LexerStateGuard`, `AnalysisFacade.cpp`'s
  `GlobalStateScope`). `printDiag()` (`Lexer.cpp`) names the file of a related
  note that is in a different file than the diagnostic (`lib/std/...` from
  `lib/std/` onward), because an instantiation chain walks out of the user's file.
- **Parser.** `SkipToNextTopLevelBoundary()` (`ParserCore.cpp`) resets its
  depth to the *curly* depth instead of 0 and resets both counters when it stops.
  Two hints: `List<int>::default()` ("put the type on the variable"), and the
  stale array-size hint (`int[5] arr` → `mut arr: int[5];`).
- **AST / visitors.** `include/ASTVisitor.h` generates `ASTVisitor`'s no-op
  methods **and** the new `ExhaustiveASTVisitor`'s pure-virtual ones from one
  `TURF_AST_NODE_LIST` (48 rows). New `include/ASTChildWalker.h`: the one place
  that says where each node kind's children are. Passes that must see everything
  derive from it and override only what they do something with. Also derived:
  `NullableRefCollector`, `SelfFieldDefVisitor`, `ASTNodeIDCollector` (the
  Sandbox's whole-tree collector, replacing `ASTDiff.h`'s chain); `ASTPrinter`
  derives from `ExhaustiveASTVisitor` directly and prints ten kinds it used to
  skip (see *Unresolved questions* 3).
- **Resolver.** `visibleTypeKind()` (`ResolverExpr.cpp`) feeds the E040/E041
  hints (`typeUsedAsValueHint()` in `ErrorsScope.h`).
- **Monomorphizer.** `InstantiationRequest::Parent`, `InstantiationEntry::Index`,
  `InstantiationCollector::setCurrentParent()`/`chainTo()`, `describeRequest()`/
  `describeChain()`, `anchorIndex()`, `exceedsInstantiationLimit()`;
  `kMaxInstantiationDepth` is now a chain length and `kMaxTotalInstantiations`
  (4096) is the fan-out backstop. `GenericInstantiationDepthError` takes the true
  depth and an optional total count (`ErrorsMonomorphize.h`).
- **CFG / analysis.** The dead-store walk applies each statement's reads and
  definitions as **one ordered event list** backwards (it applied all reads, then
  all definitions — wrong exactly for a read-modify-write), and skips a variable
  already reported as never used. `AnalysisVisitor`, `BodyDeclCollector` and
  `EscapeCheckVisitor` derive from `ASTChildWalker`.
- **Lint.** `LintExpression` and `LintChangedNodesOnly` are `ASTChildWalker`s
  (`LintVisitor`, `ChangedNodesLintVisitor`).
- **Optimization.** `collectAddressTaken()` (`ValueRange.cpp`) is an
  `ASTChildWalker` (`AddressTakenCollector`).
- **Driver.** `main.cpp`: the raw "Statements are not allowed outside of a
  function" is dropped when a parse error was already reported.
- **Test runner.** `scripts/test_runner.sh`: `EXPECT-DIAG`, `EXPECT-NO-DIAG`,
  `EXPECT-RUNTIME`.

## Runtime changes

None. (A change to `gc_rebuild_index()` was tried while investigating the CI
timeout below and reverted: it saved ~15%, not the cost. See *The CI timeout*.)

## Standard-library changes

None. (`lib/std/**` and `showcase/**` are compiled directly by the postflight;
the lint now reaches more nodes there, and any new warning is a `lib/std` warning
and so hidden by default.)

## New invariants

- **INV-LINT-1 → `holds`** (was `planned` since DIAG-001), now structural, and its
  scope widened from "lint" to every pass where a skipped node is a defect.
- **INV-DIAG-3** — an instantiation diagnostic points at the outermost user-code
  request and prints the real chain.
- **INV-TEST-2** — a `fail_*` test can pin its reason (`EXPECT-*`).

## Removed assumptions

- **"`Statements are not allowed outside of a function` is always the user's
  mistake."** It was usually the parser's own leftover. Both the resync and the
  message's guard are now conditioned on that.
- **"`kMaxInstantiationDepth` measures a depth."** It capped the number of
  entries one drain call processed. A program with 65 sibling instantiations was
  rejected. The comment above the constant described this as a "simplification";
  it was a defect with a reproducer.
- **"An instantiation error belongs where it was found."** It belongs where the
  user's code asked for it; the finding site is a note.
- **"A no-op default on `ASTVisitor` is safe."** It is safe for a pass that
  wants a few nodes and unsafe for one that wants all of them. The five
  hand-written node lists this milestone replaced each had its own omissions (see
  *Why*, items 6 and the two safety analyses). LEC-004 had patched `try` into one
  of them by hand and noted the others as a hole; this is that hole.
- **"`&x` is not a use."** (`AnalysisVisitor` had no branch for `AddressOf`.)
- **"A read-modify-write is a read followed by an independent write."** In the
  backwards liveness walk the order matters: the definition is applied first.
- **"A related note's position is in the diagnostic's own file."** No longer true
  once a chain crosses into `lib/std`.
- **"`tests/99_known_bugs/` exists."** `AGENTS.md` describes it; it did not. It does
  now, with one file.

## Known pitfalls

- **`InstantiationRequest::Parent` is the first discoverer.** A request found by
  two different clones keeps the first one's chain. The one correction: if
  ordinary (non-instantiation) code asks for something an instantiation asked for
  first, the entry is re-rooted — the shortest chain, ending at a call the user
  wrote, is the useful one.
- **The parent is set and restored explicitly, never with a guard object.** The
  nested `TypeChecker` reports an error by `longjmp`, which skips destructors; an
  RAII scope would not restore on exactly the path that matters.
- **`anchorIndex()` falls back to the outermost request** when every site is in
  `lib/std` (a non-generic stdlib function asked for it); there is no user hop to
  name.
- **A method's chain name is `Struct<args>.method`** using all of the request's
  type arguments. For a non-generic struct with a generic *method* the argument
  list therefore sits after the struct name, which reads slightly off.
- **E079's chain is clipped** (names to 60 characters, the middle of a long chain
  elided). The growth pattern is in the first hops; do not parse the line.
- **`kMaxTotalInstantiations` (4096) is only a backstop** — the fan-out test takes
  ~2 s to reach it. A real program with more than 4096 distinct instantiations
  would hit it; none comes close (the whole stdlib plus a large application is
  hundreds).
- **The analysis facade does not run the monomorphizer**, so no instantiation
  diagnostic is visible to a tool built on it (LSP). The runner can still pin the
  anchor, through the printed snippet.
- **`EXPECT-*` matches prose.** A reworded hint breaks the tests that quote it —
  intended — so quote the part that carries the meaning, never a column number.
  `EXPECT-DIAG` for a warning must be text (warnings have no code). The markers
  see the *compile* output only (and `EXPECT-RUNTIME` the program's); they do not
  count occurrences or check order.
- **`EscapeCheckVisitor` inside a `recover` block is straight-line.** The block
  is not split into CFG statements, so the walker visits its statements in order
  with one provenance map; a nested `if` that assigns a stack reference in one
  branch and a heap one in the other ends with the last writer. Before this it
  was not checked at all, so this can only add errors in a place that had none —
  watch for a false E086 there.
- **`ExhaustiveASTVisitor` is opt-in.** The Resolver, TypeChecker and
  `NarrowingVisitor` are still partial (and `CollectChangedNodeIDsInternal`
  defaults an unknown kind to "changed"). The boundary is written in
  INV-LINT-1's row.
- **`import` bodies are not descended into** by the walker (`visitModuleImport` is
  an explicit `{}`): a module is linted and analysed as its own file.
- **A broken function still produces a follow-on `Unknown function` (E041)** at
  its call sites, because it is dropped from the symbol table. Not fixed; it is
  the one remaining cascade.

## Unresolved questions

1. **Freeze?** `FREEZE.md` §6.0 rule 3: a session does not freeze things on its
   own initiative, and LEC-005's roadmap entry does not ask for one, so none was
   written. Candidates, if you want any: the `EXPECT-*` marker grammar; "an
   instantiation diagnostic anchors at the outermost user-code request";
   "`E079` measures a chain's length (64), with a 4096 total backstop". Say so and
   they become §6.20.
2. **Null-narrowing is blind inside `recover` blocks** (`NarrowingVisitor`, the
   same class as the escape fix, but not fixable the same way). `mut v: int = g()
   recover run { return p.val; };` with `p: &?Node` compiles clean and
   dereferences null (`tests/99_known_bugs/nullable_deref_inside_recover_block_unchecked.tr`).
   Recursing into the block with the statement's incoming facts would *reject
   correctly guarded code*, because the `if` inside the block narrows nothing
   without control flow of its own; the block has to be modelled in the CFG
   (statements as blocks, an edge for "falls off the end", `return` as an exit).
   That is a CFG change and a milestone of its own; it is a null-safety hole
   (F-PTR-1), so it should be scheduled, not forgotten.
3. ~~The other hand-written walkers~~ — **audited and resolved in the same
   session** (the owner asked for one pass). `NullableRefCollector` (a symbol
   touched only inside a `recover` was never Tracked) and `SelfFieldDefVisitor`
   now derive from `ASTChildWalker`; the latter overrides `visitRecoverExpr` to
   walk only the wrapped expression, since a `recover run` block must diverge and
   a field assigned in it is not assigned on the continuing path (previously
   right only by accident of the no-op default). `ASTPrinter` skipped ten node
   kinds silently (`recover`, `defer`, `unsafe`, `&x`, scope access, four
   declarations, `@caller_location`); it is now an `ExhaustiveASTVisitor` with
   printers for all of them. `ASTDiff.h`'s `CollectAllNodeIDsInternal` stopped at
   any kind it had no branch for, so the Sandbox's incremental validation never
   linted what sat under a `recover`/`defer`/`unsafe`/`compare` when the baseline
   was missing; it is now `ASTNodeIDCollector` (in `ASTChildWalker.h`, still
   descending into an import's body as before). `CollectChangedNodeIDsInternal`
   was left alone: it marks an unknown node kind *changed*, the safe default.
   Not covered by a test: `--dump-ast` output and the Sandbox collector (no
   harness reads either); checked by hand (`--dump-ast` on a program with all
   four shapes) and by the suite.
4. **The follow-on E041 for a function that failed to parse.** Suppress by
   remembering the name of a function whose parse failed?

## The CI timeout (asked for with this milestone)

The report: the suite's one failure was `tests/08_e2e_stress/07_heap_bounded_allocation.tr
(Timed out after 300s)`, 993 of 994 passing, "(Likely infinite loop)". The 300 is
`TURF_TEST_TIMEOUT_SEC=300` on the two `TURF_GC_STRESS=1` workflow steps
(`-O0`, `-O2`); it is not a default.

- **Not a hang, not a regression.** Re-measured at this HEAD, serially, on an idle
  machine: `TURF_GC_STRESS=1` takes **193 s at `-O0` and 205 s at `-O2`** (peak RSS
  ~2 MB, exit 0, every assertion passing) — the same ~3.5 minutes FDN-005 recorded
  on 2026-09-28. A bound of 300 s is 1.5x that, and a loaded shared runner is
  slower than that by more than 1.5x.
- **Where the time goes.** Under stress every one of the 5,000,000 `heap()`
  allocations is a full collection, and each collection marks the live list (up to
  1000 nodes, ~500 on average) through the type descriptor. That is inherent to
  collecting on every allocation. The one thing that looked wasteful —
  `gc_rebuild_index()` `qsort`s the *whole* block table every collection — was
  replaced by a sort-the-pending-and-merge and measured: **163 s vs 193 s**, ~15%.
  Not the cost, so not worth a change to the collector's core ordering code; it was
  reverted. (If the stress steps ever need to be cheap, the lever is a smaller live
  set or fewer allocations in the test under stress — not the table sort.)
- **The change.** `.github/workflows/test.yml`: both stress steps now use
  `TURF_TEST_TIMEOUT_SEC=900`, with the measurement and the failure written next
  to it. 900 follows the ASan job's own sizing (700 s for a measured 637 s is only
  10% of headroom; 900 s for ~200 s here is 4.5x). `scripts/test_runner.sh`: under
  `TURF_GC_STRESS` a timeout says "possibly just slow, see TURF_TEST_TIMEOUT_SEC"
  instead of "Likely infinite loop".
- **Not verified here:** a real CI run. The bound is sized from local numbers; the
  next CI run is the check.
- **Left alone, flagged:** the ASan+stress steps (`TURF_TEST_TIMEOUT_SEC=700`)
  measured 637 s when they were written. They did not fail in the report, but their
  margin is the thin one; raise them if they ever do.
