## Why

The front end keeps its working state in process-wide globals: the lexer
cursor (18 `extern`s in `Lexer.h`), `GlobalSymbolTable`, the diagnostic
list, the import caches, the `setjmp` recovery buffer
(`ARCHITECTURE_SIMPLIFICATION.md` §1). `main.cpp` runs the pipeline once per
process and never has to care. Anything that runs it again in the same
process does: `turf-lsp` re-analyses a buffer on every edit, and the SLM
`Sandbox` re-compiles a candidate fix from *inside* `DiagnosticEngine::add()`
while the compile that raised the diagnostic is still running.

Each of those callers hand-wrote its own save/restore of "the globals that
matter" — `turf-lsp/src/CompilerService.cpp`, and in-tree
`src/CompileBuffer.cpp` (which the Sandbox used) — and each got a different
subset right. `turf-lsp` no longer builds against HEAD at all (it overrides
the `visitDefaultInit` SEM-004 deleted, audit F-20). This session found
three pieces of per-compile state that *neither* reset (see *Removed
assumptions*), two of them reproduced as wrong diagnostics.

SMP-001 (`ROADMAP_v2.0.0.md` Part IV) replaces the hand-written copies with
one tested API whose implementation is the only save/restore in the
compiler.

## Language semantics

### Old behaviour

No change to what any program means. One diagnostics change, visible in an
ordinary CLI compile: `NeverReturnsErrorWarning` ("'f' is declared to
return a fallible type ('!T') but never actually returns an error") was
deduplicated by line and column only, so a fallible function in an imported
module at, say, 3:1 suppressed the warning for the entry file's own
fallible function at 3:1.

### New behaviour

The warning is deduplicated by file, line and column; both functions are
warned about.

### Is this breaking?

No. One more warning can appear where one was wrongly missing.

## Compiler architecture

**New: the query facade.** `include/turf/Analysis.h` /
`src/AnalysisFacade.cpp`, in `turfcore`.

```cpp
namespace turf {
struct SourceBuffer { std::string Path; std::string Text; };
struct AnalysisOptions { bool AllowUnsafeModules; bool IncludeStdlibWarnings;
                         bool RunLint; std::string InstallRoot; };
struct Location { std::string Path; unsigned Line, Col; };   // 1-based, byte columns
struct Diagnostic { Severity Level; std::string Code, Message, Hint;
                    Location Where; std::vector<RelatedInformation> Related; };
struct SymbolInfo { std::string Name; SymbolKind Kind; const TurfType *Type;
                    std::optional<Location> Declaration; };
class AnalysisResult {
  const std::vector<Diagnostic> &diagnostics() const;  bool succeeded() const;
  const TurfType *typeAt(Path, Line, Col) const;
  std::optional<Location> definitionOf(Path, Line, Col) const;
  std::vector<SymbolInfo> symbolsInScope(Path, Line, Col) const;
  // Internal representation (NOT 2.x-stable): program(), preludeImportCount(),
  // symbols() (the Resolver's table), typeOf(const ExprAST*)
};
AnalysisResult analyze(const std::vector<SourceBuffer> &, const AnalysisOptions & = {});
}
```

Decisions taken in writing it, beyond the roadmap's sketch:

- **`Diagnostic` is the facade's own type**, not `DiagnosticEngine::Diag`.
  `Diag` carries SLM internals (`SLM::DiagnosticHints`, `ErrorCategory`) and
  ANSI color escapes baked into `Msg`; a 2.x-stable header cannot promise
  either. Messages are ANSI-stripped (the LSP already stripped them itself).
- **`AnalysisResult` is a pimpl.** The header includes no compiler header —
  `AST.h` pulls in LLVM — so a tool can include it without the compiler's
  include path shape becoming its API.
- **An explicitly unstable "internal representation" section.** `turf-lsp`
  does semantic highlighting, completion over a module's members, and
  references by walking the AST and the Resolver's tables. Three queries
  cannot replace that, and freezing the AST as 2.x API would freeze the
  compiler. So the result exposes `program()`/`symbols()`/`typeOf()`
  read-only and says in the header they are outside the stability promise.
  The completion criterion's "uses only the facade" is read as: a tool never
  runs a pass or touches a global itself.
- **Buffers after the first are overlays.** They replace the disk text of the
  file an import loads (`SetSourceOverlay()`, consulted by `ParseFile()`);
  module *resolution* is unchanged and still needs the file to exist on
  disk.
- **`InstallRoot`** overrides `TurfInstallRoot()` for the analysis (an
  editor setting); empty means the CLI's own lookup.
- **`RunLint`** exists because the Sandbox needs lint findings and the CLI
  produces them during Codegen, which the facade never runs.
- **A recursive mutex**, because an analysis can start inside another on the
  same thread (the Sandbox inside a `--smart` compile) — safe, since every
  save is a stack push.

**The position index.** Built during `resolveAll()` through the Resolver's
existing scope-snapshot callback (`Resolver::setScopeSnapshotCallback`): one
entry per located node in a caller-supplied file (lib/std is not indexed —
thousands of nodes no query asks about), each with its name span and the
variables visible there (consecutive identical scopes stored once). A call's
callee is indexed from its call — the Resolver looks a callee's name up
without dispatching it as a child, so the callback never sees it (found by
the tests: `definitionOf` on a function name failed until this was added).
Module → file mapping for cross-module definitions is resolved inside the
analysis, while its install root is in force.

**The entry file is parsed the way `main.cpp`'s mandatory pass parses it**:
leading `unsafe module;` pragma, prelude injection, the OVH-011
`ClaimEntryFileImportSlot()` self-import check, declarations vs statements
(`Unexpected ';'` / `Expected ';'`), and "Statements are not allowed outside
of a function" — which the CLI prints and `_Exit`s on — as a diagnostic.
`CompileBuffer`'s loop had none of the first three or the last.

**Global state: `GlobalStateScope`** (`src/AnalysisFacade.cpp`) saves on
construction and restores on destruction: every lexer cursor variable,
`SourceFilename`/`MainSourceFilename`/`SourceLines`, `AllSourceLines`
(swapped, not copied — it holds all of lib/std's lines),
`g_braceDepth`/`g_parseRecursionDepth`/`g_protoOnlyPass`, the recovery
`jmp_buf`/flag, `g_AIEnabled`, `g_AllowUnsafeModules`,
`CompilerExecutablePath`, `GlobalSymbolTable`, and, through one hook per
subsystem:

- **Parser** — `PushParserCompileState()`/`PopParserCompileState()`
  (`Parser.h`) replace `PushImportCycleState()`/`PopImportCycleState()` and
  `SwapParsedTopLevelASTs()` (removed) and additionally cover
  `UnsafeTopLevelDecls`, `UnsafeModuleFiles`, and the new overlay /
  install-root settings.
- **Resolver** — `PushResolverCompileState()`/`PopResolverCompileState()`
  (`Resolver.h`): the never-returns-error dedupe set, moved from a
  function-local `static` to file scope.
- **Diagnostics** — `DiagnosticEngine::saveState()`/`restoreState()`
  (`Lexer.h`): the list, `ErrorLines`, the collect-all flag and the SLM
  cascade guard, copied verbatim. Not `restoreDiagnostics()`, which rebuilds
  `ErrorLines` from the list: after `flushAll()` (which empties the list and
  keeps `ErrorLines`) that changes `hasErrors()`.

It deliberately never touches `GlobalSourceFile`, the `ifstream` a CLI
compile reads through: the analysis reads its own `istringstream`, and the
host's stream pointer is put back untouched.

**Removed:** `include/CompileBuffer.h`, `src/CompileBuffer.cpp`
(`CompileBufferBestEffort()`, `GetVisibleNamesAtPosition()`); superseded by
`analyze()` and `symbolsInScope()`. Their only in-tree caller was the
Sandbox.

**Sandbox** (`src/Sandbox.cpp`, stage 2) — `runFullSemanticPass()` is one
`turf::analyze()` call with `RunLint`; `validate()` no longer saves/restores
`SourceLines` or the diagnostic list, and its own lint save/restore of the
recovery buffer is gone. Validation diagnostics are now
`std::vector<turf::Diagnostic>` (`Sandbox::getValidationDiagnostics()`);
`SLMIntegration.cpp`'s retry prompt reads `.Message` (ANSI-free) instead of
`.Msg`. The diffed "changed nodes" AST is now the user's declarations only,
matching the original-program AST it is diffed against (which never had the
prelude).

**Driver / build** — `CompilerExecutablePath` is defined in `turfcore`
(`ParserModule.cpp`, beside `TurfInstallRoot()`, its reader) instead of
`main.cpp`; the facade fills it from the running executable when an
embedder left it empty. New CMake target `turf-api-tests`, top-level builds
only (`turf-lsp` includes this `CMakeLists.txt` for `turfcore`).

**Cancellation (stage 3, step 0, 2026-10-06)** — `AnalysisOptions::ShouldCancel`
and `AnalysisResult::cancelled()`. `analyze()` asks after `parseEntryFile()` and
after `resolveAll()`; on `true` it destroys what it built *inside* the
`GlobalStateScope` and returns a fresh empty result with `cancelled() == true`.
Empty rather than partial on purpose: a half-resolved program answers some
queries wrongly and others not at all (`symbolsInScope()` would still list the
functions the Resolver had hoisted), and a caller that cancelled wants neither.
No `longjmp` is involved, the early return goes through the scope's destructor.
Granularity is the pipeline's own two boundaries; the passes have no
interruption points. `tests/api` `testCancellation`: a callback that never
fires changes nothing (asked exactly twice), a cancel at each boundary gives an
empty result, and the host's globals are intact after each.

**A missing standard library is a diagnostic (stage 3, 2026-10-06)** —
`parseEntryFile()` called `ParsePreludeImports()` outside any recovery guard, so
with no `lib/std` to find (an editor extension installed without it, a
`TURF_HOME` pointing nowhere) the prelude's E027 "Could not find module 'int'"
was raised with nothing to catch it and the process called `exit(1)`: the
language server vanished on the first document and said nothing. The call now
runs in the same `setjmp` guard as every other top-level parse, so the analysis
carries E027 at the top of the file (and one per `import` the program makes),
`preludeImportCount()` is 0, and the process survives. `tests/api`
`testMissingStdlibIsADiagnostic` points `InstallRoot` at an empty directory and
checks all of that plus that the next analysis is unaffected.

**Diagnostics** — the dedupe-key change in *Language semantics*.

No Lexer grammar, AST, TypeChecker, Monomorphizer, Codegen, CFG or
optimization change.

## Removed assumptions

- **"Per-compile parser state is reset between compiles."** Not all of it
  was. `UnsafeModuleFiles` (files that declared `unsafe module;`) was reset
  by nothing — not `ClearParsedTopLevelASTs()`, not the old
  `PushImportCycleState()`. In any process that analyses more than once, a
  file analysed once with the pragma kept the raw-pointer capability after
  the pragma was deleted. Reproduced by
  `testUnsafeCapabilityDoesNotOutliveThePragma` with the reset removed: the
  pragma-less file analysed clean. `UnsafeTopLevelDecls` likewise kept raw
  pointers to a previous compile's (freed) AST nodes — a later node
  allocated at the same address would be treated as declared inside
  `unsafe { }`. Not reproduced (allocation-address dependent); fixed by the
  same push/pop.
- **"A Resolver warning is emitted once per function."** It was emitted once
  per *process* per line:col: the dedupe was a function-local `static` that
  nothing reset, so the second analysis of a file silently lost the warning
  (`testWarningSurvivesReanalysis` — both runs fail with the old no-op
  reset), and keyed without the file (`testWarningDedupeIsPerFile` — 1
  warning instead of 2 with the old key).
- **"`CompilerExecutablePath` is the embedding program's to define."** It
  is now defined in `turfcore`. A program that still defines it (today:
  `turf-lsp/src/main.cpp:47`) gets a duplicate-symbol link error and must
  delete its definition; it may keep assigning it.
- **"Tooling calls `CompileBufferBestEffort()`."** Removed; use
  `turf::analyze()`.
- **"`Sandbox::getValidationDiagnostics()` returns `DiagnosticEngine::Diag`."**
  It returns `turf::Diagnostic`; `.Msg` is `.Message`, with no ANSI codes.
- **"A restore can reopen the source file."** The old `CompileBuffer` restore
  ended with `OpenSourceFile(SourceFilename); resetLexer();`, rewinding the
  host compile's input to byte 0 when the Sandbox ran mid-parse. Simulated
  in the facade against `tests/44_slm_diagnostics/fail_deterministic_typo_keyword.tr`
  under `--smart`: no difference in output, so no user-visible failure is
  claimed — but the facade never touches `GlobalSourceFile`, and must not.

## Known pitfalls

- **New front-end state must go in a hook.** A global or function-local
  `static` that one compile fills and a later one reads will leak between
  analyses exactly as the three above did. Add it to
  `PushParserCompileState`/`PushResolverCompileState`/`GlobalStateScope`
  and add a back-to-back fixture that exercises it — the isolation test only
  catches what its programs touch.
- **An analysis reports fewer diagnostics than `turf`.** The CFG passes
  (definite assignment, FDN-002 escape rules, liveness, infinite recursion,
  …) and monomorphization-time errors run only inside Codegen / the
  pre-pass. A clean `succeeded()` does not mean the file compiles.
- **Positions are 1-based with byte columns**, the compiler's convention; an
  LSP must convert from 0-based lines and UTF-16 columns.
- **Only caller-supplied files are indexed.** `typeAt`/`definitionOf` on a
  lib/std file return nothing unless that file is passed as a buffer.
- **After the first error inside a function, the rest of that function is
  unindexed** — the Resolver recovers per top-level declaration, not per
  statement.
- **`definitionOf` covers variables, parameters, functions and methods.**
  Not fields, struct/enum type names, enum variants, or module names yet.
- **`symbols()` is the Resolver's table at the end of resolution** — the
  global scope. Scope-sensitive lookups on it answer for the file's top
  level, not a position; use `symbolsInScope()`.
- **The module directory index (`IndexModuleDir()`) is cached per process.**
  A long-running tool does not see a module added to lib/std or lib/usr
  until it restarts.
- **An overlay does not make a module importable.** Resolution still looks
  for the file on disk.
- **`setjmp` locals.** `HoistingClean` is `volatile` because it is assigned
  after a `longjmp`; any new local written on the far side of one of the
  facade's `setjmp`s needs the same.

### Step 0 — add cancellation to the facade (this repository)

turf-lsp's `CompilerService::analyze()` takes an `isCancelled` callback. It
checks it between parse and resolve and between resolve and typecheck, and
returns `nullptr` when it fires, so a superseded keystroke analysis stops
early (see its `include/CompilerService.hpp:20-29`). `turf::analyze()` has
no equivalent. Add one rather than lose that responsiveness on large files:

- `AnalysisOptions` gets `std::function<bool()> ShouldCancel;`. It is empty by
  default, and when empty it is never called.
- `analyze()` calls it after `parseEntryFile()` and after `resolveAll()`.
  When it returns true, `analyze()` returns at once. The result reports
  `cancelled() == true`, has no diagnostics, and its queries answer nothing.
  `GlobalStateScope` restores state as usual: the early return goes through
  its destructor, and no `longjmp` is involved.
- Add `bool AnalysisResult::cancelled() const;`. It belongs with the stable
  queries, not the internal section.
- Add a `tests/api` test with two parts. One cancels after parsing, then
  checks `cancelled()` and that the host state is intact, the same way
  `testHostStateIsRestored` does. The other runs a cancel callback that
  never fires and checks that the output matches a run without one.
- Add a line to this record's *Compiler architecture* section.
