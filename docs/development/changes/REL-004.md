## Why

Part VII makes "any compiler crash, assertion, ICE or hang on a valid program,
or on any program the fuzzer produces" and "any sanitizer report in the
compiler or runtime" automatic release blockers. Before this item nothing
looked for either: the ASan job instrumented the *runtime* only, no input
outside `tests/` was ever mutated, and `lib/std`/`showcase/` were compiled by
`session_postflight.sh` (a human) and never by CI.

The fuzzer found real bugs on its first runs, so the "why" is concrete. Each was
a one-token mutation of a passing test:

| Input | Before | Now |
|---|---|---|
| `fn main(): int { return 0------…(5000×) }` | segfault (C++ stack overflow in the type checker) | E111 "Expression nested too deeply to parse" |
| `fn f(x: int): int ;` / `operator [](b: Box, i: int): int ;` | segfault (null function body in Codegen) | E107 "has no body" |
| `fn main(): int { return; }` | "Internal compiler error: generated LLVM IR is invalid" | E064 "gives back no value" |
| `n[0]` on an `int`, `box[0]` on a struct with no `operator []` | `LLVM ERROR: Internal error: Base is not an array or pointer` | E126 "Cannot index a value of type 'int'" |
| `import test %` (any binary operator after a top-level `import`) | the `%` swallowed the next declaration as its right operand, so `import` and `main` vanished from the Resolver's hoisting pass and a **second error appeared inside `lib/std/testing/test.tr`** | one E102 at the stray operator |
| `(((n--…1500×)--…1500×)--…1500×)`: pieces each inside every limit | segfault (exit 139) in the type checker, tree 4500 deep | E111, pointing at the declaration |
| `fail_generic_fanout_instantiation_limit.tr` | 23 s to reach the 4096-instantiation cap | 0.4 s, same E079 and same request count |
| `struct S { x: guess }` (F-GUESS-3), `fn f(x: guess)`, `fn f(): guess` | the field compiled silently; the parameter failed at the call ("No matching overload"); the return type said "declares 'guess' but returns 'int'" | one E128 at the `guess`: "can only declare a local variable" |
| any program rejected with an error while compiled with `-g` that mentions an `http::Server` (`tests/34_http_and_json/fail_server_routes_private.tr`, found by running the **existing suite** at `-g`) | `Assertion 'Ty->isSized()' failed` in `getDebugType()` | the same E088 as without `-g` |

## Language semantics
### Old behaviour
The four inputs above crashed or hit an ICE; see the table.
### New behaviour
Each is a diagnostic with a code. `fn f(): T;` ("forward declaration") is no
longer parsed at all: nothing downstream accepted a function with no body, and
no program in `tests/`, `lib/std/`, `showcase/` or `examples/` used one.
### Is this breaking?
No for any program that compiled. A program that used `fn f(): T;` crashed the
compiler, so there is nothing to migrate.

## Compiler architecture
- **Parser** — `ParsePostfixExpression()` (`ParserLiteral.cpp`) now spends the
  shared recursion budget (`g_parseRecursionDepth`) once per link of a postfix
  chain and gives it back when the chain ends. A chain is a loop, not recursion,
  so `ParseRecursionGuard` never saw it, yet every link deepens the AST the
  recursive visitors walk. `ParseFunction()` and `ParseOperatorDecl()`
  (`ParserDecl.cpp`) report `;` after a signature instead of building a
  `FuncDefExprAST` with a null body.
- **TypeChecker** — `visitReturn()` rejects a bare `return;` unless the function
  returns `void` or `!void`. `visitArrayAccess()` reports E126 for a base nothing
  can index: a primitive, or a value whose type has no `operator []`/`[]=` written
  for it (candidates are gathered by *name* from every visible file, so "none
  found" is never the test; the first parameter's type head is compared). An
  assignment target stays quiet there because it has its own E056
  (`IndexWriteTarget_`, `TypeChecker.h`).
- **Build** — `TURF_COVERAGE` (`CMakeLists.txt`, `main.cpp`): gcov instrumentation. `main()` ends in `std::_Exit()`, which skips the atexit handler gcov writes its counters from, so the first coverage build reported **0%** for the whole compiler; `TURF_FLUSH_COVERAGE()` calls `__gcov_dump()` before each `_Exit` under the flag. Measured result in `tests/CONFORMANCE.md`.
- **Build** — `TURF_SANITIZE_COMPILER` (`CMakeLists.txt`): ASan + UBSan on
  `turfcore`, `turfc`, `turf-api-tests`, with `-fno-sanitize=vptr` (LLVM has no
  RTTI) and `-fno-sanitize-recover=undefined` (a report aborts, so the runner
  sees a crash).
- **Parser** (F-GUESS-3) — `ParseType()` accepts `guess` only while the local-variable declaration parse has set `g_AllowGuessType` (set only when the annotation *starts* with `guess`, so a generic argument or pointee cannot carry one); anywhere else it is E128 and the parse of that declaration stops.
- **Parser** (further) — `ParseExpression()` returns a declaration node (`fn`, `struct`, `enum`, `error`, `machine`, `extern fn`, `import`) without looking for a binary operator after it. A top-level `import` is parsed by `ParseImport()`, not
  `ParseExpression()` (`main.cpp` ×2, `ParserModule.cpp` ×1): an import is never
  part of a larger expression. `AppendFlattenedTopLevelDecl()` measures every
  top-level declaration's finished tree with `AstDepthProbe`
  (`ASTChildWalker.h`: a depth-fenced walk that never recurses past the limit
  itself) and reports E111 above `MaxParseRecursionDepth`, releasing rather than
  destroying the tree (destruction recurses as deep as the passes would).
- **Monomorphizer** — `InstantiationCache::find()` is a hash lookup on
  `(Kind, DeclKey, SourceModule, Decl, getName() of each argument)` followed by
  `sameInstantiationAs()` on the bucket; it was a linear scan that rebuilt two
  nested type names per comparison. Sound only because every `isEquivalent()`
  implies equal `getName()`; the header says so beside the hash.
- **Codegen** — `getDebugType()` (`CodegenCore.cpp`) returns the replaceable stub
  for a struct whose LLVM type is not `isSized()`, not only for an opaque one: a
  struct can have a body and still contain a field that is an opaque struct nobody
  has codegenned yet, and `DataLayout` asserts on an unsized type.
- **Everything else** — None.

## Removed assumptions
- *"A function with no body is a forward declaration."* It never worked; the
  parser accepted it and Codegen dereferenced null.
- *"`ParseRecursionGuard` bounds the depth of every expression."* It bounds
  recursion. A loop that wraps its result in itself (postfix chains) needs its own
  accounting. Anything else added to the parser in that shape does too.
- *"If the TypeChecker gave an expression no type and no error, Codegen copes."*
  Codegen's `report_fatal_error` is a crash. A `setType(&Node, nullptr)` with no
  `reportError` beside it deserves a second look.
- *"The suite passing means the tree builds."* The runner covers `tests/` only.

## Known pitfalls
- **The ASan stack.** Under `TURF_SANITIZE_COMPILER` the parser's 2000-level
  nesting cap is not reached before an 8 MB stack is: `fail_deeply_nested_expression`
  and `fail_deeply_nested_generic_type` die with a SEGV. The sanitizer job runs
  `ulimit -s 65536`. Measured: the plain release build needs under 4 MB for the
  same input, so the plain build's margin is about 2×; a Debug (`-O0`) build was not
  measured.
- **`pkill -f crash_fuzz.py` kills the shell that typed it** if the command line
  contains that string. Use the PID.
- **A fuzzer hang is only a finding if the seed does not hang.** The E079
  fan-out test takes ~20 s to compile on its own and was reported as the
  first "hang". The fuzzer now re-runs the unmutated seed before keeping one.
- **Minimizing a hang costs the timeout per probe.** The reducer has a probe cap
  *and* a 180 s wall-clock cap; without the second one a run that found a hang
  was still reducing it 12 minutes after its time budget ended.
- **A signature regex is a guess about output.** The first "assertion" finding
  was the stdlib's own message "An assertion failed here". The patterns match
  glibc/LLVM's formats (`Assertion \``, `LLVM ERROR`), not the word.
- **Symlinked seed directories.** A seed that imports a sibling must find it, so
  the fuzzer mirrors the seed's directory as symlinks and writes the mutant
  beside them. Never run the compiler with `cwd` in `tests/` (`turfc --resolve`
  writes into the cwd).

## Unresolved questions
0. **Coverage reading.** File-level gcov percentages overstate gaps (header inline functions are credited to each including file; STL instantiations; `--dump-*` printers; facade-only code). Use the uncalled-function list, filtered to Turf's own symbols, as the gap finder. Recipe in `tests/CONFORMANCE.md`.
1. *(Resolved in this record.)* The `import test%` "cascade" was not a
   cascade policy problem at all: `import` went through `ParseExpression()`, so a
   binary operator after the module name ate the next declaration. Fixed at the
   cause, not by hiding errors that are anchored in `lib/std`. The earlier
   attempt, which hid *warnings* from the stdlib (`--stdlib-warnings`), could
   never have helped: this was an error.
   **Same class, also fixed:** every other declaration was parsed with
   `ParseExpression()` too, so `fn f(): int { return 0; } % 5` read the `%` as an
   operator on the function and said "A void value can't be used here" (E067)
   about a stray token. `ParseExpression()` now returns a declaration node
   as it is, before any binary-operator loop; the message is E103 at the `%`.
2. *(Resolved in this record.)* The 20 s compile was `InstantiationCache::find()`.
3. *(Resolved in this record.)* Tree depth is now measured on the finished tree.
   **Limits of the fix:** it covers top-level declarations of the entry file and
   of every module (all go through `AppendFlattenedTopLevelDecl()`); an `import`
   body is checked as its own file. The limit is the parser's 2000, not a
   measured stack budget: 2000 levels of a *wide* node (e.g. a `compare` with a
   large frame) might still be too deep on a small stack, and the ASan build
   needs the bigger stack regardless.
4. **CI is unproven.** Nothing in `test.yml`'s new steps, `nightly.yml`, or the
   sanitizer job has run on a runner; they were verified by running the same
   commands locally. `nightly.yml`'s issue filing in particular has never run.
   Deferred by the owner (2026-10-12): Actions minutes are exhausted for about
   three weeks; check the first runs then and file any failure as an issue.
5. **The fuzzer's reach.** It mutates passing programs; it does not generate
   programs and it mutates one file at a time. (Program generation now lives
   in the separate `turf-fuzz` repository.) Seeds under `examples/` and any
   package project are skipped (`turf.toml` directories).
