## Why

A test that is set aside, one that may hang, one that must hold at every
optimization level, a short expected output, and a subset of a large suite:
the compiler's own suite does each with runner flags, file-name conventions
and `.expected` files. Options let a test written in Turf say them where the
test is.

## Language

`@test(<outcome>, name: value, ...)`, each option at most once, in any order:
`skip: "reason"`, `timeout: <ms>`, `levels: all | [O0, ...]`,
`stdout: "text"`, `tag: "t" | ["t", ...]`, and the bare word `serial`. Values
are literals; `timeout:` and `stdout:` on a `compile_error` test, an unknown
name, a repeat and a value of the wrong kind are E146, whose hint lists the
outcomes and the options. The names reserve nothing. `FREEZE.md` 6.22 has the
rules.

An annotation argument may now be a `[...]` list of words, paths, whole
numbers and strings (`AnnotationArg::IsList`, `Items`); `@test` is the only
annotation that accepts one.

## Compiler and runner

- **`TestAnnotation::parse()`** reads the options into `Spec` (`Skip`,
  `TimeoutMs`, `Levels`, `HasStdout`, `Tags`, `Serial`); the test build's
  manifest carries them (`skip`, `timeout_ms`, `levels`, `stdout`, `tags`,
  `serial`, present only when written), and `TestExpect::ParseManifest()`
  reads them back.
- **`turfc --test`** (`TestRunner.cpp`):
  - `skip:` reports `SKIPPED (reason)`; the summary counts `Skipped:` apart
    and lists each with its reason (`TestResult::Skipped`).
  - `timeout:` is the test's own limit in milliseconds; `RunProcess()` takes
    milliseconds, and kills the test's process group on time-out as before.
  - `stdout:` runs the test with stdout through a pipe of its own
    (`RunProcess(..., SplitStdout)`, POSIX and Windows); `TestStdout()` drops
    the report line, and the rest must equal the option.
  - `levels:` builds the file once more per level a test names (the first
    time one needs it) and runs the test at each, as `name [-O2]`; the first
    failing level ends it.
  - `--tag <tag>` / `--skip-tag <tag>` (`TestRunOptions::Tags`, `SkipTags`)
    select `@test` functions by `tag:`; a file that is a test of its own has
    no tags.
  - `serial` is recorded and has no effect: one file's tests already run one
    at a time.
- **Driver interface 1.13**, feature `test-tags`.
- **turf-cli**: `turf test --tag` / `--skip-tag`, passed through, asking for
  interface 1.13 only when used.

## Tests

- `tests/57_test_functions/07_options.tr`: every option on a passing test.
- `tests/57_test_functions/fail_test_*`: one file per misuse (an unknown
  option, a repeat, each wrong value kind, `timeout:` and `stdout:` on a
  `compile_error` test).
- `scripts/smoke/test_cmd_smoke.sh`: the failing side, run by the runner: a
  skip listed and counted, a time-out killed with the file's other tests still
  run, a wrong `stdout:`, each level of `levels: all`, a failure naming its
  level, and `--tag` / `--skip-tag` selection.

## Known pitfalls

- `levels:` multiplies a file's build time by the levels it names, once per
  file however many tests ask for each level.
- The TDP's check that `levels: all` catches a test whose output differs
  between levels has no fixture: no program in the suite behaves differently
  by level on purpose.
