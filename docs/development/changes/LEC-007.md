## Why

2.0 freezes the standard library: what is `pub` after this is what a 2.x
program can rely on, and changing it later is a 3.0 break. LEC-002 had made
everything private by default and then marked nearly everything public to keep
the build green; nobody had reviewed the result. The review found a library
that disagreed with itself (a dozen camelCase names among snake_case ones;
`write_string` returning `bool` beside `read_to_string` returning `!string`),
a promised-but-missing `StringBuilder`, a `Map` that LEC-002 had made
impossible to iterate, and a quadratic `repeat`.

## The owner's rule for what is public

Stated by the owner during this session, after I got it wrong twice, and now
frozen as F-API-4:

> Functions that do a job are public, whether or not *we* use them — real users
> will. Struct internals with no use in a real program are private. Server
> internals stay private until they serve a real job in a real program.

What I did wrong, recorded because the next session could repeat it:

1. I started to make `test::assert_fail_eq/neq` private because nothing outside
   `test.tr` calls them. That is the "we don't use it" reasoning the rule
   forbids. **Not done; they stay public.** (They are message builders that
   always fail, so whether a program *wants* them is arguable — but the rule is
   that the repository's own use is not the test.)
2. I made the raw libc bindings in `io` (`fopen`, `fwrite`, `getchar`,
   `printf`, ...), `random` (`rand`, `srand`) and `sys` (`write`) public,
   reasoning that they enabled things the wrappers do not (append, streaming,
   seeding). The owner stopped it immediately: raw C bindings are dangerous to
   expose, and the wrappers *are* the interface. **Reverted before any commit**
   (`git checkout` of the three files). The rule in F-API-4 now says so.

## Standard-library changes

### Review, module by module

"Public" means after this change. The full list is `scripts/stdlib_surface_check.sh --list` (305 items).

| Module | Decision |
|---|---|
| `int` `double` `bool` | Kept as is. Already snake_case. |
| `char` | **Renamed** all nine helpers to snake_case (`is_digit` … `to_lower`); `is_alphanumeric`, one word. |
| `array` | Kept. (Every function takes an explicit length — a language limitation, noted in the module.) |
| `strings` | **Added** `StringBuilder` (`append` `append_char` `reserve` `length` `clear` `to_string`) and `last_index_of`. **Linear** `repeat`, `replace`, `join`, `substring`. `substring` and `StringBuilder.reserve` panic with the caller's location. Kept `strlen`, `byte_at_unchecked`. The seven libc bindings (`strstr`, `strcmp`, `strcpy`, `strcat`, `strncpy`, `toupper`, `tolower`) stay private. |
| `hashing` | Kept (`hash`). |
| `list` | **Removed** `list_sort`, `list_binary_search`, `list_find`. `pop` panics with the caller's location. |
| `stack` `queue` | `pop`/`peek`/`dequeue` panic with the caller's location. |
| `map` | **Renamed** `indexOf` → `index_of`, `tryGet` → `try_get`. **Added** `keys()`, `values()`. `get` panics with the caller's location. The four `bucket*` methods stay private (hash-index mechanics). |
| `set` | **Renamed** `indexOf` → `index_of`. `bucket*` private. |
| `io` | `write_string` is now `!void` (`FileError::WriteFailed(path)`). The stdio and `write`/`strlen` bindings stay private. |
| `fs` | `mkdir`, `remove_file`, `remove_dir` are now `!void` (`FsError`). The private `last_index_of_char` is replaced by the public `strings::last_index_of`. The `pub extern fn mkdir(path, mode)` overload (a custom-mode `mkdir`) is kept as it was. |
| `os` | `set_env` is now `!void` (`OsError::SetEnvFailed(name)`). |
| `sys` | Kept (`abort`, `exit`, `panic`, `STDERR_FD`). |
| `math` | Kept. |
| `time` | Kept, including the pre-existing `pub extern` `time`, `clock`, `usleep`. |
| `random` | `random_int` panics on `max < min`. |
| `mem` | Kept. `malloc_usable_size` / `usable_size` are glibc-only; flagged in FREEZE §6.20 as not a platform-independent promise. |
| `net` | **Added** `TcpConnection.raw_fd()` / `TcpListener.raw_fd()`. `close()` is **idempotent** on both. `buildSockAddr` stays private (returns raw memory). |
| `json` | **`escape_string` made public** and corrected (see below). `stringify_array`/`stringify_object` and the whole `Parser` stay private (`stringify`/`parse` are the interface). `JsonValue`'s fields stay public — there is no other way to read an element's value or enumerate an object's keys (see *Unresolved questions*). `get`/`at` panic with the caller's location. |
| `http` | `Server.listener` and `Server.routes` are **private**: storage, not something a program does anything with. `Request`'s fields and `Response.conn` stay public (a handler reads and writes them). `Request.get_header` and `Server.get_route` panic with the caller's location. `Server.route_index` stays private (`has_route`/`get_route` cover it). |
| `test` | Unchanged, including `assert_fail_eq/neq` (see above). `turf test` (REL-002) needs nothing more than `assert*`/`fail` and the exit-code convention the runner already uses. |

### Removals (R1)

`list::list_sort`, `list_binary_search`, `list_find`. `import list::list_sort;`
is now E030 (pinned by `fail_removed_list_sort.tr`). Migration: `l.sort(cmp)`,
`l.binary_search(x, cmp)`, `l.find(pred)`, which work for every element type.

### Behaviour changes worth knowing

- **`json::escape_string`** used to escape only `" \ \n \r \t` and emitted raw
  control bytes (invalid JSON under RFC 8259) for everything else. It now writes
  `\b \f` and `\u00XX` for every other byte below `0x20`, copies bytes `>= 0x80`
  through, and is linear. `stringify` uses it, so `stringify` output changes for
  such strings (it was invalid before). `parse` still cannot read `\u00XX` back.
- **`close()` is idempotent.** Previously `defer conn.close();` plus an early
  explicit `conn.close();` closed the same number twice; the kernel reuses the
  lowest free descriptor, so the second call could shut an unrelated socket or
  file. `tests/33_net_dns/03_close_is_idempotent.tr` makes that observable
  (a fresh connection provably takes the freed number).
- **Panic messages gain a `file:line: ` prefix** (they still contain the old
  text).

## Removed assumptions

- **"`bool` is enough for a failing file operation."** The old comment on
  `write_string` said so. It is not: the caller cannot tell which of several
  writes failed or why, and the read functions beside it already carried the
  path. The rule is now by *cause*, not by whether the result looks binary.
- **"A private field costs nothing."** LEC-002 made `Map.keys` private, which
  silently removed the ability to enumerate a map. Privatising storage needs the
  replacement operation to exist in the same change (`keys()`/`values()`).
- **"A test for 'no quadratic blow-up' can assert it by finishing."** It can
  only if the size is chosen so the old code *exceeds the per-test limit*. The
  old `repeat` loop took 1.9 s at 200,000 pieces — it passes a 5 s limit. At
  600,000 it takes 23 s. The test uses 600,000, and its header records both
  measurements.
- **"The second hop of an E079 chain is stable."** It is whichever fan-out branch
  is the 4097th request; removing three functions from `list.tr` flipped it.

## Known pitfalls

- **The dead-store lint reports a false positive on the natural way to consume
  a `!void`.** `mut failed = false; f() recover run { failed = true; };
  if failed {...}` warns "assigned but never read" on `failed`, because the
  analysis treats the `recover run` body as always executed and so thinks the
  initial `false` is overwritten. The pre-existing
  `25_errors/06_recover_run_void_success.tr` warns identically on the
  unchanged baseline. Not fixed (a lint/CFG change, outside this record). The
  migrated tests use `recover run { test::fail("...") }`, which has no flag. This
  matters more now that four stdlib functions return `!void`.
- **`turfc --resolve` writes an executable into the working directory** (named
  after the source file). I looped it over `showcase/*.tr` from the repo root
  and a following `git add -A` committed seven binaries; caught from the
  commit's file list, removed before anything was pushed. Compile into a
  scratch directory with `-o`.
- **The commit subject of `10ddf77` cites "F-STD-1"** for the naming rule. The
  frozen id is F-API-2.
- **A `RUNTIME_ABORT_EXPECTED` test that pins `file:line:` is brittle by
  design.** Insert a line above the call and the pin fails — that is the
  intent, but it makes the first failure look like a regression. Five of mine
  were first written with the wrong line (caught by the pin).
- **`Map.keys()`/`values()` after `remove()`** return swap-with-last order, not
  insertion order. Documented, and not part of the surface.
- **`io.tr`'s private libc declarations of `fclose`, `fseek`, `fflush`,
  `getchar`, `printf` and `scanf` use a 64-bit `int` return where C returns a
  32-bit `int`.** (`net.tr`, `fs.tr`, `random.tr` and `strings.tr` already
  declare theirs `int32`.) Harmless today — every result in `io.tr` is
  ignored — and invisible to users since the bindings are private. Recorded
  because it is exactly the `strcmp` bug documented in `strings.tr` and would
  bite the first time `io.tr` compared one, e.g. `getchar()` against `-1`.

## Unresolved questions

Each of these is a decision for the owner, none is made here.

1. **`JsonValue`'s fields stay public** (`kind`, `bool_val`, `num_val`,
   `str_val`, `arr_val`, `obj_keys`, `obj_vals`) because there is no other way to
   read a value's own content or list an object's keys. That freezes the
   representation for 2.x. The alternative is accessors (`as_number()`, `keys()`,
   `kind()`) and then making the fields private; I did not add a parallel API on
   my own.
2. **Two panics sit on input a remote peer controls**: `Request.get_header` on a
   missing header and `JsonValue.get` on a missing key. Each has a predicate
   (`has_header`, `has`), but a server that forgets to ask can be crashed by a
   client. A `try_` twin returning `!string` / `!JsonValue` would fit the rule;
   not added.
3. **Capability gaps a real program will meet, none addressed (roadmap: "no new
   modules")**: `random` reseeds from the clock on *every* call, so there is no
   seed and no reproducible sequence; `io` has whole-file read/write only — no
   append, no file handle, no reading one character; `fs` has no directory
   listing; `net` is TCP-only. These are the places a user will reach for a raw
   libc function, which the owner has ruled out exposing, so they are the
   argument for new Turf-level functions — `random::seed(n)`, `io::append_string`,
   a file handle type — in a later milestone. They belong in `FUTURE.md`.
4. **`os::env` returns `""` for an unset variable**, indistinguishable from one
   set to the empty string; `os::argv(i)` returns `""` out of range instead of
   panicking. Both predate this record and are consistent with "a question gets a
   sentinel", but an `os::has_env` would remove the ambiguity.
5. Whether to fix the dead-store false positive (above) in this milestone or
   with the next diagnostics work.
