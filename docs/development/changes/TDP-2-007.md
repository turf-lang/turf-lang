# TDP-2-007 — Analysis warnings for unsafe code, loops, recursion and leaks

The items of TDP-2-007 (`docs/planning/ROADMAP_v3.0.0.md`, AN-1 … AN-7, LB-5)
that ship in 2.3.0. Every check lands as a warning (the 5.4 ladder, rung 0)
with a registry code, `SinceMinor` 3, and starts at `allow`
(`ErrorCodeEntry::AllowByDefault`) while its false-positive record grows over
the 2.3 … 2.11 minors; B-1 decides promotions at 3.0.

---

## LB-5 — a method call through a raw-pointer receiver (issue #331)

**No change.** The roadmap and `pointers_and_references.md` §1.2 listed this as
a known gap. It is not one: a method call through a raw-pointer receiver has
been E130 outside `unsafe { }` since 2.0.0 (74ae2820, "a method call through a
raw pointer needs `unsafe`"), pinned by
`tests/05_arrays_pointers_ffi/fail_raw_pointer_method_call_outside_unsafe.tr`
and `26_raw_pointer_method_call_in_unsafe.tr`. B-13 (the 3.0 error) is
therefore already the 2.x behaviour. The stale note now states the rule.

## AN-7 — dead code (issue #334)

| Code | What | Fix |
|---|---|---|
| E178 | a private function or method nothing calls or names | — |
| E179 | an import nothing in its file uses | removes the line |
| E180 | a `pub` function in a program's root file that nothing calls | — |

`src/analysis/UnusedDecls.cpp`, run by the driver after the main
TypeChecker pass and by the query facade with `RunLint` (so a compiler fix's
re-check sees E179), only on a program with no error.

Uses are what resolution recorded: every candidate a call resolved against, its
final target, a function value (`ResolvedFunctionRef`), a method call's target,
and — inside a generic body, where a method call on a `T` is resolved only per
instantiation — the method's name. A declaration is quiet when it, or any
function of the same (module-qualifier-free) name, is used: an overload or a
same-named method elsewhere being used can hide a dead function, never report
a live one. `main`, operators, `@test` functions, `extern fn` and all of
lib/std are never reported; a module checked with `--module` has no E180.

An import is used when its file writes `m::`, names something the module
declares (`import m::Name`, a wildcard, a bare import's types), or calls a
function whose symbol came from `m` (a method of one of its types, UFCS). The
prelude is never reported.

### False-positive record (2.3.0)

Over every plain test, `showcase/` and `lib/std` with all three at `warn`:

- One false positive found and fixed before landing: `a.get()` inside
  `fn<T> call_get(a: T)` (`tests/38_monomorphization/operations_on_t_checked_per_instantiation.tr`)
  reported `V.get` as unused; method names called in a generic body now count.
- The remaining hits are true: functions a test declares on purpose and never
  calls (`dead` in `tests/14_cfg_analysis/4[5-8]_*`, `unused_*` in
  `generic_instantiation_only_in_signature.tr`, `add` beside the deprecated
  `add_old`), a test module's private helpers (`secret_twice`, `Shown.hidden`,
  `Shown.make_private`, the private `pick(string)` overload) that the
  visibility tests reach only from `fail_*` files, `import test` in
  `tests/57_test_functions/04_error_type_named_error.tr`, and the import that
  `entry_file_reimported_transitively.tr` exists to make. `showcase/` and
  `lib/std` have none.

## AN-6 — `int` to `double` precision loss (issue #353)

| Code | What | Fix |
|---|---|---|
| E181 | an `int` converted to `double` that may be outside +-2^53 | — |

Opt-in (F-22, Overhaul 10.5): it starts at `allow` and stays a warning. The
TypeChecker records every `int` expression that becomes a `double` in the
compilation's `AnalysisFacts` side table (`src/analysis/AnalysisFacts.h`,
keyed by node id): an explicit `x to double`, and an `int` stored into,
passed as or returned as a `double`. The value-range walk
(`src/analysis/ValueRange.cpp`) warns at each one whose value it cannot prove
within +-2^53 (the interval analysis of NM-2, TDP-2-002). A constant within range, an integer literal, an enum's `COUNT`
and a converted `double` literal (`(9.9 to int) to double`) are proven.
Nothing is recorded or checked when E181 is at `allow`.

### False-positive record (2.3.0)

Over every plain test, `showcase/`, `examples/` and `lib/std` with E181 at
`warn`:

- Two hits had no source location and were not true: `Color::COUNT to double`
  and `(9.9 to int) to double`. Both shapes are now proven and pinned by
  `tests/36_numeric_semantics/int_to_double_precision_warns.tr`.
- Two hits remain, both true by the check's definition: a value no range
  bounds converted to `double` (`mask | 1` in
  `tests/01_syntax/15_pratt_cast_binds_tighter_than_comparison.tr`, a
  parameter in `25_errors/24_try_passes_error_unchanged.tr`). Loop counters
  converted inside their loop are bounded by the loop's test (NM-2's ranges,
  TDP-2-002) and do not warn. `showcase/`, `examples/` and `lib/std` have
  none.

## AN-3 (a) — mutual recursion with no base case (issue #332)

| Code | What | Fix |
|---|---|---|
| E182 | functions that call each other on every path | — |

E010 reports one function whose every path calls itself; E182 is the same
rule over the call graph. `src/analysis/MutualRecursion.cpp` builds the graph
from each function's CFG (`CFG::calledFunctions`, resolved calls only, so a
call through a function value is no edge), finds its strongly connected
components (Tarjan) and warns once per component of two or more functions in
which every function's every path passes through a call into the component
(`CFG::allPathsCallAnyOf`). The warning sits on the first function in source
order and names every member; the others are related locations. A cycle whose
first function is in lib/std is never reported.

### False-positive record (2.3.0)

Over every plain test, `showcase/`, `examples/` and `lib/std` with E182 at
`warn`: no hit outside `tests/14_cfg_analysis/mutual_recursion_warns.tr`.

## AN-3 (b) — a recursive base case proven unreachable (issue #333)

| Code | What | Fix |
|---|---|---|
| E183 | a recursive function's base case that the values reaching it rule out | — |

The value-range analysis of NM-2 (`src/analysis/ValueRange.cpp`, TDP-2-002)
proves some CFG edges are never taken: a test whose narrowed range is empty,
from a constant, a range `for`'s bounds or a condition earlier on the path.
When a function is not E010 (it has a path that returns without calling
itself) but every path calls itself once those edges are removed
(`CFG::allPathsRecurseWithout`), E183 is reported at each dead edge leading
into a block from which the exit is reachable without a self call
(`CFG::blocksReachingExitWithoutSelfCall`): the base case that can never run.
A constant `if false` is not a dead edge here (E030 covers it). lib/std is
never reported.

### False-positive record (2.3.0)

Over every plain test, `showcase/`, `examples/` and `lib/std` with E183 at
`warn`: no hit outside `tests/14_cfg_analysis/unreachable_base_case_warns.tr`.

## AN-2 — loops that never end (issue #350)

| Code | What | Fix |
|---|---|---|
| E184 | a `while`/`do while` whose test reads only variables nothing in the loop writes, the test being its only way out | — |
| E185 | a loop whose every way out is an edge the value ranges prove is never taken | — |
| E186 | a loop whose every way out that can be taken comes after `sys::panic`, `sys::abort` or `sys::exit` | — |

Warnings in every version: termination is undecidable, so there is no
promotion. `reportEndlessLoops()` in `src/analysis/ValueRange.cpp` finds the
natural loops of the CFG (one per head of a depth-first back edge), their exit
edges, and reads NM-2's ranges (`RangeSolution::DeadEdges`). A loop with no
exit at all is E157's and `hasUnbreakableLoop()`'s. A loop containing `?`
(an early return the CFG does not draw) is never reported, and E184 and E185
skip a loop that calls one of the three functions above (ending the program
may be its way out).

E184 counts a variable as written by any whole-statement write in the loop
(assignment, `op=`, `++`/`--`, a range `for`'s `step`) and treats a variable
whose address is taken (`&x`), that a closure captures or that is written
anywhere but a whole statement as written everywhere (OPT-002's trackability
rule). A test containing a call, a method call, a field or an index is never
reported. A break or `return` the loop can take, or a body the ranges prove
never runs, keeps it quiet. A `break` block lies outside its natural loop, so
E186 looks for the call both in the block a loop leaves from and in a
single-entry `break`/`return` block it leaves to.

The trackability scan reads a bare variable that is a whole statement (`while
go`, a test the CFG holds as a statement) as a read.

### False-positive record (2.3.0)

Over every plain test, `showcase/`, `examples/` and `lib/std` with E184, E185
and E186 at `warn`: no hit outside `tests/14_cfg_analysis/endless_loops_warn.tr`.

## AN-5 — manual-heap memory that is never freed (issue #352)

| Code | What | Fix |
|---|---|---|
| E187 | memory from an `@ownership(acquires)` call that nothing frees and nothing lets out | — |

`reportLeaks()` in `src/analysis/AliasAnalysis.cpp`, run at the end of
`AliasAnalysisPass::runOnCFG` (the double-free / use-after-free pass, whose
`@ownership` reading it shares). It is flow-insensitive and conservative.
Variables assigned to one another form a group. An allocation held by a
group is freed when any releasing call in the function releases a variable
of the group, a `defer` included. It escapes when a variable of the group is
used anywhere except:

- as an index or field base;
- as an operand of `==` or `!=`;
- as the argument a releasing call frees;
- as an argument to a `mem` function that keeps nothing (`zero`,
  `usable_size`, `memcpy`, `memmove`, `memset`, `memcmp`);
- as the target of an assignment.

Storing the pointer in a field or an array, passing it to any other call
(`mem::root`, `Pool.track`, `mem::grow`, an `extern`), converting it and
capturing it in a closure are all escapes. An acquiring call whose result is
thrown away (a statement on its own) is a leak at that call. A `return` of
the pointer is a use like any other, so an escape. lib/std is never
reported.

### False-positive record (2.3.0)

Over every plain test, `showcase/`, `examples/` and `lib/std` with E187 at
`warn`: no hit outside `tests/05_arrays_pointers_ffi/manual_heap_leak_warns.tr`.
