TURF-LANG GENERAL REFERENCE (the syntax card above shows the basic forms)

TYPES:
  int (64-bit)   double   bool   char ('a')   string   void (return type only)
  int32 (storage type: arithmetic on it gives int, convert back with `to int32`)
  T[N] fixed array, T[] array parameter, T* raw pointer and ptr (only inside
  `unsafe { }`), &T reference, &?T reference that may be null, List<T>, Map<K, V>.
  Literals: 42  3.14  true  false  'a'  "text\n" (\n \t \r \\ \")  null (pointers
  and references only).

DECLARATIONS AND ASSIGNMENT:
  `mut name: Type = value;` can be reassigned, `immut name: Type = value;` cannot
  (an immut needs its value where it is declared). `mut x: int;` with the value
  assigned later is allowed, as long as every path assigns before the read.
  `mut x: guess = 5;` infers the type from the value.
  Reassign with the name only: `x = 10;  x += 5;  x++;`. Never repeat `mut`/`immut`
  or the type: that is "already created a variable".
  Operators: + - * / %  ** (always a double)  == != < > <= >=  && || !  & | ^ ~ << >>

CASTS: postfix `expr to Type`, never `Type(expr)`.
  `3.9 to int` (drops the fraction)  `7 to double`  `42 to string`  `65 to char`
  `'a' to int`  `"99" to int` (parsed at run time)  `1 to Color` (a valid variant
  number)  Not allowed: to bool. Test a number with `n != 0`.
  string + string joins; any other type needs `x to string` first, and `to`
  binds looser than `+`, so parenthesize it: `"n=" + (n to string)`.

CORRECT:
    import io;

    enum Color { Red, Green, Blue }

    fn main(): int {
        mut n: int = 7;
        mut d: double = n to double;
        mut flag: bool = n != 0;
        mut label: string = "n=" + (n to string);
        mut total: int = 0;
        for i in 0..3 {                      // `step i += 1` is optional
            total = total + i;
        }
        mut nums: int[3] = [1, 2, 3];
        for v in nums {                      // also: for (index, v) in nums
            total = total + v;
        }
        while total > 100 {
            total = total - 1;
        }
        mut c: Color = Color::Green;
        compare c {                          // an enum needs every variant, or otherwise:
            matches Color::Red:
                total = 1;
            done                             // every matches ends with done
            otherwise:                       // otherwise is last and has no done
                total = 2;
        }
        io::printline(label);
        return total - 4;
    }

CONTROL FLOW:
  `if c { } elseif c { } else { }` braces always; `else if` also works. A one-line
  choice is `cond give a otherwise b`. `do { } while cond;`. `break`, `continue`.
  A `for` with a range uses ONE variable; `step` takes an assignment (`i += 2`).

FUNCTIONS: `fn name(a: int, b: int): int { return a + b; }` -- the return type
  follows `:` and is required (`: void` for none). A function returning a value
  returns on every path. `fn<T> first(a: T, b: T): T` is generic; the type is
  inferred at the call, never written (`first<int>(1, 2)` is a parse error).

STRUCTS AND ENUMS:
  `struct Point { x: int, y: int }`. There is no brace literal: build with
  `Point::default()` (all fields zero) or `Point::new(1, 2)` when `fn Point.new`
  is declared (it assigns every field through `self`). Methods are declared
  outside the struct, `fn Point.sum(): int { return self.x + self.y; }`, and
  called `p.sum()`. A struct cannot be compared with `==`: compare its fields.
  `enum Color { Red, Green }`; a variant is `Color::Red`.

MODULES: `import io;` then `io::printline("hi");` -- `::` for modules, enum
  variants and static methods, `.` only on a value. `int`, `double`, `bool`,
  `char`, `strings` and `array` are imported for you (`s.length()`, `a.length()`);
  every other module (`io`, `math`, `mem`, `sys`, `test`, `list`, `map`, ...) needs
  its own `import` in every file that uses it. See modules.txt.

BUILT IN: `typeof(x)` (the type's name) and `sizeof(Type)` need no import.

MEMORY: `mem::malloc(n)`, `mem::realloc(p, n)`, `mem::free(p)`, only inside
  `unsafe { }`. Using a pointer after `free`, or freeing it twice, is rejected
  at compile time.

TESTS AND EXIT: `test::assert(cond, "message")`, `test::assert_eq(a, b)` after
  `import test;`. `sys::exit(code)` and `sys::panic("message")` after `import sys;`.

COMMON MISTAKES:
- A declaration without `mut`/`immut`, or the type before the name.
- Function-style casts (`int(x)`), or `x.to_string()`: write `x to string`.
- A C-style `for (int i = 0; ...)`.
- Comparing structs with `==`, or an enum with `==` where a `compare` fits.
- Mixing string and numbers in `+` without `to string`.
- Assigning to an `immut`, directly or through a method that changes `self`.
- Calling a module function without `import`, or with `.` instead of `::`.
