TURF-LANG GENERAL REFERENCE
============================

NOTE ON SEMICOLONS:
  Semicolons are REQUIRED after every statement. `mut x: int = 5` (no
  semicolon) is a syntax error: "Expected ';' after statement."

---

TYPES:
  int      64-bit signed integer
  double   64-bit floating point
  bool     boolean: true or false
  string   string
  void     ONLY allowed as a function return type, never as a variable type
  ptr      opaque pointer (FFI); any T* is a typed pointer to T

---

LITERALS:
  42          integer
  3.14        double
  true        bool
  false       bool
  "hello\n"   string (escape sequences: \n \t \\ \")
  null        the null pointer literal

---

VARIABLES:
  Every declaration starts with `mut` (reassignable) or `immut`
  (write-once), then `name: Type = value`. The type annotation comes AFTER
  the name, separated by a colon. A value is required at declaration time.

    mut x: int = 5;
    immut pi: double = 3.14;
    mut flag: bool = false;
    mut msg: string = "hi";

  REASSIGNMENT (name only, no `mut`/`immut`, no type):
    x = 10;
    x += 5;
    x -= 2;
    x *= 3;
    x /= 2;
    x %= 4;
    x++;
    x--;
    ++x;
    --x;

  Reassigning an `immut` variable is a compile error ("Oops! You can't
  change the value of 'x' because it's immutable."), including indirectly
  through a struct method that mutates one of its own fields.

---

ARRAYS:
  mut name: Type[SIZE] = [v1, v2, v3];

    mut nums: int[5] = [1, 2, 3, 4, 5];
    immut primes: int[3] = [2, 3, 5];

  ACCESS:
    primes[0]                // read element (zero-indexed)
    primes[0] = 7;            // write element
    primes[0] += 1;           // compound assignment on an element IS supported

  LENGTH: a method call, not a property.
    mut n: int = primes.length();

  RULES:
  - SIZE must be a positive integer literal.
  - The initializer list's length must exactly match the declared SIZE.
  - Every element's type must match the declared element type (or be a
    compatible numeric promotion) -- e.g. `int[3] = [1, "two", 3]` is
    rejected at compile time.

---

OPERATORS:
  Arithmetic:  +  -  *  /  %  ** (exponentiation -- result is ALWAYS
                                 double, even for two int operands, e.g.
                                 `2 ** 3` is 8.0, not 8)
  Relational:  ==  !=  <  >  <=  >=
  Logical:     &&  ||  !  (prefix ! desugars to `expr != true`)
  Bitwise:     ~ (not)  &  |  ^ (XOR)  <<  >>
  Unary:       - (negate)  ~ (bitwise not)
  Assignment:  =  +=  -=  *=  /=  %=
  Increment:   x++  x--  ++x  --x
  Scope:       :: (enum variant access, e.g. Color::Red)

  TYPE PROMOTION IN EXPRESSIONS:
    bool -> int -> double (promoted automatically in expressions)
    string cannot be combined with any other type in arithmetic --
    concatenate with `<expr> to string` first.

---

TYPE CASTING (explicit, POSTFIX -- `expr to Type`, not `Type(expr)`):
    3.14 to int        // 3 (truncates)
    10 to double        // 10.0
    42 to string        // "42"
    true to string       // "true"
    "99" to int          // 99 (runtime parse of string)
    99 to Color          // cast an int to an enum type -- the value must be
                         // a valid variant index, or it's rejected at
                         // compile time when it's a literal

---

CONTROL FLOW:

  IF: block form only. There is no single-line `then`/`else` form -- use
  the `give ... otherwise ...` ternary (below) for a single-expression
  conditional instead.

    if <cond> {
        ...
    } elseif <cond> {
        ...
    } else {
        ...
    }
    // Parentheses around <cond> are optional.
    // `elseif` is ONE word -- `else if` (two words) is a parse error.

  TERNARY (single expression, no blocks):
    <condition> give <then_value> otherwise <else_value>

    mut y: int = x > 0 give 1 otherwise 0;

  WHILE LOOP:
    while <cond> {
        ...
    }

  FOR LOOP:
    for <var> in <start>..<end> step <step_expr> {
        ...
    }
    // <step_expr> is an ASSIGNMENT EXPRESSION executed after each
    // iteration (e.g. `i += 1`, not a bare number). The loop variable is
    // automatically declared as int or double based on <start>/<end>.
    // IMPORTANT: nothing forces <step_expr> to touch the loop variable --
    // if it never does (typo, or it updates a different variable by
    // mistake), the loop runs forever or not at all. The compiler warns
    // about this ("the loop variable is never changed by this loop's
    // 'step' or its body") but it does not stop compilation.
    EXAMPLE:
      for i in 0..10 step i += 1 { }
      for i in 10..0 step i -= 2 { }

  BREAK / CONTINUE:
    break     // exits innermost loop
    continue  // skips to the step expression of innermost loop

---

FUNCTIONS:
  fn name(param: Type, param2: Type, ...): ReturnType {
      return value;
  }

  The return type comes AFTER the parameter list, separated by a colon --
  the opposite order from the parameters themselves.

    fn add(a: int, b: int): int {
        return a + b;
    }

    fn greet(name: string): void {
        io.printline(name);
    }

  RULES:
  - Return type is required: int, double, bool, string, void, a struct/enum
    name, a pointer type, or an array type.
  - Non-void functions must return a value on every code path.
  - void functions may use a bare `return;` or omit it.
  - void is not a valid parameter type.
  - Functions can be called before they are defined (pre-pass hoisting).
  - `fn<T> name(x: T): T { ... }` declares a generic function; T is erased
    to a 64-bit slot at codegen time (works uniformly for int/double/bool/
    pointers).

---

STRUCTS:
    struct Point {
        x: int,
        y: int
    }

  Construct with a struct literal (field names required, any order):
    mut p: Point = Point { x: 1, y: 2 };
    p.x = 5;                 // field access/assignment via '.'

  Methods are declared OUTSIDE the struct body, qualified by struct name:
    fn Point.sum(): int {
        return self.x + self.y;   // 'self' is the implicit receiver
    }
    p.sum();                  // call via '.', same as a field access

  A method can mutate and return `self` (as a pointer) to support chaining:
    fn Counter.increment(): Counter* {
        self.val = self.val + 1;
        return self;
    }
    c.increment().increment();   // chained calls

  Struct (and enum) names live in ONE flat namespace shared by the current
  file and every imported module -- unlike functions, they are NOT
  namespaced per-module, so `List<int>` works without a `list.` prefix.
  Two different modules declaring a same-named struct is a compile error.

  Generic structs: `struct Box<T> { val: T }`, instantiated as `Box<int>`.

  Struct instances do NOT support `==`/`!=` comparison -- compare the
  fields you care about individually instead (`a.x == b.x`).

---

ENUMS:
    enum Color { Red, Green, Blue }

  Access a variant with `::` (also used nowhere else in the language today):
    immut c: Color = Color::Red;

  Compare with a `compare` block, not `if`/`==`:
    compare c {
        matches Color::Red:
            ...
        done
        matches Color::Green:
            ...
        done
        otherwise:
            ...
    }
  Every `matches` arm's body ends with `done`. `otherwise:` (optional) must
  be the LAST arm and has no `done`. Omitting a variant without an
  `otherwise:` arm is a compile error ("Non-exhaustive enum comparison").
  Casting an out-of-range integer LITERAL to an enum type is rejected at
  compile time (e.g. `99 to Color` when Color only has 3 variants).

---

MODULES / IMPORTS:
  import io;
  import list;
  import mem;

  Call a module's function qualified by module name:
    io.printline("hi");
    mem.malloc(64);

  Several stdlib functions (print, printline, input, assert, lengthof,
  typeof, sizeof) also work unqualified, without an explicit `io.`/module
  prefix, since they're resolved through the module search path
  automatically when there's no ambiguity.

---

BUILTIN / INTRINSIC FUNCTIONS (no import needed):

  print(expr) / printline(expr)
    Print expr (no newline / with newline). Accepts int, double, bool, string.

  input()
    Reads a line from stdin. Returns: string.

  lengthof(str)
    Number of characters in a STRING. Returns: int.
    For arrays, use `.length()` (a method call) instead.

  typeof(expr)
    Compile-time type name as a string, e.g. "int", "double", "Point".

  sizeof(Type)
    Size in bytes of a type (FFI/memory use).

  assert(condition, message)
    Aborts at runtime with `message` if `condition` is false.

---

MEMORY (via `import mem;`, manual, no garbage collector):
  mem.malloc(size)              -- allocate size bytes, returns a raw pointer
  mem.realloc(ptr, newSize)     -- resize a previous allocation
  mem.free(ptr)                 -- release memory
  Using a pointer after free(), or calling free() twice on the same pointer,
  is a compile-time-detected bug where the compiler can prove it (dataflow
  analysis, not a runtime check).

---

COMMON PITFALLS:
- Forgetting `mut`/`immut` before a variable name, or putting the type
  before the name instead of after the colon.
- Using `else if` (space) instead of `elseif` (one keyword).
- Using C-style for loops: `for (int i = 0; ...)` does not exist in Turf.
- Forgetting `step <expr>` in a for loop (step is required), or writing a
  step that never actually updates the loop variable (infinite loop).
- Using function-call-style casts (`int(x)`) instead of postfix `x to int`.
- Calling `lengthof()` on an array instead of using `.length()`.
- Mixing string and numeric types in arithmetic without an explicit
  `to string` cast.
- Comparing two struct instances with `==` (not supported -- compare fields).
- Comparing an enum value with `==` instead of a `compare`/`matches` block.
- Reassigning an `immut` variable, directly or through a mutating method.
