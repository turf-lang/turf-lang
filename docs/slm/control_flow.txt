TURF CONTROL FLOW:

NOTE ON SEMICOLONS:
- Semicolons are REQUIRED after every statement, not optional.

IF STATEMENT: block form only -- there is NO single-line `then`/`else` form.
  Syntax: if <condition> { <body> } elseif <condition> { <body> } else { <body> }
  The condition can optionally be wrapped in parentheses.

  CORRECT EXAMPLES:
    if x > 0 {
        io::printline(x to string);
    } elseif x < 0 {
        io::printline((-x) to string);
    } else {
        io::printline("0");
    }

    if (score >= 90) {    // parentheses around condition are optional
        io::printline("A");
    }

  RULES:
  - `elseif` is one keyword (no space). `else if` (with a space) also works: it
    is an `else` whose body is an `if`.
  - `else` branch is optional.
  - There is no `then` keyword at all in this language.

  For a single EXPRESSION conditional (no blocks/statements), use the
  `give ... otherwise ...` ternary instead of `if`:
    mut y: int = x > 0 give 1 otherwise 0;

WHILE LOOP:
  Syntax: while <condition> { <body> }

  CORRECT EXAMPLES:
    while x < 10 {
        x++;
    }

    while (running) {    // parentheses around condition are optional
        x += 1;
    }

BREAK AND CONTINUE:
  - `break` exits the innermost loop immediately.
  - `continue` skips to the step/condition of the innermost loop.
  - Both are a compile error ("Control flow error! 'break'/'continue' used
    outside of a loop") if used outside a loop body -- even if a function
    containing one is never actually called.

  CORRECT EXAMPLE:
    while true {
        if x > 5 {
            break;
        }
        x++;
    }

FOR LOOP:
  Syntax: for <var> in <start>..<end> [step <step_expr>] { <body> }
  `step` is optional: `for i in 0..10 { }` counts up by one.

  IMPORTANT: the `step` clause is an arbitrary EXPRESSION executed after
  each iteration, most commonly an assignment (i += 1). It does NOT have
  to modify the loop variable -- the compiler will happily accept
  `step 1` or `step someOtherVar += 1` syntactically. If `step` (and
  nothing in the body either) ever actually changes the loop variable, the
  compiler emits a WARNING ("the loop variable is never changed by this
  loop's 'step' or its body, so it will loop forever" / "...the body will
  never execute even once") but still compiles the code -- this is not a
  hard error, so don't assume a stuck loop is impossible just because
  compilation succeeded.

  The loop variable `<var>` is automatically declared as int or double
  based on the type of <start>/<end>.

  CORRECT EXAMPLES:
    for i in 0..10 step i += 1 {
        io::printline(i to string);
    }

    for i in 10..0 step i -= 1 {
        io::printline(i to string);
    }

    immut factor: int = 2;
    for i in 1..100 step i *= factor {
        io::printline(i to string);
    }

  INCORRECT EXAMPLES:
    for i in 0..10 step 1 { }        // compiles, but WARNS: i never advances
    for i in 0 to 10 step i += 1 { } // ERROR: use '..' for the range, not
                                     // 'to' (that's the cast keyword)
    for (i = 0; i < 10; i++) { }     // ERROR: C-style for loops do not exist

COMMON MISTAKES:
- Trying to use a `then`/single-line `if` form -- it doesn't exist; use
  `give ... otherwise ...` instead.
- Writing a `step` (or body) that never actually updates the loop variable
  -- syntactically valid, but produces a real infinite loop at runtime; the
  compiler only warns, it doesn't refuse to compile.
- Using `..` in the wrong place, or `to` (the cast keyword) instead of `..`
  in a for-loop range.
- Using `do { } while` or C-style `for(;;)` -- these do not exist in Turf.
