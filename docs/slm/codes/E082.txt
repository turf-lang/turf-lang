TURF E082 -- UNNARROWED NULLABLE CAST:

CAUSE:
  `x to &T` converts a maybe-null `&?T` into a definitely-non-null `&T`. That
  is a promise the value is not null, and the compiler accepts it only where
  it can see the promise kept (inside a `!= null` check). `x to T` (copying
  the value out of the `&?T`) reads through it and needs the same check.

INCORRECT:
    struct Box { val: int }

    fn bad(b: &?Box): int {
        mut safe: &Box = b to &Box;      // b might be null
        return safe.val;
    }

CORRECT:
    struct Box { val: int }

    fn good(b: &?Box): int {
        if b != null {
            mut safe: &Box = b to &Box;  // proven non-null here
            return safe.val;
        }
        return 0;
    }

FIX:
  Do the `to &T` inside an `if x != null { ... }`. Often the conversion is not
  needed at all: inside the check, `b` can be used directly. Only a VARIABLE
  can be checked: if the operand is a field, a call result or a list element
  (`h.item to &Box`), first `mut b: &?Box = h.item;`, then check and cast `b`.

RELATED: E081 (reading a field of a `&?T` without the check).
