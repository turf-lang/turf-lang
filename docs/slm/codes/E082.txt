TURF E082 -- UNNARROWED NULLABLE CAST:

CAUSE:
  `x to &T` converts a maybe-null `&?T` into a definitely-non-null `&T`. That
  is a promise the value is not null, and the compiler accepts it only where
  it can see the promise kept (inside a `!= null` check). `x to T` (copying
  the value out of the `&?T`) reads through it and needs the same check.

INCORRECT:
    struct Box { val: int }

    fn bad(b: &?Box): int {
        mut safe: &Box = b to &Box;      // b might be null
        return safe.val;
    }

CORRECT:
    struct Box { val: int }

    fn good(b: &?Box): int {
        if b != null {
            mut safe: &Box = b to &Box;  // proven non-null here
            return safe.val;
        }
        return 0;
    }

FIX:
  Do the `to &T` inside an `if x != null { ... }`. Often the conversion is not
  needed at all: inside the check, `b` can be used directly and passed,
  returned or stored as a `&Box` as it is. The same error is reported for a
  `&?T` used as a `&T` with no check (`return b;`, `f(b)`). A variable or a
  field reached from one (`h.item`) can be checked; a check on a field lasts
  until the next call or the next write to a field with that name. A call
  result or a list element is stored in a variable first, then checked.

RELATED: E081 (reading a field of a `&?T` without the check).
