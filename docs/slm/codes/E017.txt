TURF E017 -- DOUBLE FREE:

CAUSE:
  A raw pointer was passed to `mem::free(...)` more than once. Once memory
  is freed, that allocation is gone -- freeing the same pointer a second
  time corrupts the allocator's internal bookkeeping (the classic "double
  free" bug family in any manually-managed-memory language). Turf's alias
  analysis tracks this statically and rejects it at compile time instead of
  letting it become a runtime crash or, worse, silent memory corruption.

CORRECT USAGE:
    unsafe {
        mut buf: int* = mem::malloc(40);
        // ... use buf ...
        mem::free(buf);
        buf = null;   // good practice: nothing left to accidentally free again
    }

INCORRECT:
    unsafe {
        mut buf: int* = mem::malloc(40);
        mem::free(buf);
        mem::free(buf);   // ERROR: Double free detected for 'buf'.
    }

WHAT THIS ERROR IS NOT:
  - Not about USING memory after it's freed (reading/writing through the
    pointer) -- that's UseAfterFreeError (E018), the closely related sibling
    check.

FIX:
  Free each pointer exactly once. If a pointer might legitimately need to
  be freed from more than one code path (e.g. an early-return branch and
  the normal end-of-function cleanup), restructure so only one of those
  paths actually runs for a given pointer -- or set the pointer to `null`
  immediately after freeing it as a defensive habit.
