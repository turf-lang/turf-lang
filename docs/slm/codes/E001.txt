TURF E001 -- ARRAY BOUNDS:

CAUSE:
  A LITERAL (compile-time-constant) array index was used that falls
  outside the array's declared size. Turf arrays are zero-indexed and
  fixed-size, and a negative index counts back from the end (Python-style),
  so `arr[N]` is only valid for `-SIZE <= N < SIZE`.

  This check only fires for an index the compiler can prove constant at
  compile time (`arr[5]`, `arr[-4]`). A computed index (`arr[i]`) that is
  out of bounds is not a compile-time error; it panics at run time instead.

CORRECT USAGE:
    immut primes: int[3] = [2, 3, 5];
    mut first: int = primes[0];    // valid: index 0
    mut last: int = primes[2];     // valid: index 2 (SIZE - 1)
    mut also_last: int = primes[-1];  // valid: -1 is the last element
    mut also_first: int = primes[-3]; // valid: -SIZE is the first element

INCORRECT:
    mut oops: int = primes[3];
    // ERROR: Array index out of bounds! You tried to access
    //   'primes[3]', but 'primes' only has 3 elements (indices 0 to 2, or
    //   -1 to -3 counting from the end).
    mut oops2: int = primes[-4];   // same error: below -SIZE

FIX:
  Recount from 0: the last valid index is always `SIZE - 1` (or `-1`),
  never `SIZE`, and the first is `0` (or `-SIZE`). If the array genuinely
  needs to hold more elements, increase
  its declared size (`int[3]` -> `int[4]`) and add the missing
  initializer, rather than indexing past the end of the current one.
