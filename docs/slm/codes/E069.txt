TURF E069 -- STRUCT LAYOUT CYCLE:

CAUSE:
  A struct contains itself BY VALUE, either directly or through a chain of
  other structs/arrays/generic instantiations. This makes the type's size
  uncomputable (size(A) depends on size(A), with no base case), so the
  declaration is rejected before any layout, default value, or GC
  descriptor is ever computed for it.

  Two shapes trigger this:
  1. Direct: `struct A { me: A }`.
  2. Mutual/chain: `struct A { b: B } struct B { a: A }` -- neither struct
     is self-referential individually, but the cycle closes across both.
     An array field (`bs: B[2]`) counts the same as a plain `B` field,
     since an array's size is element-size * length. A generic struct's
     OWN field referencing its own base name (`struct Box<T> { inner:
     Box<T> }`) is a cycle regardless of what T is instantiated to.

  The diagnostic names the full cycle explicitly (`cycle: A -> B -> A`)
  with one note per field that forms it, so the fix target is unambiguous
  even for a long chain.

WHAT IS NOT AN EDGE (does NOT trigger this error):
  - A reference field: `&T` (non-null reference), `&?T` (nullable
    reference). Both are a fixed one-word size regardless of what they
    point to, which is exactly why they are the correct way to write a
    real recursive data structure (linked list, tree, etc.). A raw `T*`
    breaks the cycle too, but a raw pointer outside `unsafe` is its own
    error (E130), so a struct field is written `&?T`, not `T*`.
  - `string` and any other type that is itself pointer-shaped.

CORRECT (a reference breaks the cycle):
    struct Node {
        value: int,
        next: &?Node    // fixed size -- always legal, and may be null
    }

INCORRECT (rejected):
    struct A { me: A }
    // ERROR: struct 'A' cannot contain itself by value [E069]
    //   cycle: A -> A
    //   Note: field 'A::me' has type 'A' (line N, col N)

    struct A { b: B }
    struct B { a: A }
    // ERROR: struct 'A' cannot contain itself by value [E069]
    //   cycle: A -> B -> A
    //   Note: field 'A::b' has type 'B' (line N, col N)
    //   Note: field 'B::a' has type 'A' (line N, col N)

WHAT THIS ERROR IS NOT:
  - Not about reference fields at all -- `next: &?Node` is the
    INTENDED, unaffected way to write self-referential data. Do not "fix"
    this error by making default-value construction depth-limited or by
    special-casing the pointee's initialization; the cycle in the TYPE
    itself is the actual bug being reported.
  - Not a runtime check -- this is a purely static, declaration-time
    property (the Resolver's containment-graph check, run once every
    struct name is registered, before any layout is computed).

FIX:
  Change exactly ONE field anywhere in the reported cycle from holding the
  struct by value to holding a reference to it (`&T`, or `&?T` when it may
  be null) -- whichever fits how that field is read/written elsewhere. The
  rest of the cycle's fields do not need to change.
