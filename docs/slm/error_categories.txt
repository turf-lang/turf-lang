TURF-LANG ERROR CATEGORIES REFERENCE

Use this file to classify a compiler error into exactly one category.
Choose the most specific category that matches, or GENERAL if none fit.

---

TYPE_MISMATCH
  A value of one type is used where a different, incompatible type is
  expected.
  Examples:
    - Assigning a double to an int variable without `... to int`
    - Assigning a string to an int or double variable
    - Mixing incompatible types in an arithmetic expression
    - Comparing two struct instances with == / !=
    - Casting an out-of-range integer literal to an enum type
    - A struct method call whose argument TYPES don't match its parameters
      (not just the argument count)

UNDECLARED_VARIABLE
  A name is used but was never declared (or isn't visible) in this scope.
  Examples:
    - Using a variable before declaring it with `mut`/`immut`
    - Using a variable outside the block (or loop) where it was declared
    - Misspelling a variable, function, or struct-method name
    - Calling a method that doesn't exist on a struct

CONTROL_FLOW
  An error in the structure of if/elseif/else, while, for, break, continue,
  or compare/matches.
  Examples:
    - Missing '..' or 'step' in a for loop
    - Using 'break' or 'continue' outside a loop
    - Missing '{' after an if/elseif/else/while condition
    - Using 'else if' (with space) instead of 'elseif'
    - Function that doesn't return on all code paths (MissingReturnError)
    - Non-exhaustive enum `compare` (missing a variant and no `otherwise:`)
    - Duplicate or misplaced `otherwise:` arm in a `compare` block
    - Duplicate `matches` pattern in a `compare` block

SYNTAX_ERROR
  A general structural or token-level parse error.
  Examples:
    - Unexpected token when starting an expression
    - Misspelled keyword recognized by the compiler (KeywordError)
    - Unterminated string literal
    - Missing closing parenthesis, bracket, or brace
    - Missing ':' between a name and its type, or ';' after a statement

ARITHMETIC
  An operator is used with incompatible numeric types.
  Examples:
    - Using an unsupported/nonexistent operator
    - Applying an arithmetic operator to incompatible types

STRING_CONVERSION
  An illegal type conversion involving strings.
  Examples:
    - Trying to add a string and a number using + (without `to string` first)
    - Passing a non-string to lengthof()
    - Casting an unsupported type `to string`

ARRAY_ERROR
  An error during array declaration, access, or initialization.
  Examples:
    - Array index out of bounds (compile-time literal check)
    - Array size mismatch with the initializer list
    - Using a non-integer index
    - Array element type mismatch against the declared element type

DECLARATION
  A name is declared a second time where it shouldn't be, or an unknown
  type name is referenced.
  Examples:
    - Redeclaring a variable (with `mut`/`immut`) that already exists in
      this exact scope
    - Shadowing a variable from an outer scope (this is a WARNING, not an
      error)
    - Duplicate struct field name, duplicate enum variant name, or
      duplicate function parameter name
    - Two different modules (or a file and an imported module) declaring a
      same-named struct or enum -- these share one flat namespace
    - Referencing an unknown/misspelled type name in a variable
      declaration, struct field, function signature, or generic type
      argument (e.g. `List<NoSuchType>`)
    - Reassigning an `immut` variable, directly or through a mutating
      struct method
    - `import`ing a module that doesn't exist, or `import module::symbol;`
      naming a symbol that module doesn't export
    - A circular import chain (module A imports B imports ... imports A)
    - Two on-demand imports (`import module::[...];`) flattening two
      DIFFERENT symbols under the same bare name
    - `Left::Right` where `Left` isn't a known enum or a known (imported)
      module (see modules.txt for `::`'s full scope)

FUNCTION_SIGNATURE
  An error in a function definition, call, parameters, or return type.
  Examples:
    - Wrong number of arguments in a function or struct-method call
    - Return type of a function doesn't match its declared return type
    - Using a void function's result as a value in an expression

BUILTIN_FUNCTION
  An error specific to one of the FEW true compiler intrinsics -- typeof,
  lengthof, assert, fail, sizeof. These never require an import and are
  not declared in any .tr file. print/printline/input, and everything in
  mem/math/list/strings/etc., are standard library code (lib/std/*.tr),
  NOT intrinsics -- an error calling one of those belongs in whatever
  category the error itself is about (UNDECLARED_VARIABLE for an unknown
  name, FUNCTION_SIGNATURE for wrong arity, etc.), not here.
  Examples:
    - Wrong number/type of arguments to typeof/lengthof/assert/fail
    - Misspelling a true intrinsic name (rare, since 'lengthof' vs.
      'praintln' would actually be an UNDECLARED_VARIABLE case -- printline
      is stdlib, not an intrinsic)

MEMORY_ERROR
  Manual memory management misuse (via `import mem;`).
  Examples:
    - Using a pointer after mem::free() was called on it (use-after-free)
    - Calling mem::free() twice on the same pointer (double-free)
  These are detected by dataflow analysis where the compiler can prove the
  bug statically -- not every use-after-free/double-free is caught (e.g.
  ones that depend on runtime-only conditions).

GENERAL
  Use this ONLY when none of the above categories apply.
