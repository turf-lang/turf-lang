TURF-LANG MODULES / IMPORTS / `::` REFERENCE

THE CORE RULE: `.` IS FOR A VALUE YOU HOLD, `::` IS FOR A NAME.
  `.` reaches a struct value's fields and methods: `p.x`, `p.sum()`.
  `::` reaches something by name: a module's function or type, an enum variant,
  a static method, or a constructor.
    io::printline("hi");      Color::Red      Point::new(1, 2)      Point::default()
  `io.printline("hi")` and `p::sum()` are both wrong.

IMPORT FORMS (a file imports every module it uses, except the six prelude
modules int, double, bool, char, strings and array, which are always there:
`s.length()`, `strings::length(s)`). There is no automatic `io`.
    import io;                      // qualified only: io::printline("hi")
    import io::printline;           // one name, also usable bare: printline("hi")
    import io::[print, printline];  // several names
    import math::[*];               // every public name (clashes are errors)
  Naming something the module does not have is an error on the import line.

TYPES BELONG TO THEIR MODULE: `import list;` gives `list::List<int>` and
  `list::List::default()` only; a bare `List<int>` needs `import list::List;`
  (error E032 otherwise). Two modules may each declare a `Node`: they are two
  types, `a::Node` and `b::Node`. If a bare name could mean two types (your own
  `Point` plus one from `import m::[*];`) it is an error: qualify the imported
  one (`m::Point`) and list only the names you use.

PRIVATE BY DEFAULT: everything a module declares -- functions, structs, enums,
  errors, machines, extern fns, and each struct field and method -- is private
  to its file unless written `pub`. Another file may use only `pub` items
  (E088), and a `pub` signature may not mention a private type (E089). The file
  you run (the main program) needs no `pub`.

CORRECT:
    // shapes.tr
    pub struct Point { pub x: int, pub y: int }
    pub fn Point.sum(): int { return self.x + self.y; }
    pub fn origin(): Point { return Point::default(); }
    fn secret(): int { return 1; }              // private: only shapes.tr may call it

    // main.tr
    import shapes;
    import shapes::Point;
    fn main(): int {
        mut p: Point = shapes::origin();
        p.x = 3;
        return p.sum() - 3;
    }

CLASHES AND CYCLES: two on-demand imports that bring in the same bare name are
  an error at the second import; qualify the calls instead (`a::f()`, `b::f()`).
  If module A imports B and B imports A (directly or through others) the compiler
  reports the chain `a --imports--> b --imports--> a`: move what both need into a
  third module. Two modules importing the same third one is fine.

CONSTANTS: a top-level constant is `export immut NAME: Type = literal;` and
  nothing else (not `export mut`, not inside a function, and the value must be a
  plain literal). Use it as `consts::NAME`, or bare after `import consts::NAME;`.
    export immut MAX_USERS: int = 100;

ENUMS: `enum Color { Red, Green }`, `Color::Red`, `Color::COUNT` (number of
  variants). A name before `::` that is not an enum, struct or imported module is
  an error: check the spelling and the `import`.

STANDARD MODULES: io (print, printline, input), math (abs, power, sqrt, min, max,
  ...), mem (malloc, free, ...; raw pointers need `unsafe`), sys (panic, exit),
  test (assert, assert_eq), list (List<T>), map (Map<K, V>), set, stack, queue,
  strings, os, fs, json, time, random, net, http. They are ordinary Turf files
  under lib/std; which subfolder one lives in never matters to `import`. A module
  is searched in the standard library, the installed packages, the importing
  file's folder, then the current folder; exactly one must have the name (E090).
