TURF UNDECLARED VARIABLE OR IDENTIFIER:

CAUSE:
  The compiler cannot find a variable, function, or name that is referenced.
  This happens when:
  1. The name was never declared.
  2. It was declared in a different (inner) scope that has since ended.
  3. The name is a typo of a known variable, function, or builtin.
  4. A module-qualified name is missing its module prefix, or vice versa.

DECLARATION SYNTAX:
  mut name: Type = value;
  immut name: Type = value;

  CORRECT:
    mut count: int = 0;
    count = count + 1;             // count is visible here

  INCORRECT:
    if true {
        mut x: int = 5;
    }
    io.printline(x to string);      // ERROR: x is out of scope here --
                                    // "I can't find anything named 'x'."

SCOPE RULES:
  - Variables declared inside { } are only visible inside that block.
  - A `for` loop's induction variable is only visible inside the loop body
    -- it does not exist before or after the loop.
  - Top-level (function-body) variables are visible everywhere after their
    declaration, within that same function.
  - Struct/enum names and function names live in a single flat/per-module
    namespace visible throughout the file, independent of block scoping.

BUILTIN / INTRINSIC NAMES (exact spelling required):
  print   printline   input   typeof   sizeof   assert

CORRECT USAGE:
  mut x: int = 5;
  io.printline(x to string);

INCORRECT USAGE:
  io.printline(y);                // ERROR: y was never declared
  io.praintline("hi");            // ERROR: typo -- should be 'printline'
  length("hi");                   // ERROR: no such function -- use strings::length("hi")

COMMON MISTAKES:
- Typos in variable names (e.g. `coutn` instead of `count`).
- Typos in builtin/function names (e.g. `printLine`, `print_line`, `println`).
- Using a `for` loop's induction variable outside the loop body.
- Forgetting to declare a variable (with `mut`/`immut`) before using it.
- Using a variable from a nested block after that block has closed.
- Referencing a struct's own type-parameter name (`T` in `fn<T> f(x: T)`)
  outside a generic function/struct where it's actually in scope.
